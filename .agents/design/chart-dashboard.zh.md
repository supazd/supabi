# 图表与仪表盘 Spec 设计（v1）

状态：已实现，持续演进。与 [查询 IR](query-ir.zh.md)、[数据集模型](dataset.zh.md) 配套。第 7 节记录主要设计取舍。

筛选器直接绑定数据集字段或图表指标，不要求图表暴露筛选器；支持动态维度/指标与级联候选。旧的筛选器 ID 绑定由数据库迁移转换，不需要重建数据。本轮新增属性均为可选项，`specVersion` 仍为 1；未配置动态字段或级联的旧图表保持原有行为。

交互参考 DataWind 的[动态维度/动态指标](https://docs.volcengine.com/docs/Datawindprivatization/Dynamicdimensionsdynamicmetrics?lang=zh)与[全局过滤器](https://docs.volcengine.com/docs/Datawindprivatization/Globalfilter?lang=zh)。本项目实现筛选配置、动态切换、关联接管与级联的主流程；下文的字段身份、请求协议、反向回填和限制是 SupaBI 的实现规则，不将参考文档未说明的细节推断为 DataWind 的行为。

## 1. 定位

- **图表**：一个查询加一种呈现方式。可复用，独立保存，可以被多个仪表盘引用。
- **仪表盘**：若干图表的布局，加上作用于这些图表的筛选。

两者都是声明式 JSON，带版本号，存在元数据库中。拖拽编辑器、AI、接口产出和消费的都是同一种结构，渲染库不出现在其中。

图表和仪表盘另有独立的内容 `revision`，与配置格式 `specVersion` 无关。读取和列表接口返回内容版本；更新必须传 `expectedRevision`，省略或无效返回 400 `revision_required`。保存事务按数据集、图表、仪表盘的顺序锁定依赖与当前资源，检查当前版本后更新内容并递增版本。同一版本的并发保存只允许一个成功，过期保存返回 409 `resource_revision_conflict`，不修改内容或引用索引。图表和仪表盘尚不记录完整修订历史。

编辑器与数据集使用同一差异处理窗口，比较原始内容、当前草稿、服务器最新内容。名称和描述独立选择；图表的查询、可视化和筛选配置作为一组，仪表盘的布局、组件、筛选及联动作为一组，避免把互相依赖的配置拆开拼接。未改变的一方自动让位于改变的一方，双方不同的修改必须明确选择。关闭窗口保留草稿和原版本；应用只更新草稿及保存基线，可继续编辑；仪表盘同时清空撤销/重做记录，因为合并前的状态基于旧版本，撤销回去再以新版本号保存会不经提示覆盖他人修改。再次保存仍进行版本检查和正常校验，期间的新修改会再次提示冲突。此冲突与保存期间引用的数据集、图表变更导致的依赖冲突分别处理。

## 2. 图表 Spec

```jsonc
{
  "specVersion": 1,
  "query": { /* 查询 IR，见 query-ir.md */ },
  "viz": {
    "type": "bar",
    "x": "month",
    "y": ["revenue", "paid_revenue"],
    "series": "region",
    "stacked": true,
    "formats": { /* 可选，见 2.6 */ }
  },
  "filters": [ /* 见 2.3；以数据集参数为目标的见 2.11 */ ],
  "dynamics": [ /* 可选，见 2.4 */ ],
  "allowExport": false, /* 可选，见 2.9 */
  "drill": { /* 可选，见 2.10 */ }
}
```

`viz` 中引用的都是查询输出列的别名，不是数据集字段的内部 ID。这样图表的呈现只依赖查询结果的形状。

### 2.1 图表类型

| `type` | 含义 | `x` | `y` | `series` | 其他 |
|---|---|---|---|---|---|
| `bar` | 柱状图 | 必填，一个维度列 | 必填，一个或多个度量列 | 可选，一个维度列 | `stacked` |
| `hbar` | 条形图 | 同上，沿纵轴从上往下排 | 同上 | 同上 | `stacked` |
| `line` | 折线图 | 同上 | 同上 | 同上 | |
| `area` | 面积图 | 同上 | 同上 | 同上 | `stacked` |
| `combo` | 组合图 | 必填，一个维度列 | 必填，至少两个度量列 | 不支持 | `lines`：画成线的度量，其余画成柱；`rightAxis`：读右侧数值轴的度量 |
| `scatter` | 散点图 | 必填，每个取值一个点 | 必填，两到三个度量列：横轴、纵轴、气泡大小 | 可选，按它的取值区分颜色 | |
| `pie` | 饼图 | 必填，分类列 | 必填，恰好一个度量列 | 不支持 | |
| `funnel` | 漏斗图 | 必填，每个取值一层 | 必填，恰好一个度量列 | 不支持 | 从大到小排列，不合并为「其他」 |
| `treemap` | 矩形树图 | 必填，每个取值一块 | 必填，恰好一个度量列 | 可选，作为分组，每组一种颜色 | |
| `heatmap` | 热力图 | 不支持 | 必填，恰好一个度量列 | 不支持 | `rows`、`columns` 各恰好一个维度列，分别排在纵轴和横轴 |
| `gauge` | 仪表盘 | 不支持 | 必填，一到两个度量列；第二个是目标值 | 不支持 | 取结果第一行 |
| `kpi` | 指标卡 | 不支持 | 必填，一个或多个度量列 | 不支持 | 取结果第一行 |
| `table` | 表格 | 不支持 | 不支持 | 不支持 | 按查询的列顺序展示；`hiddenColumns` 可隐藏指定输出列；`columnGroups` 在表头上方给相邻的列加分组 |
| `pivot` | 透视表 | 不支持 | 必填，一个或多个度量列 | 不支持 | `rows`、`columns`：放在左侧和上方的维度列，每个维度恰好放在一处，至少一个 |
| `sankey` | 桑基图 | 不支持 | 必填，恰好一个度量列：流量 | 不支持 | `levels`：从左到右各层的维度列，2 到 4 个，查询的每个维度恰好一层 |

明细表不是另一种 `type`：它是查询为明细模式（`mode: "detail"`，见 [查询 IR](query-ir.zh.md) 3.3）的 `table`。`viz` 只依赖结果的形状，而汇总表和明细表的区别在于问的是什么，所以记在查询里。图表编辑器里只有一种「表格」类型。选中后，图表类型下方出现「聚合 / 明细」分段控件，它不在可折叠的分组里，始终可见，因为它决定画布上放的是「维度 + 指标」还是「列」。选「明细」时，维度栏和指标栏换成一个「列」栏，维度和度量可以放进去，指标不行，因为指标在一行上没有值。来回切换时，已选的字段尽量保留。新建图表默认是「表格 · 明细」，从其他图表类型切到表格时默认是「聚合」。图表有按聚合结果筛选的条件时，「明细」不可选，控件下方说明原因。

数值指标的字段菜单有「指标计算」，支持「原值 / 占全部 / 组内占比」。组内占比可多选当前维度，至少选择一项；动态指标的 `%` 按钮使用相同配置。配置保存在查询的 `compute` 中，预览、仪表盘和再次打开均使用同一口径（[查询 IR](query-ir.zh.md) 3.5）。更改计算方式时清除该列的图表格式覆盖，默认显示百分比；只打开并确认原配置不会改变格式。原始指标和占比可同时放入图表。移除维度会从占比的分组中移除它，全部移除后变为占全部。

同一窗口支持「同比 / 环比」：选择时间字段、本期范围、同比（前 1 年）或环比（偏移量与日/周/月/季/年单位），输出同期值、差值或增长率。本期范围同步写入该字段的图表筛选；已有筛选保留 ID 和标签；原单日期控件升级为日期范围控件，确保显示与本期范围一致，其他控件保留。未有筛选则新增固定筛选。范围必须有限且不包含空日期。保存并重新打开、动态指标切换及仪表盘执行均保留计算；原值、占比、同比与环比可作为不同别名的指标并存。增长率默认百分比，同期值及差值沿用原指标格式。动态选项的名称作为计算前名称，结果追加同比、环比或占比说明；旧图表再次保存时自动转换相应名称属性。

同一窗口还有「累计」，口径见 [查询 IR](query-ir.zh.md) 3.5：

- 选择沿哪个维度累计，候选是图表当前的维度，默认取第一个时间维度，没有时取第一个维度。图表没有维度时没有这一项。
- 只有求和、计数、最小、最大的指标能累计。平均、去重计数和数据集指标的这一项不可选，并说明原因：它们的累计不能由各分组的值依次得出。动态指标设了累计时，全部候选都必须是这四种聚合，保存时校验，与其他候选的校验一样，避免默认候选能用、切换后失败。
- 窗口里说明口径：在其余维度里各自从头累计；从筛选范围的起点开始，不包括更早的数据；结果筛选、排序和行数限制不改变累计值。
- 名称加「（累计）」，格式沿用原指标的格式。原值和累计可以同时放进图表。
- 从图表中移除沿着的那个维度，或把聚合换成不能累计的方式时，计算改回原值。沿着的是可留空的动态维度、查看者选了空时，这一列是普通的聚合，即整个范围累计到最后的值。

图表类型由作者选定，编辑器不替作者更换。增删字段不会改变图表类型；字段不满足所选类型的要求时（如柱状图删掉了唯一的维度），类型保持不变，画布显示还缺什么或多了什么（如「柱状图还需要 1 个维度」），对应的维度栏或指标栏标出来。这时不发查询，上一次的结果也不显示，因为它和当前字段对不上，容易被当成当前的图表；图表也不能保存。字段补齐后立即重新查询，即使查询本身与之前相同（如从缺维度的柱状图切到指标卡）。任何图表类型都可以先选、再按提示补字段；鼠标移到图标上，会显示这种图表需要什么字段，例如饼图需要「1 个维度和 1 个指标」。编辑器对字段的要求：

| 类型 | 维度 | 指标 | 编辑器怎么放 |
|---|---|---|---|
| 柱状图、条形图、折线图、面积图 | 1 或 2 | 1 个以上；有 2 个维度时恰好 1 个 | 2 个维度时，时间维度放在类目轴，另一个拆成序列 |
| 组合图 | 1 | 2 个以上 | 第一个指标画成柱，其余画成线，都读左轴；在「样式」里逐个改成柱或线、放到右轴 |
| 散点图 | 1 或 2 | 2 或 3 | 第一个维度的每个取值是一个点，第二个维度区分颜色 |
| 饼图、漏斗图 | 1 | 1 | |
| 矩形树图 | 1 或 2 | 1 | 2 个维度时第一个是分组 |
| 热力图 | 2 | 1 | 时间维度放在横轴，另一个放在纵轴；都不是时间时第一个在横轴 |
| 仪表盘 | 0 | 1 或 2 | 第二个指标是目标值 |
| 指标卡 | 0 | 1 个以上 | 「指标卡样式」里可以让一个指标与另一个对比 |
| 表格 | 不限 | 不限 | |
| 透视表 | 1 个以上 | 1 个以上 | 维度栏换成「行」和「列」两栏；字段菜单里可以在行和列之间移动 |
| 桑基图 | 2 到 4 | 1 | 维度按栏里的顺序从左到右排成各层 |

**栏里字段的顺序**可以直接拖动调整，新字段也可以拖到栏里的任意位置。早先新字段只能加到末尾，要换顺序得先删掉再加回来。

- **范围**：维度、指标、明细列、透视表的「行」和「列」、筛选器，各在自己的栏里拖动调整顺序，动态维度和动态指标也一样。不能拖到别的栏，拖过去时不接受（光标显示不可放）；透视表的行和列之间仍用字段菜单里的「移到列 / 移到行」。拖到别的栏见 [暂缓事项](../backlog.zh.md)。
- **拖动**：按住整个字段块拖，不另加把手；单击仍打开它的菜单或筛选设置。拖动时落点处显示一条竖线：指针在某个字段块的左半边就放在它前面，右半边就放在它后面，栏里的字段换了行也按指针所在的那一行判断；拖到栏的空白处放在最后。拖到栏外松手或按 Escape，顺序不变；放回原处也不变，不重新查询。
- **从左侧字段列表拖进来的新字段**同样落在松手的位置，竖线的规则相同；点击添加或拖到栏的空白处仍放在最后。筛选器和动态字段要先在弹窗里设置，确认后放在松手的位置，取消就什么都不加。已经在栏里的维度或列再拖进来，与现在一样不变，也不挪位置。
- **键盘**：字段菜单里有「前移」「后移」，已在最前或最后时不可用。筛选器的字段块点开是筛选设置，没有菜单，所以所有字段块获得焦点时都可以按 Alt+← / Alt+→ 前移或后移一位。
- **顺序变了会影响什么**：维度、指标、列的顺序就是查询返回列的顺序，所以会重新查询。表格的列顺序、没设排序时按维度依次排序（2.7）、合并相同值时左边的列约束右边（2.8）、透视表行列的嵌套、桑基图的各层、组合图没指定时第一个指标画成柱、仪表盘的第二个指标是目标值，都跟着栏里的顺序。筛选器的顺序是画布和仪表盘上控件的先后。
- **不受影响**：排序、显示格式、隐藏、列宽、对齐都认输出列的别名，不随顺序变。表头分组见 2.7。只读的图表不能拖。

规则：

- **一个数值轴**。多个度量共用同一个轴；量级差异大的度量应拆成两张图。唯一的例外是组合图：作者把某个度量明确放到 `rightAxis` 时，它读右侧的第二个数值轴，图例里它的名字后面注明「右轴」，右轴不画网格线。默认没有右轴，编辑器在勾选右轴时提示两个轴容易让人比较本不可比的高度。
- `series` 把一个维度的取值拆成多条序列。柱状图、条形图、折线图、面积图使用 `series` 时 `y` 只能有一个度量。
- **序列和扇区的颜色按固定顺序分配，不循环**。超过 8 个时，按合计值保留前 7 个，其余合并为「其他」。散点图的点可能挨着任意别的点，8 色中只有前 3 色两两都能分清（含色觉障碍模拟），所以散点图按点数保留前 3 组，其余合并为「其他」，用中性灰。漏斗图的层有先后，不合并，颜色用同一色相由深到浅（暗色模式由浅到深）；热力图同样用单色相表示大小，附一条色阶。没有分组的矩形树图所有块同色，靠块之间的空隙区分。
- `stacked` 只对可加的量有意义，是否可加由制作者判断。
- **透视表**的行按查询返回的顺序排列（可能是按某个度量排序），列按取值的自然顺序排列。外层维度连续相同的值只写一次，跨越它所包含的行或列。没有列维度时只有一组列；没有行维度时只有一行。有小计时，行按外层维度的取值聚在一起（各组按它的第一行出现的先后排，组内保持查询的顺序），每组之后是它的小计行（「华东 小计」），更内层的组在前；列同样在每组之后插入小计列。最后是合计行和合计列。
- **合计**（表格和透视表）由数据库计算，写在查询的 `totals` 里（[查询 IR](query-ir.zh.md) 3.8.1），前端不把各行加起来，所以平均值、去重计数的合计也是对的。编辑器里的「显示合计」开关：聚合表格要总计；透视表要每行的合计（右侧一列）、每列的合计（底部一行）和它们交汇处的总计，合计会按全部维度分组的（即表格本身）不要。
- **小计**是透视表的另一个开关「显示小计」，在「显示合计」打开、且行或列有两个以上维度时出现。小计也由数据库计算：行维度的前 i 个和列维度的前 j 个两两组合，各是一项 `totals`（如行是地区 > 城市、列是月份时，加上 `["region", "month"]` 和 `["region"]`），这样小计行在每一列（包括小计列和合计列）下都有值；写在不带小计时的三项之后，所以已有图表的 `totals` 不变。一共 (行维度数+1)×(列维度数+1)−1 项，超过查询的上限 16 项（如行 4 个、列 3 个维度）时不写小计，开关不可用并说明原因。打开图表时，`totals` 恰好是带小计的写法就恢复成打开。不并进「显示合计」，原因有二：小计让查询从至多 3 次变成至多 15 次，数据源慢时代价明显；小计行夹在数据中间，很多时候只想要底部和右侧的合计。合计覆盖全部数据，不受行数上限影响。表格只取回了一部分组时（设了「最多显示行数」，或者被默认的行数上限截断），合计行写「合计（全部数据）」，免得以为是显示的这些行的合计；只合计显示的行要在数据库里限定为取回的那些组，见 [暂缓事项](../backlog.zh.md)。图表有按结果筛选的条件时不显示合计，表格底部说明原因。明细表没有合计。
- **桑基图**的每条连线是相邻两层的一对取值之间的流量。只有两层时，查询的每一行就是一条连线；三层及以上时，相邻两层之间的流量取自查询的 `totals`（编辑器为每对相邻层各写一项，如 `[["channel","status"],["status","region"]]`），由数据库计算，去重计数、平均值的每条连线也是对的；只有拿不到合计时（如有按结果筛选的条件），才把行加起来。节点的高度是流入、流出连线中较大的一侧之和，所以流量最好是可加的（求和、计数）：去重计数时每条连线都对，但节点高度是连线相加，可能比该取值的实际去重数大。不同层的同名取值是不同的节点。第一层保留前 7 个取值，其余合并为「其他」（共 8 个，与调色板相同），按取值出现的顺序着色；后面各层保留前 11 个，用中性色；连线取起点的颜色、半透明。流量为零或负的连线不画。
- **指标卡的对比**：`compare` 把一个指标与另一个指标配对，例如 `{ "revenue": "target" }`。被对比的指标不再单独成卡，也不能再与别的指标对比。卡片下方写变化的百分比（相对被对比值的绝对值）或差值，前面有 ▲ 或 ▼，方向不只靠颜色表达。

### 2.2 保存时的校验

1. `query` 按查询 IR 的规则对数据集编译一次，任何编译错误都拒绝保存。
2. `viz` 引用的列必须是查询的输出列，且角色正确：`x`、`series` 是维度，`y` 是度量。
3. 各类型的必填项和互斥项符合上表。`lines`、`rightAxis` 只能列出 `y` 里的度量，各一次；透视表的每个维度列恰好在 `rows` 或 `columns` 里出现一次；桑基图的每个维度列恰好是一层，超过两层时查询的 `totals` 要有每一对相邻层；`compare` 的两边都是 `y` 里的度量，不能自比，也不能连环对比。
4. `formats` 的每一项都指向查询的数值或日期输出列，格式的属性与列的类型相符，格式本身合法，见 2.6。
5. `style` 的每一项都适用于这种图表，取值合法，见 2.8。
6. `hiddenColumns` 只适用于表格，引用查询输出列的别名，不可重复，且必须至少保留一列显示；允许清空的动态维度全部清空后也要满足此条件。
7. `columnGroups` 只适用于表格。引用的都是查询的输出列，每列最多出现一次；每个分组至少有一项、名字不为空且最多 50 个字，最多套三层；每个分组盖住的列在查询的输出列里相邻，隐藏的列也算在内。见 2.7。

### 2.3 筛选器

图表上的时间范围和其他条件是同一种东西：筛选器。时间范围就是日期字段上的筛选器，不再单独建模。

```jsonc
"filters": [
  // 固定条件：没有 control，查看者看不到，也改不了
  { "id": "f_paid", "field": "status", "op": "in", "value": ["paid"] },

  // 显示为图表筛选器：有 control
  { "id": "f_date", "field": "order_date", "op": "time",
    "value": { "last": { "n": 30, "unit": "day" }, "includeCurrent": true },
    "label": "下单日期", "control": { "type": "relative" } },

  // 与全局筛选器是否绑定无关，control 只决定是否显示控件
  { "id": "f_uid", "field": "uid", "op": "in", "value": [],
    "label": "UID", "control": { "type": "search_select" } },

  // 同一度量可以筛选明细，也可以明确指定聚合方式筛选结果
  { "id": "f_total", "field": "amount", "aggregation": "sum", "op": "gte",
    "value": 1000, "label": "金额合计", "control": { "type": "number" } }
]
```

| 属性 | 含义 |
|---|---|
| `id` | 图表内唯一，提交本地图表筛选值时使用 |
| `field` | 数据集的维度、度量或指标字段；无 `aggregation` 时维度和度量过滤明细，指标过滤聚合结果 |
| `aggregation` | 可选，数值度量的结果筛选聚合方式：`sum`、`avg`、`min`、`max`、`count`、`count_distinct`，编辑器里默认求和；数据集指标已有聚合定义，不可再聚合 |
| `op` | 条件，见下表 |
| `value` | 取值。有 `control` 时是初始值，空表示不限制；固定条件需要有效条件值，无值操作符除外 |
| `control` | 查看者用来改值的控件。省略即固定条件 |
| `label` | 控件上显示的名字，有 `control` 时必填 |
| `dependsOn` | 可选，当前图表内的父筛选器 ID 数组；限制候选选项，见 2.5 |

筛选器也可以指向数据集参数，写 `param` 而不写 `field`，规则不同，见 2.11。

`control` 决定固定或显示为图表筛选器。旧数据中的 `exposed` 字段仅兼容读取，不再控制全局筛选器的能力。度量没有 `aggregation` 时筛选的是原始行，设置后筛选每组计算结果；这与字段是否已被放到图表指标栏无关。结果筛选通过 `filterMeasures`/`HAVING` 实现，不增加显示列；明细表不允许结果筛选。

图表编辑页在预览图表上方展示可交互筛选器，控件与仪表盘一致，空间不足时自动换行并让出图表高度。试选只影响预览，不修改默认值或产生未保存状态；默认值仍通过筛选配置修改。预览遵循自动运行开关，关闭后点击「运行」应用；固定条件继续参与取数但不显示控件。修改筛选定义或切换数据集会清理失效的临时取值。

图表保存按钮仅在草稿有修改且配置有效时启用，保存成功后恢复禁用；保存期间继续发生的修改仍视为未保存。查询按钮在运行时切换为等宽的「取消」，取消请求并保留上次结果；新查询、切换数据集或离开编辑页也会取消不再需要的请求，迟到响应不会覆盖当前结果。查询操作栏右侧显示当前已展示结果的耗时（ms）与条数。

**条件与控件分开。** `op` 决定条件的含义，`control.type` 决定查看者怎么填值，能用哪些控件由字段类型和 `op` 决定：

| 字段类型 | `op` | 可用控件 |
|---|---|---|
| 文本、整数、布尔 | `in`、`not_in` | `select`（下拉）、`search_select`（输入后到服务端搜索）、`tiles`（平铺，超过 30 个取值或结果被截断时显示为下拉）；`multi` 控制单选或多选 |
| 文本 | `eq`、`ne`、`contains`、`not_contains`、`starts_with`、`ends_with`、`like`、`not_like` | `text`（输入条件，不查询选项） |
| 数值 | `between`、`not_between` | `number_range`，支持开闭区间与单边界 |
| 数值 | `eq`、`ne`、`gt`、`gte`、`lt`、`lte` | `number` |
| 日期、时间 | `time` | `date`（单日）、`date_range`（固定范围）、`relative`（紧凑入口，面板内选择动态、固定、高级或特殊值） |

`time` 的取值结构见 [查询 IR 3.6](query-ir.zh.md#36-时间范围)：`last`、`current`、`start`/`end`、`bounds`、`special` 互斥。高级范围的起止可分别固定、相对或无限；特殊值为全部、空日期、非空日期。图表/全局控件用 `{}` 表示全部，`{ "bounds": {} }` 也表示不限范围；`{ "special": "is_null" }`、`{ "special": "not_null" }` 分别筛选空值和非空值。`includeNull`、`grain`、`weekStart` 修饰区间（包含空日期、按年-月-日/年-月/年-周编辑、本筛选器的周计算逻辑）；只有修饰项的值也表示全部，编辑器借它记住粒度。时区、周起始日、左闭右开沿用查询 IR，既有日期控件与已保存时间值兼容。

规则：

- 各筛选器之间是「并且」。
- 一个图表可以有多个日期筛选器，各自作用于不同的日期字段。
- **系统不替制作者创建筛选器。** 数据集没有「默认时间字段」这个概念；图表本地筛选器由制作者添加，全局筛选器独立指定各图表的字段。
- 筛选器不写进 `query`。取数时服务端把它们编译成条件追加到查询上，所以 `query` 描述「问什么」，`filters` 描述「在什么范围内问」。
- 数值范围兼容 `[最小值, 最大值]`，也可写 `{ "min": 0, "max": 100, "includeMin": false, "includeMax": true }`，未指定闭合方式时两端包含。单端为空时转为对应单边比较，双端为空表示不限；`not_between` 取区间外，边界取反。开放端的转换发生在图表条件层，原始查询 IR 的范围条件仍需双端值。开闭属于条件本身：显示为控件且默认值为空时，仍保存 `{ "includeMin": false }` 这样只含闭合方式的值，查看者输入的边界沿用它。
- 固定条件还可以用 `is_null`、`not_null`，文本可用 `is_empty`、`not_empty`。后两者针对空字符串，不能代替 NULL 判断。日期的空/非空切换可通过 `time.special` 暴露为控件。
- `contains`、前缀和后缀匹配按字面量处理；`like`、`not_like` 中 `%` 表示任意长度、`_` 表示单个字符，反斜杠转义通配符。所有值仍通过绑定参数执行。
- 下拉选项通过「图表 + 筛选器」取得，查看者不需要数据集权限；`search_select` 把输入的文字交给服务端按「包含」查找，一次最多返回 500 个。
- 聚合指标按结果类型使用控件：数值比较/范围、日期/相对时间、文本比较、布尔单选/多选。布尔候选固定为 true/false，其他聚合结果不枚举取值。条件进入 `HAVING`，未被图表选中的指标不会增加结果列。

### 2.4 动态维度与动态指标

动态字段是在一个固定输出位置提供作者指定的候选，查看者选择的是候选 ID。它改变分组字段或被计算的指标，不是按某个字段值筛选行。

```jsonc
"dynamics": [
  {
    "id": "group", "kind": "dimension", "label": "分析维度", "alias": "category",
    "allowEmpty": true,
    "options": [
      { "id": "region", "field": "region", "label": "地区" },
      { "id": "month", "field": "order_date", "grain": "month", "label": "下单月份" }
    ]
  },
  {
    "id": "metric", "kind": "measure", "label": "分析指标", "alias": "value",
    "options": [
      { "id": "revenue", "field": "revenue" },
      { "id": "average", "field": "amount", "agg": "avg", "label": "平均金额" }
    ]
  }
]
```

- 每项必填 `id`、`kind`（`dimension` 或 `measure`）、`label`、`alias`、`options`。`alias` 对应 `query.dimensions` 或 `query.measures` 的稳定输出名；`viz` 持续引用该别名。编辑器在基础 query 中保留第一项候选。
- 候选必填 `id`、`field`，可选 `label`。编辑器保存时为每个候选写入名称（未自定义时取字段名，附带聚合或粒度），因为仪表盘查看者无法读取数据集来命名候选。维度候选只允许数据集维度，可为日期指定 `grain`；指标候选引用指标，或引用行级字段并用 `agg` 指定聚合（度量和维度必填，编辑器里度量默认求和）。指标候选不可设置 `grain`，数据集指标不可再聚合。
- 一个图表最多 16 个动态位置，每个 1–64 个候选；位置 ID、别名以及各位置内的候选 ID 必须唯一。保存时验证所有候选，避免默认值可用而切换后失败。明细模式不支持动态字段。
- 取数请求用 `selections: { "group": "month", "metric": "average" }`；省略位置使用首项。只有 `allowEmpty: true` 的维度接受空字符串，表示不按该维度分组；指标不能留空。未知位置、未知选项或不允许的空值直接报错。
- 先解析动态选择，再叠加图表和全局条件。全部维度为空时视觉回退到表格，热力图少了行或列的维度时也回退到表格，桑基图剩下不到两层时也一样；移除的维度同时从查询的 `totals` 中去掉，见 [查询 IR](query-ir.zh.md) 3.8.1；仅移除当前横轴时使用剩余首维度，移除的系列或与横轴重合的系列被清理。图表按别名写在被移除维度上的设置，在这一次展示里也一并去掉：按它的排序、显示格式、条件格式、是否隐藏、列宽和对齐，以及它在表头分组里的位置（分组里一列都不剩时分组也去掉）。保存的图表仍保留这些设置，维度选回来后照常生效。保存时会把所有可留空的维度都留空再校验一遍，这些设置不能让这次校验失败。
- 编辑预览与仪表盘中的选择属于临时状态，不修改已保存 query 或默认候选。全局绑定具体 `field` 时始终筛选该字段；绑定动态指标 `measure` 别名时则跟随当前候选的聚合语义，所有候选必须与全局控件及目标结果类型兼容。

### 2.5 级联筛选

图表筛选器和全局筛选器均用 `dependsOn: [父筛选器 ID]` 表达依赖；两者各自成图，不能用本地图表 ID 引用全局筛选器，反之亦然。只有明细层的 `in` 精确选择可参与级联，父子都必须使用 `select`、`search_select` 或 `tiles`。`not_in`、文本模糊匹配、日期、聚合结果和固定条件不能作为级联节点。保存时拒绝缺失父项、重复依赖、自引用和环。

正向选择父项后，清理其后代的临时值并按全部祖先重新读取候选；未提供的值使用已保存默认值，显式空值表示解除限制。读取某个控件的候选时排除它自己的取值，避免选中后只能看到已选项。图表候选保留查询本身的约束与固定条件，不由无关的交互筛选器缩小候选。

本项目的反向联动先清除旧祖先值及相关兄弟分支，再使用新选的子项查询匹配祖先，避免旧父项阻止切换到另一分支。候选接口的 `related: true` 允许用同一连通分量内的条件反查；前端负责明确提交需要清空的值。自动回填只使用 `truncated: false` 的完整候选：单选父项仅在唯一匹配时回填，多选父项可回填完整匹配集合；没有匹配或结果被截断时不猜测。反向回填是 SupaBI 的交互规则，不是对 DataWind 未公开细节的断言。

全局级联还要求：每个节点 `optionsFrom` 所指组件，必须存在同一连通分量中其余节点的字段映射。允许多图表、不同数据集显式映射，但一个候选请求只查询选定来源组件的数据集，不做跨数据集联查或候选并集。全局候选保留未被接管的固定条件和祖先全局值。组件自身候选保留固定本地条件与本地祖先；全局模式下还应用当前作用于该组件的全部全局条件，切回图表模式后忽略这些全局条件。

### 2.6 显示格式

数值和日期的显示格式默认取自数据集字段（[数据集模型](dataset.zh.md) 5.5）。图表可以按列覆盖：

```jsonc
"viz": {
  "type": "bar", "x": "month", "y": ["revenue", "orders"],
  "formats": {
    "revenue": { "unit": "wan", "decimals": 1, "suffix": "元" }
  }
}
```

- 键是查询输出列的别名，值是一个完整的格式，结构与数据集字段的 `format` 相同。没有覆盖的列跟随数据集；数据集也没有格式时，数值按「无」原样显示，日期按默认值写。
- 要在图表上不用数据集的格式、原样显示，写 `{ "style": "none" }`。界面上「跟随数据集」与「无」「数值」「百分比」并列，是同一个选择。
- 日期没有「无」，要在图表上不用数据集的格式、按默认值写，写 `{}`。界面上「跟随数据集」与「横线」「斜线」「中文」并列；选了写法之后，再选时间写到哪里（时间戳才有）和按周时怎么写。
- 覆盖是整体替换，不按属性合并。按属性合并时，「不写千分位」和「跟随数据集」分不清；整体替换的结果一眼可知。编辑器从「跟随数据集」改为「数值」或「百分比」时，以数据集的格式为起点。
- 只能给数值和日期列设置，属性与列的类型相符。动态位置按位置的别名覆盖，切换到别的候选时同样适用；切到类型不同的候选时不生效，切到 `date` 候选时 `time` 不起作用。
- 格式不进入查询，不影响取数，也不出现在查询结果里，由前端叠加在结果的列上。

### 2.7 排序、行数与列显示

排序和行数直接写在 `query` 的 `sort`、`limit` 里（[查询 IR](query-ir.zh.md) 3.8），图表 Spec 不另设字段：

```jsonc
"query": {
  "dimensions": [{ "field": "city" }],
  "measures": [{ "field": "revenue", "agg": "sum" }],
  "sort": [{ "by": "revenue", "desc": true }],
  "limit": 10
}
```

- `sort[].by` 是输出列的别名，和 `viz`、`formats` 一样不引用数据集字段。可以有多个键，靠前的优先。没有 `sort` 时按维度依次升序，明细表不排序。
- 编辑器在维度、指标和明细列的字段菜单里设置升序、降序或取消排序。新排序的列排在已有的键后面；只改方向的列保留原来的顺位。排了序的列在名称后显示方向，有多个键时还显示第几顺位。动态位置暂不能在编辑器里设置排序。
- 列从图表上移除后，按它的排序随之删除，再把这列加回来也不会恢复排序。
- `limit` 是 1 到返回行数上限（默认 10000，在「系统管理 → 通用设置」里改，[启动配置](configuration.zh.md) 10.7）之间的整数，在编辑器配置栏的「通用」分组里设置。配置栏在「图表类型」下按组排列，每组可以折叠，组标题是带底色的标题栏，折叠图标在右侧。只属于某些图表的分组（如「样式」里的堆叠）在前，没有可设置的项时整组不显示；「通用」每种图表都有、改得也少，排在最后。折叠状态按分组记在浏览器里，不存进图表。不写时用默认返回行数（默认 1000，同样在通用设置里改）；这时结果被截断，编辑器会提示。写了 `limit` 时，返回的行数少于实际行数是作者要的结果，不再提示；只有 `limit` 大于上限时，图表按上限返回，输入框提示超出范围，截断的提示也照常显示。
- 仪表盘和预览直接使用 `query` 里的排序和行数。候选接口取值时去掉它们，候选来自全部行，不受 Top N 的影响（见 3.6）。
- 编辑器不能设置 `offset`。含 `offset` 的图表在编辑器里只读。

表格的明细列、聚合表的维度和指标，可以在字段菜单中选择「在表格中隐藏」，再通过同一菜单恢复显示。隐藏的字段仍留在编辑器中，标注「已隐藏」；动态维度和指标同样支持。配置写在 `viz.hiddenColumns` 中，例如 `{ "type": "table", "hiddenColumns": ["customer_id", "revenue"] }`。

- 只控制当前图表的呈现，不改 `query`；隐藏列仍参与查询、分组、排序、指标计算和合计。隐藏维度不会重新聚合，可能出现显示名称相同的多行。接口结果和编辑器底部的查询结果仍包含全部列，隐藏不属于数据权限。
- 预览和仪表盘使用同一显示规则；隐藏列的表头、单元格和合计一起隐藏，冻结首列改为冻结第一列可见列。
- 设置跟随输出列的稳定别名，重命名显示名、更改聚合方式和动态候选不丢失；移除输出列时清除它的隐藏设置，再添加时默认显示。动态维度临时清空时只从本次呈现中去掉它，不修改保存的默认设置。
- 至少保留一列显示。可清空的动态维度不能是唯一显示的列；如果移除其他列导致不满足此条件，编辑器提示恢复显示并阻止保存。
- 只对明细表和聚合表生效。切换到其他类型时不写入 `hiddenColumns`；在同一次编辑中切回表格，仍存在的输出列保留原设置。

**表头分组**（`viz.columnGroups`）像在 Excel 的表头上方加几行，把相邻的几格合并后写上名字。明细表和聚合表都能用；透视表的列表头由数据生成，没有这一项。

```jsonc
"viz": {
  "type": "table",
  "columnGroups": [
    { "label": "地区", "columns": ["region", "province", "city"] },
    { "label": "业绩", "columns": [{ "label": "金额", "columns": ["revenue", "profit"] }, "orders"] }
  ]
}
```

- **结构**：分组是一棵树。`columns` 里的每一项是输出列的别名，或者一个更小的分组，按列在表格里的顺序写。分组只能嵌套，不能交叉：一个分组盖住相邻的几列，最多套三层，表头最多四行。一个分组可以只盖一列，相当于在这一列上方单独加一个标题。没有放进分组的列，表头一直拉到顶。
- **画法**：表头的行数是分组最深的层数加一。分组名最多 50 个字，与坐标轴标题和页名相同，在它盖住的列上方居中，单行显示，宽度等于下面各列之和。列名写在最底下一行，上方没有分组时向上延伸，文字贴底。往下滚动时表头的几行都停在顶部，与透视表相同；为此表头的行高是固定的，不随页面的行高变化。列宽只能拖最底下一行的列名调整。
- **编辑**：只在图表编辑器的画布上编辑，仪表盘和预览里只能看。
  - 点一个表头选中它，按住 Shift 再点另一个，选中两者之间的各项。只能在同一层、同一个上级分组里连选，点到别处时从那一项重新开始。点空白处或按 Escape 取消选择；关对话框或菜单的 Escape 不算。隐藏或显示一列时，选择也取消，以免选中的是看不见的列。拖动表头右边缘调整列宽，不会选中。
  - 表格上方有一条工具条，没有选中时写着怎么选，所以选中前后表格不会移动。选中的是列或几项时有「合并为分组」：新分组叫「分组」，名字处直接进入编辑。选中一个分组时有「重命名」和「取消分组」，双击分组名也可以改名。名字清空后确认，仍用原来的名字。
  - 「取消分组」只拆掉这一层，里面的列和小分组留在原处，归到上一层。
  - 夹在选中各列之间的隐藏列也放进新分组，这样它重新显示时仍在分组里。
  - 合成后会超过三层时，「合并为分组」不可用，并说明原因。
- **列变化时**：
  - 列从图表上拿掉，就离开它所在的分组；分组空了就去掉。
  - 新加的列排在末尾，不进任何分组。聚合表里新加的维度排在维度和指标之间：如果那里有分组跨过维度和指标，新维度归进跨过那里的最内层分组，保证每个分组的列仍然相邻。新字段拖到栏里中间的位置时（2.1）同样处理。
  - 拖动调整列的顺序时（2.1），拖动的列先离开原来的分组：落在某个分组的列中间，就归进那个分组的最内层；落在分组外面或分组边上，就不在任何分组里。否则把分组里的一列拖到远处，分组会把中间的列全都盖进去。
  - 分组只盖显示出来的列；一个分组下面的列全部隐藏时，这个分组也不显示。可清空的动态维度临时清空时同样处理，这时编辑分组也不会把它从分组里去掉。
  - 分组跟着输出列的别名走，重命名显示名、更改聚合方式和动态候选都不影响它。
  - 换成别的图表类型时，分组留在草稿里但不保存；在同一次编辑中切回表格，仍在的列保留原来的分组。
- **与其他设置**：
  - 冻结首列仍只冻结第一列可见列。第一列在某个分组里时，分组那一格随表格横向滚走；要冻结整个分组得做成「冻结前几列」，见暂缓事项。
  - 合并相同值（2.8）、合计行和点击联动不受影响。
  - 导出、「查看数据」（3.8）和底部「数据」面板仍只有一行列名，不带分组。

**分页**（`style.paging`、`style.pageSize`）在「表格样式」里选，聚合表和明细表都能用；透视表有分组和小计，一组被分到两页的规则要另定，没有这一项。

- **只给已经取回的行分页**：查询照常取回「最多显示行数」那么多行（默认 1000，上限 10000，都可以在通用设置里改），翻页只改显示哪些行，不再查询数据库。翻页因此很快，一次只画一页，几千行的表格也不会卡。要浏览超过上限的数据得在数据库里分页，见 [暂缓事项](../backlog.zh.md)。
- **三种方式**：
  - **显示全部**：不写 `paging`，就是原来的样子，已有的图表不变。
  - **分页**（`paging: "pages"`）：每页行数写在 `pageSize`，1 到 1000 的整数，不写时 20；页数是取回的行数除以它，向上取整。
  - **自动**（`paging: "auto"`）：按表格能用的高度算每页几行：减去表头、合计行和翻页条，除以一行的高度，至少 1 行。卡片改了大小、放大查看、全屏时重新算。为了算得准，表格正文的行高和表头一样固定下来，不随页面的行高变化。
  - `pageSize` 只在 `paging` 是 `pages` 时可写，其他时候服务端拒绝保存；编辑器换了方式时把它留在草稿里，换回来时还在。
- **翻页条**在表格下方靠右：「上一页」「第 3 / 12 页」「下一页」，旁边写「第 41–60 行，共 1000 行」；结果被行数上限截断时不知道总共有多少行，改写「第 41–60 行，结果超过行数上限，只显示前 1000 行」，与编辑器里截断的提示相同，免得以为全部数据就这些。只有一页时也显示，表格的高度不随翻页条出现或消失而跳动。查看者不能改每页行数。翻页后表格滚回顶部。
- **什么时候回到第 1 页**：筛选、联动、动态选择变了，或者编辑器里改了查询，回到第 1 页。定时刷新或手动刷新同一个查询时留在当前页；行数变少了，当前页超过总页数时退到最后一页。自动分页的每页行数变了时（卡片改了大小、全屏），显示正在看的那几行所在的页，而不是同一个页码。
- **当前页不保存**，分享链接也不带当前页。放大查看（3.8）是另一张表，从第 1 页开始，关闭后卡片仍在原来的页。
- **与其他设置**：
  - 合计行算的是全部数据，每页都显示。
  - 合并相同值（2.8）只在当前页里合并，一组被分到两页时，下一页开头再写一次这个值；斑马纹也按页从头开始。
  - 「最多显示行数」在分页时是最多取回多少行，编辑器在它旁边说明。
  - 冻结首列、列宽、表头分组、点击联动照常；导出和「查看数据」（3.8）仍是全部行。

### 2.8 样式

图表的外观写在 `viz.style` 里。它只影响怎么画，不影响取数，也不改变画什么。全部可选，不写就是默认样式：

```jsonc
"viz": {
  "type": "bar", "x": "month", "y": ["revenue", "orders"], "stacked": true,
  "style": {
    "legend": "bottom",
    "labels": "value",
    "palette": "warm",
    "colors": { "orders": "aqua" },
    "percent": true,
    "barWidth": 40,
    "xAxis": { "title": "月份", "rotate": 45 },
    "yAxis": { "min": 0, "hideGrid": true }
  }
}
```

| 属性 | 取值 | 适用的类型 | 默认 |
|---|---|---|---|
| `legend` | `top`、`bottom`、`left`、`right`、`none` | 柱状、条形、折线、面积、组合、散点、饼、漏斗、矩形树 | 多于一个序列时在顶部；漏斗图的层名写在旁边，默认没有图例 |
| `labels` | `value`、`percent`、`none`；`percent` 只用于饼、漏斗、矩形树、桑基 | 以上各类型加热力图、桑基图 | 饼图和漏斗图标占比（漏斗是占第一层的比例），桑基图只写节点名称（占比是占第一层流出总量的比例），其余不标；散点图的 `value` 是在点旁写名称 |
| `palette` | `fresh`、`warm` | 柱状、条形、折线、面积、组合、散点、饼、矩形树、桑基 | 默认顺序 |
| `colors` | 度量列 → 色相名（`blue`、`orange`、`aqua`、`yellow`、`magenta`、`green`、`violet`、`red`） | 柱状、条形、折线、面积、组合；有 `series` 时不可用 | 按配色方案的顺序 |
| `smooth`、`points` | 布尔值 | 折线、面积、组合 | 否 |
| `percent` | 布尔值，只用于堆叠时 | 柱状、条形、面积 | 否 |
| `solid` | 布尔值 | 饼图 | 否（环形） |
| `barWidth` | 4–80 的整数，柱子最宽多少像素 | 柱状、条形、组合 | 28 |
| `xAxis`、`yAxis`、`y2Axis` | 见下 | 有坐标轴的类型 | |
| `gauge` | `{ "min", "max" }` | 仪表盘；有目标值时不能写 `max` | 0 到数值按首位进一（如 6,868,017 → 7,000,000） |
| `nodeAlign` | `left`、`right`：没到最后一层就结束的路径停在左边或右边 | 桑基图 | 延伸到最后一层 |
| `striped` | 布尔值，隔行底色 | 表格、透视表 | 否 |
| `density` | `compact`、`comfortable` | 表格、透视表 | 标准行高 |
| `freeze` | 布尔值，横向滚动时第一列不动 | 表格、透视表 | 否 |
| `merge` | 布尔值，维度列里连续相同的值合成一格 | 表格 | 否 |
| `paging` | `pages`、`auto`，见 2.7 | 表格 | 显示全部 |
| `pageSize` | 1–1000 的整数，只在 `paging` 是 `pages` 时 | 表格 | 20 |
| `widths` | 输出列 → 40–800 的整数像素 | 表格、透视表 | 按内容 |
| `columnAlign` | 输出列 → `left`、`center`、`right` | 表格、透视表 | 数值靠右，其余靠左 |
| `highlights` | 数值列 → 1 到 5 条规则，见下面的「条件格式」 | 表格、透视表 | 不上色 |
| `textAlign` | `left`、`center` | 指标卡 | 靠左 |
| `size` | `small`、`large` | 指标卡 | 中 |
| `compareAs` | `percent`、`diff`、`both`；只在有 `compare` 时 | 指标卡 | 百分比 |
| `redUp` | 布尔值，上涨用红色、下跌用绿色；只在有 `compare` 时 | 指标卡 | 上涨绿色、下跌红色 |

- **适用范围由服务端检查**。不适用于这种图表的项直接拒绝保存，而不是留着不用：Spec 里写着的就是起作用的。编辑器在切换图表类型时把不适用的项留在草稿里，换回来时还在，但保存的 Spec 里只有适用的项。
- **坐标轴按在屏幕上的位置命名**，因为条形图的数值轴在横向、类目轴在纵向，按角色命名反而要换算。数值轴可设 `title`、`min`、`max`（`min` 小于 `max`）、`hideGrid`、`hideLabels`；类目轴可设 `title`、`rotate`（45 或 90）、`hideLabels`。哪个轴是数值轴：柱状、折线、面积、组合的 `yAxis`（组合图另有 `y2Axis`，只在有 `rightAxis` 时可写），条形图的 `xAxis`，散点图两个都是；热力图两个都是类目轴。散点图的轴没写标题时，用度量的名称做标题，否则分不清哪个轴是哪个度量。
- **颜色只能从调色板里选**。配色方案是同样 8 个色相的不同顺序，每种顺序都验证过：相邻两色在红绿色觉障碍模拟和正常视觉下都能分清，前 3 色两两都能分清。`colors` 存色相名而不是色值，浅色和暗色模式各用自己那一档。给某个度量指定了颜色后，其余度量按配色方案的顺序取剩下的颜色，不会与它撞色。按维度取值拆出的序列不能单独指定颜色：取值会变，颜色应当跟着实体，而不是跟着位置。
- **百分比堆叠**把每个类目画成 100%，数值轴显示百分比，提示框里同时写出占比和原值。
- **数据标签**写在柱子顶端或线上的点上；堆叠时写在柱子里面。标签之间不做避让，类目很多时会重叠，这是作者开启时的取舍。
- 仪表盘有第二个度量时，它是目标值，刻度到它为止，下方写「目标 X · 完成 Y%」；没有目标值时下方写度量名称。
- **列宽**在编辑器里拖动表头右边缘设置，写进 `widths`；「表格样式」里可以恢复自动列宽。透视表可以拖行维度和度量的表头（只有一个度量时度量没有表头，不能拖）。仪表盘和预览里不能拖。列从图表上拿掉后，它的列宽和对齐留在草稿里，但不写进 Spec，加回来时恢复。
- **对齐**在字段菜单里设置（表格和透视表的维度、指标、明细列都有）。再选一次当前的对齐方式就恢复默认。
- **合并相同值**（`merge`）在「表格样式」里打开，聚合表和明细表都能用；透视表的行维度本来就把连续相同的值只写一次，没有这一项。
  - 只合并维度列。指标列不合并：两行的销售额恰好相同，不应该并成一格。
  - 只合并相邻的行，不为了合并调整行的顺序，所以效果取决于排序：按销售额排序时，同一个大区的行分散在各处，几乎合并不了。开关下面写明这一点，提示先按要合并的列排序。
  - 一列只在它左边的维度列都相同的范围里合并，和透视表的行维度一样：相邻两行省份相同、大区不同时，省份不合并。最后一个维度通常每行都不同，自然不会合并。明细表里夹在中间的指标列不影响这个范围。
  - 只看显示出来的列：隐藏的维度列（2.7）不合并，也不限制它右边的列。
  - 按原始值判断是否相同，与透视表一样：空值和空值相同，空值和空字符串不同。
  - 值写在合并后格子的顶部，与透视表相同；格子比表格的可见区域还高时，往下滚动会看不到值。打开合并时维度列不画斑马纹，否则一个格子会跨过深浅不同的几行；指标列照常隔行变色。对齐、列宽和冻结首列照常。
  - 合计行不参与合并。点击联动时，点合并后的格子就是选中这个值。
  - 导出、「查看数据」（3.8）和底部「数据」面板仍是一行一行的结果，每行都有值。
- **条件格式**（`highlights`）按格子里的值给它上底色，还可以在数字前加一个小图标，把要注意的数标出来，如完成率低于 80% 标红、达到 100% 标绿。

  ```jsonc
  "style": {
    "highlights": {
      "completion": [
        { "op": "lt", "value": 0.8, "color": "red", "icon": "down" },
        { "op": "lt", "value": 1, "color": "yellow" },
        { "op": "gte", "value": 1, "color": "green", "icon": "up" }
      ]
    }
  }
  ```

  - **哪些列**：数值列。表格里是聚合表的指标和明细表的数值列，透视表里是度量。维度列、文本和日期没有这一项。
  - **规则**：每列 1 到 5 条，从上往下看，用第一条满足的，后面的不再看。所以上面的三档写成「低于 0.8」「低于 1」「不低于 1」。条件是和一个固定的数比较，`op` 与查询里筛选的写法相同：`lt`、`lte`、`gt`、`gte`、`eq`、`ne`。规则再多时更适合用色阶，见 [暂缓事项](../backlog.zh.md)。
  - **比的是原始值**，不是显示出来的数：显示成「80%」的比例写 0.8，显示成「120万」的写 1200000。编辑器在输入框旁边按这一列的格式写出它显示成什么（「= 80%」），免得写错单位。空值不满足任何规则，不上色。
  - **颜色**从调色板的 8 个色相里选，与 `colors` 一样存色相名。画成浅底色：色相与格子原来的底色混合，文字仍是正文的颜色，所以黄色这样的浅色上文字也看得清，混合后文字与底色的对比度不低于 4.5:1。浅色和暗色模式各用自己那一档，仪表盘上自定义了背景时与那个背景混合。底色不透明，冻结首列时也盖得住滚过去的内容。只上底色，不改文字颜色，见暂缓事项。
  - **图标**可选：`up` ▲、`down` ▼、`dot` ●，写在数字前面。红绿色觉障碍的人分不清红底和绿底，所以用红绿区分好坏时应当配上图标，编辑器在规则下方写明这一点。
  - **不上色的格子**：表格的合计行、透视表的小计和合计不上色。它们和普通格子的量级不同，按城市定的销售额门槛对大区的小计没有意义。
  - **与其他设置**：上了色的格子不画斑马纹；点击联动选中的值照常加粗；隐藏的列不显示，规则留着；合并相同值只合并维度列，与它无关。
  - **列变化时**：规则跟着输出列的别名走，与列宽、对齐一样，列从图表上拿掉后规则留在草稿里但不写进 Spec，加回来时恢复。改了聚合方式或「指标计算」（占比、同比环比、累计）时清除这一列的规则，与清除格式覆盖的时机和原因都相同：原来的门槛和新的数对不上。动态位置按位置的别名设置，切到不是数值的候选时不生效；与显示格式一样，编辑器里暂不能给动态位置设置，只能通过接口。
  - **编辑**：表格和透视表里数值列的字段菜单有「条件格式」，在「显示格式」上方，打开一个对话框，一条规则一行：条件、数值、颜色、图标，每行可以上移和删除，底部「添加规则」，满 5 条时不可用。新规则依次取红、黄、绿、蓝、紫中还没用过的颜色。设了规则的字段块上有「上色」标记，与改过格式的「格式」标记并排。
  - **服务端检查**：只用于表格和透视表；键必须是查询返回的数值列，透视表还必须是它的度量；每列 1 到 5 条；`op`、`color`、`icon` 只能取上面的值，`value` 必须是数。
  - 导出、「查看数据」（3.8）和底部「数据」面板不带颜色，导出照旧写原始值。
- 编辑器的画布和仪表盘用同一个组件画表格，样式所见即所得；底部「数据」面板仍是分页的原始结果。

### 2.9 数据导出

`allowExport` 决定仪表盘上能否导出这张图表的数据，缺省为 `false`。在配置栏「通用」分组里以「允许导出数据」开关设置，对所有角色生效：关闭时，数据开发和管理员在仪表盘上也没有导出入口，做仪表盘的人看到的就是查看者看到的。

- 打开后，能打开仪表盘的人可在图表的「…」操作条中导出数据，按当前筛选、动态选择、联动和下钻（2.10）取完整结果，行列权限照常生效。导出按已保存的仪表盘执行，所以编辑态和页内预览中有未保存的修改时按钮置灰，保存后才能导出；组件属性栏显示该图表是否允许导出。
- 导出保留 `query.limit`。设置了「最多显示行数」时，导出也只含这些行，编辑器在开关旁提示；没有设置时不受显示默认的 1000 行限制。
- 导出查询结果的行，写原始值，不套用 `formats`；表格的 `hiddenColumns` 不导出，透视表导出扁平的行，合计与小计首版不导出。

执行、文件格式、权限复查和导出中心见 [导出设计](exports.zh.md) 第 2 节。

### 2.10 下钻

状态：已实现。

下钻让查看者沿作者排好的层级往下看：在按大区分组的柱状图上点「华东」，选「下钻到省份」，图表换成华东各省份；再点「江苏」，换成江苏各城市。它换掉这张图的一个分组维度，并只看点中的那个值，不筛选别的图表；要筛选别的图表用联动（3.4）。参考 Quick BI 的[钻取](https://help.aliyun.com/zh/quick-bi/user-guide/drilling-filter-interaction-and-hyperlink)：层级配在图表的维度上，与联动并存时由查看者选。

```jsonc
"drill": {
  "alias": "region",          // 查询里一个维度的输出名，它就是第一层
  "levels": [
    { "field": "province", "label": "省份" },
    { "field": "city", "label": "城市" }
  ]
}
```

日期沿同一个字段往细的粒度走：

```jsonc
"drill": {
  "alias": "order_date",      // 按年分组的下单时间
  "levels": [
    { "field": "order_date", "grain": "quarter", "label": "下单时间（季度）" },
    { "field": "order_date", "grain": "month", "label": "下单时间（月）" },
    { "field": "order_date", "grain": "day", "label": "下单时间（日）" }
  ]
}
```

**层级记在图表里，不在数据集里。** 数据集里没有层级，数据集的修改就不会让下游图表的下钻悄悄失效，也不用先给数据集加一种新东西。多张图表反复配同一套层级时，再考虑在数据集里定义，作为编辑器里的预设填进图表，见 [暂缓事项](../backlog.zh.md)。

**Spec**

- `alias` 必填，是 `query.dimensions` 里一个维度的输出名，这个维度的字段和粒度是第一层。`levels` 是往下的各层，按顺序 1 到 7 项，连第一层最多 8 层。每层必填 `field`，可选 `grain`，只有日期字段可以设。编辑器保存时为每层写入 `label`（取字段名，日期附带粒度），因为仪表盘查看者读不到数据集，与动态候选（2.4）相同。
- 一张图表只有一个 `drill`，也就是只有一个维度能下钻。
- 适用的图表：柱状图、条形图、折线图、面积图、组合图和饼图，`alias` 必须是 `x`，带 `series` 的图只钻类目轴，序列不变；聚合表格可以是任意一个维度列，这一列不能在 `hiddenColumns` 里。明细表和其他类型不能下钻。
- `alias` 不能是动态位置的别名（2.4）：动态维度本身就会换字段，叠在一起时不知道下一层接在哪个候选后面。
- 每层只能是数据集的维度，不能是度量或指标。各层（含第一层）的字段和粒度不能重复，也不能与查询里的其他维度相同，否则下钻后有两列一样。
- 同一个日期字段连续的两层，下一层的每个时间段都要完整落在上一层的一个时间段里：粒度按年、季度、月、日、小时、分钟往细走，可以跳过中间的；周会跨月、跨年，所以周后面只能接日、小时、分钟，也不能接在年、季度、月后面。不同字段之间没有这个限制，「大区 → 品类」也可以：点了华东，按品类看华东。
- 保存时按每一层替换后的查询各编译一次，与动态候选一样，避免第一层能看、往下点了才报错。

**作者怎么配**

- 能下钻的维度，字段菜单里有「钻取设置」：图表的类目轴维度、饼图的维度、聚合表格的每个维度列。带序列的图，序列维度上没有这一项。已经有别的维度配了钻取时，这一项不可用，并说明一张图表只能有一个维度下钻。
- 点「钻取设置」弹出同名对话框。第一行是这个维度本身，不能改；下面每层一行：选字段，日期再选粒度，每行可以上移和删除，底部「添加下一层」。日期维度第一次打开时预先填好比它细的粒度（按年分组时是季度、月、日），可以删。删掉全部下层再确定，就是不再下钻。
- 日期的粒度与维度栏一样是年、季度、月、周、日；同一个字段接在上一层后面时，比上一层粗或会跨段的粒度不可选，新加的一层默认取下一个更细的粒度，别的日期字段默认按月。小时和分钟服务端也接受，编辑器里不提供。各层不满足规则时，对话框说明原因，「确定」不可用。
- 配了钻取的字段块上有「钻取」标记，与「格式」「上色」并排。
- 从图表中移除这个维度时一起移除钻取设置。图表类型换成不能下钻的、或这个维度不再是类目轴时，钻取设置留在草稿里但不写进 Spec，换回来时恢复，与条件格式（2.8）相同。改了第一层的粒度、不再满足往细走的规则时，字段块标出问题，不能保存。
- 数据集的影响分析把下钻各层引用的字段也算上（[数据集模型](dataset.zh.md) 8）。

**查看者怎么用**

- 点下钻列上的一个值：柱子（带序列时是其中一段）、扇区、聚合表格里这一列的格子；折线图、面积图和组合图默认不画数据点，在某个类目上方的绘图区里任意位置点击都算点了这个类目。点击先在点击处弹出菜单，选了才执行；按 Escape 或点别处关掉菜单，什么都不做。
- 菜单里的项：
  - 「下钻到省份」，省份是下一层的名称。已经在最后一层时没有这一项。
  - 「图表联动」，这一列是联动来源（3.4）时才有。点到的正是已经联动的值时，这一项是「取消联动」。
  - 一项都没有时不弹菜单，鼠标指针也不变成手形。
- 下钻后，图表筛选器下方、图表上方出现一行面包屑，左侧是图层图标和「下钻层级：」，后面第一项是第一层的名称，再依次是点中的值，如「下钻层级：大区 › 华东 › 江苏」。点其中一项回到那一层；最后一项是当前所在的值，不能点。没有图表筛选器时面包屑紧接在标题栏下方；隐藏了标题栏的图表（3.14）也显示。面包屑占一行，图表相应变矮；在第一层时不显示，不占高度。
- 点中的值按联动（3.4）的规则变成条件：取原始值，不用显示格式后的文字；NULL 是 `IS NULL`，面包屑写「空值」，空字符串写「空字符串」；日期按所在层的粒度换成半开的时间区间，时区用图表查询的时区。面包屑上的其他值照图表上的写法显示。饼图合并出的「其他」和表格的合计行不能点。
- 下钻时输出列的别名不变，只换字段、粒度和列名，所以 `viz`、排序、行数上限、合计、占比的 `within`、累计的 `along`、表头分组和列宽都照常按别名生效。列的显示格式取这一层字段的格式；图表上给这一列设的格式覆盖只在类型相同时套用。
- 下钻条件和其他筛选一样限定范围：同环比时，日期条件与联动一样一起偏移（3.4）；累计从这个范围的起点开始。
- 列级权限只检查这次查询用到的层，即当前这一层和它上面的各层。往下点到看不到的字段时，图表显示「无权限」（[权限设计](access-control.zh.md) 5.2），面包屑仍在，可以返回。

**与其他交互**

- 下钻只改这张图，不筛选别的图表。
- 下钻条件在全局筛选接管、本地筛选和联动之后以「并且」追加，保留查询自身的条件、数据集限制和行级策略。全局筛选、图表筛选、联动、动态选择变了，下钻位置保留，结果为空就显示空，从面包屑返回；定时刷新和「刷新数据」也保留。查询容器的「重置筛选条件」把下钻一起清掉，回到第一层，与它清除联动点击相同。
- **与联动**：联动按第一层的字段映射目标，所以下钻列只在第一层可以联动；下钻到下一层后这一列换了字段，菜单里只剩下钻。表格里其他列作为联动来源不受影响，下钻后照常可选「图表联动」。
- 下钻和返回都清除这张图发出的联动点击，与它的动态选择变化时相同（3.4）：下钻改了它受到的条件和分组，原来点的值不一定还在图上。
- 图表自身筛选和全局筛选的候选不受下钻影响。
- 放大（3.8）与卡片共用下钻位置：放大时下钻，关闭后卡片停在同一层。「查看数据」展示的是当前这一层的结果。
- 导出（2.9）带上当前的下钻路径，导出的是眼前这一层的数据。
- 分享链接（3.10）带上下钻位置：携带当前条件时，打开后各图表停在分享时的那一层。
- 下钻位置是临时状态，不保存，不进撤销历史；每个图表组件、标签页容器里的每个标签各有一份。
- 图表编辑器的预览里同样能点着下钻，规则与仪表盘上相同，菜单里只有下钻；改了图表配置后回到第一层。没下钻时预览照旧在前端拼查询、交给 `/query`；下钻后改由草稿取数接口取数（见下文「提交什么」），由服务端用与仪表盘相同的代码拼查询。这样下钻的翻译规则只有服务端一份：`/query` 只收拼好的查询，用它就得在前端再写一份，两份迟早会对不上。

**提交什么**

取数和导出的请求加一项 `drill`，是从第一层起依次点中的值，最长为 `levels` 的项数：

```jsonc
{ "drill": ["华东", "江苏"] }   // 查看江苏各城市
```

省略或空列表表示第一层。服务端按保存的层级生成条件、替换维度，查看者仍然只能提交取值（3.5）。图表没有下钻、路径比层级长、值不是标量或 null、日期不是读得出日期的文字时，返回 400 `invalid_drill`。处理顺序：先解析动态选择，再按下钻替换维度，然后叠加图表筛选、全局筛选、联动和下钻条件。

图表编辑器里没保存的图表，下钻后用新增的草稿取数接口 `POST /charts/preview/data`。请求与已保存图表的 `POST /charts/{id}/data` 相同（`filters`、`selections`、`drill`、`diagnostics`、`refresh`），另加必填的图表草稿 `spec`，与草稿候选接口（3.6）的做法一致。服务端按与已保存图表相同的规则校验草稿、拼查询并执行，不写库；与其他草稿接口一样需要数据开发角色（第 5 节）。已经保存、在编辑器里只读打开的图表照旧用 `POST /charts/{id}/data`。

**实现顺序**

原计划每一步做完都能在页面上试、提交后再做下一步；实际三步一起实现、测试，一起提交：

1. 钻取设置：服务端 Spec 的 `drill`、保存校验和影响分析；图表编辑器字段菜单的「钻取设置」对话框和字段块的「钻取」标记。可以配置、保存，重新打开后还在。
2. 在图表编辑器的预览里下钻：图表取数接受 `drill`，新增草稿取数接口，点击弹出菜单，面包屑。
3. 仪表盘：仪表盘取数、草稿预览和导出接受 `drill`；点击弹出菜单，联动也改为先弹菜单（3.4）；面包屑；与放大共用、重置时清除；示例内容（`make dev-seed-content`）加几张能下钻的图表。

**第一版不做**，见 [暂缓事项](../backlog.zh.md)：在数据集里定义层级；下钻后在下一层继续联动或同时筛选别的图表；下钻到明细；散点图、矩形树图、漏斗图、热力图、桑基图的下钻和透视表的展开折叠；点中一个值后临时选维度往下看。

### 2.11 数据集参数

状态：已讨论，待实现。

数据集 SQL 里的参数（[数据集模型](dataset.zh.md) 4）原来只能取数据集的默认值。图表可以在 `filters` 里放以参数为目标的筛选器：作者在图表里给参数另定一个值，或者让查看者改。

参数只在筛选器做不到时才用，见 [数据集模型](dataset.zh.md) 4 的「什么时候用参数」。只为缩小范围的条件，把那一列输出出来、用字段筛选器就够了：条件加在数据集 SQL 外层，数据库会把它推进 SQL 里，查看者还有候选、日期范围、全局筛选、联动和下钻。

```jsonc
"filters": [
  // 下拉：查看者从作者写的选项里选
  { "id": "p_region", "param": "regions", "label": "大区",
    "control": { "type": "select" },
    "options": ["华东", "华南", "华北"],
    "value": ["华东", "华南"] },           // 省略时跟随数据集的默认值

  // 输入：查看者自己填
  { "id": "p_dt", "param": "biz_date", "label": "业务日期",
    "control": { "type": "input" } },      // 默认值跟随数据集，如 today-1d

  // 固定：没有 control，查看者看不到
  { "id": "p_top", "param": "top_n", "value": 20 }
]
```

**Spec**

- `param` 是数据集声明的参数名，与 `field` 二选一。参数筛选器没有 `op`、`aggregation` 和 `dependsOn`，别的筛选器也不能 `dependsOn` 它：参数只是一个值或一组值，`=`、`IN` 写在 SQL 里。
- `control.type` 是 `input` 或 `select`。省略 `control` 就是固定值，查看者看不到也改不了，这时必须写 `value`。有 `control` 时 `label` 必填，编辑器默认填参数的显示名。
- `input`：控件由参数类型决定。文本是输入框，整数和小数是数字框，日期选一天，时间选日期和时间；多值参数可以填多个值，每行一个或用逗号分隔，与字段筛选器的「手动输入」相同。布尔参数没有 `input`。
- `select`：`options` 是作者写的选项，按写的顺序显示，最多 500 项，不能重复；多值参数是多选下拉。布尔参数的选项固定是「是」「否」，不写 `options`。
- `value` 是默认值。省略时跟随数据集参数的默认值，数据集改了默认值，图表跟着变；作者在图表里改过才写进来。`select` 的 `value` 必须在 `options` 里。
- 查看者看到的选项是 `options` 加上当前的默认值，所以选项里始终有默认值。默认值不在 `options` 里时排在最前面，这只会发生在跟随数据集、而数据集后来改了默认值的时候。
- 日期参数的选项和默认值可以是相对日期，写法与数据集的默认值相同（`{ "relative": "today-1d" }`），控件上显示为「昨天（10-21）」：`today` 是今天，`today-1d` 是昨天，`today+1d` 是明天，其余写作「3 天前」「3 天后」。按查询时区（[查询 IR](query-ir.zh.md) 3.9）计算。
- 一张图表里每个参数最多一个参数筛选器。已经写在 `query.params` 里的参数不能再有参数筛选器：`query.params` 是始终成立的值，与 `query.filter` 的地位相同，只能通过接口写，查看者改不了。
- 选项和默认值按参数类型校验：多值参数的 `value` 是列表，单值参数是单个值。

**空值**

- 有的参数**离不开值**：数据集里勾了必填，或者 SQL 里有写在 `[[ ]]` 外面的占位符。其余参数可以不给值，这时它所在的 `[[ ]]` 整段去掉，也就是不限。
- 与字段筛选器一样，空表示不限，不是恢复默认值：查看者清空输入框或取消全部选择，参数就不传值。在查询里，单值参数显式传 `null`、多值参数传 `[]` 都是这个意思（[查询 IR](query-ir.zh.md) 3.10）。
- 离不开值的参数，控件不能清空：输入框空着时不提交，提示必须填写；多选至少留一项。默认值也不能为空：跟随数据集、而数据集也没有默认值时，作者必须在图表里写一个，否则不能保存。
- 能不给值的参数，默认值也可以是空：作者取消全部默认选择，打开时就是不限。这时 `value` 写成 `null` 或 `[]`；省略 `value` 才是跟随数据集。

**作者怎么配**

- 数据集有参数时，图表编辑器左侧字段列表的最下面多一组「参数」，列出各参数的显示名和类型。参数只能拖到筛选器栏，也可以点一下，然后打开「参数设置」对话框；已经在筛选器栏里的参数标出「已在筛选器栏」，不能再加。
- 「参数设置」对话框：
  - 显示名。
  - 「显示为图表筛选器」：不勾选是固定值，只填一个值（多值参数是一组值）；勾选后选「输入」或「下拉选择」。
  - 下拉选择：选项列表，每行一项，可以添加、删除和上移。第一次打开时，列表里是数据集的默认值，多值参数是默认值的每一项。每项前面的单选框（多值参数是复选框）标出默认值。
  - 默认值：开头写「跟随数据集：昨天（10-21）」。作者改了默认值就不再跟随，这里出现「恢复为数据集的默认值」。
  - 值按参数类型填写，与数据探索里填参数的默认值相同：日期可以写 `today`、`today-1d` 这样的相对日期，选项旁边显示它现在是哪一天，如「昨天（10-21）」；多值参数的默认值和固定值用逗号分隔。
- 参数筛选器在筛选器栏里排在字段筛选器前面，写进 Spec 时也在前面：参数决定读哪些数据。字段块上有「参数」标记，写着当前的默认值。预览上方的控件与字段筛选器一样可以试选，不改默认值。
- 数据集里的参数删了、改了类型或多值，这个参数筛选器在筛选器栏里标出问题，删掉或改好才能保存。

**查看者怎么用**

- 控件和字段筛选器在同一行：图表编辑器的预览、仪表盘的卡片、放大（3.8）里都一样。
- 下拉里显示选项的值本身，没有另设的显示名，见 [暂缓事项](../backlog.zh.md)。

**提交什么**

- 取值与字段筛选器一样按筛选器 ID 提交：图表取数放在 `filters`，仪表盘取数放在 `chartFilters`（3.5）。例如 `{ "p_region": ["华东"], "p_dt": "2026-10-20" }`。省略的用图表的默认值；`null` 或 `[]` 表示不传值。
- 服务端检查：值的类型；`select` 的每个值必须在查看者看到的选项里；`input` 只接受具体的值，不接受相对日期，原样传回的默认值除外。不合格的返回 400 `invalid_param_value`；离不开值的参数提交了空值，返回 400 `missing_param`。固定的参数筛选器不接受提交，与固定条件相同。
- 服务端把取值写进查询的 `params`，覆盖数据集的默认值。
- 查看者读不到数据集，所以图表的读取接口（`GET /charts/{id}`，以及仪表盘返回的 `charts`）另带 `params`：按筛选器 ID 给出每个显示的参数筛选器的类型、是否多值、能否清空（`needsValue`）、当前的默认值和下拉的选项，按数据集当前的修订算出。图表编辑器有数据集，按同样的规则自己算。

**与其他功能**

- 字段筛选器的候选，以及全局筛选从这张图取的候选（3.2），数据集参数都用这张图当前的取值：换了一天的快照，候选也跟着换。
- 同环比只偏移时间字段上的筛选条件，参数不偏移（[查询 IR](query-ir.zh.md) 3.5）。参数是业务日期时，本期和同期读的是同一天的数据。
- 全局筛选器不能关联参数，见 [暂缓事项](../backlog.zh.md)。全局筛选的接管和「使用图表筛选」只涉及字段筛选器，参数筛选器总是生效。联动和下钻不改参数。
- 分享链接（3.10）带上参数的取值，归入「图表筛选」一类。打开链接时，下拉的取值已经不在选项里的，与其他失效的条件一样丢弃并提示。
- 导出（2.9）按当前的参数取值导出。查询诊断和审计照常记下绑定的参数值。
- 数据集的影响分析（[数据集模型](dataset.zh.md) 8）列出用到这个参数的图表，参数筛选器和 `query.params` 都算。

**实现顺序**

三步一起实现、测试，一起提交：

1. 服务端：Spec 的参数筛选器和保存校验；图表和仪表盘取数、候选、导出、分享按参数筛选器的取值执行；查询引擎里单值参数的 `null` 改为不传值；影响分析列出用到参数的图表。
2. 图表编辑器：字段列表的「参数」组、「参数设置」对话框、筛选器栏和预览上的控件。
3. 仪表盘卡片上的控件和分享；数据探索参数区的引导（[数据集模型](dataset.zh.md) 4）；示例内容（`make dev-seed-content`）加一个带参数的数据集和几张用到参数筛选器的图表。

**第一版不做**，见 [暂缓事项](../backlog.zh.md)：全局筛选器关联参数；下拉选项的显示名。

## 3. 仪表盘 Spec

```jsonc
{
  "specVersion": 1,
  "layout": {
    "columns": 96,
    "items": [
      { "id": "w1", "type": "chart", "chartId": "ch_3f8k…", "x": 0, "y": 0, "w": 8, "h": 4 },
      { "id": "w2", "type": "chart", "chartId": "ch_9c2m…", "x": 8, "y": 0, "w": 4, "h": 4 }
    ]
  },
  "filters": [ /* 全局筛选器，见 3.2 */ ],
  "queryContainer": { "x": 0, "y": 0, "w": 12, "h": 2 }
}
```

### 3.1 布局

- 默认 96 列细分栅格。`x`、`w` 以列为单位，`y`、`h` 以行为单位。可选 `layout.grid` 保存每格高度、横纵格间距、容器间最小纵向留白和自动补位，详见下文。
- `items[].id` 在仪表盘内唯一，是全局筛选器引用组件的方式。
- `type` 是 `chart`、`title`、`text` 或 `tabs`，标题和文本组件见 3.12；仪表盘级的标签页见 3.13；组件作为容器的外观、空的图表容器见 3.14；一个容器里放几张图、用标签切换的标签页容器（`tabs`）见 3.15。
- 组件引用图表的 ID，不内嵌图表定义。

编辑工作台保留最左侧仪表盘目录树岛屿，右侧编辑区域分为顶部操作栏、窄工具栏、中央画布和可收起的右侧属性栏。顶部显示名称和重命名图标、撤销/重做、页面设置、预览和保存；保存状态仅在工作台底部展示。名称默认只读，点击编辑图标后输入，Enter 或失焦提交，Escape 取消。工具栏提供图表库、标题、文本、全局筛选器和图表联动；图表库复用图表编辑页的 ResourceTree，支持目录层级展开、搜索、拖入画布和点击添加，不提供源图表的移动或删除操作。

画布单独滚动，点击图表只选中组件，不自动展开属性栏；属性栏已经打开、显示的是页面设置或查询容器设置时，点击组件切换到该组件的属性，点击查询容器切换到查询容器设置（属性栏显示页面设置或组件属性时）；图表库打开时点击组件只选中，不切换，以便继续往选中的空容器里放图。通过图表操作中的配置按钮进入属性栏后，可修改网格宽高、查看关联筛选器、进入源图表或移除组件。点击空白处仅取消组件选中，页面设置只由顶部按钮打开。页面设置包含名称、描述与画布布局，仪表盘内容显示图表、标题和文本各有几个，最后是修订历史（4.1）；布局以分段控件展示，目前只有「网格布局」，下方提供网格配置。名称、描述及网格配置先暂存，属性栏底部的整行「应用」按钮仅在存在未应用变更时启用；点击后一次更新画布并进入撤销历史，右上角「保存」才写入服务器；未应用的输入不会被保存。网格配置偏离默认值时显示单项重置图标，重置也需应用。应用时空值恢复原值，越界值限制到允许范围；支持撤销、重做，切换面板保留待应用输入，离开页面时提示未应用修改。选择组件或切换面板不写入仪表盘 Spec。所有移除组件入口均二次确认，确认后同时清理关联筛选器；源图表不被删除，撤销可一起恢复组件与关联。

图表右上角以「…」收起操作，点击后图标操作条向左展开；再次点击、点击外部或按 Escape 收起。编辑态包含刷新、组件配置和移除，有全局关联时也提供筛选来源切换；查看态和页内预览包含刷新及有全局关联时的筛选来源切换。图标附带操作提示，收起时不进入键盘焦点顺序。

图表筛选控件根据卡片宽度自动换行，图表内容按标题与筛选区占用后的实际剩余高度绘制，随卡片尺寸、筛选行数和面板开合调整。卡片过矮时在内部纵向滚动，保留最小图表显示空间，避免筛选与图表重叠。

全局筛选器通过左侧工具栏打开三栏弹窗，并收起右侧属性栏。左栏新增、选择、重命名或删除筛选器；中栏上方选择关联图表，下方选择各图表的映射字段；右栏配置精确筛选、条件筛选或手动输入、默认值、控件样式及级联关系。确认一次性提交整组修改，取消不改变草稿。全局控件统一放入「查询容器」，不显示标题栏，通过空白区域拖动、右侧调整宽度（手动高度时通过右下角调整大小），与图表共享网格；位置尺寸保存为可选的 `queryContainer`，不参与图表数据查询与字段映射。右上角「…」提供重置筛选条件、设置与移除操作；「设置」打开右侧查询容器设置面板，按顺序展示「容器设置」「图内控件样式」「查询设置」，分别配置容器高度、控件样式和查询触发方式，样式复用图表的横向/纵向、紧凑/标准/宽松配置，保存在仪表盘 `filterStyle` 中并应用于预览和查看态。确认移除会清空全部全局筛选器及容器布局、样式，撤销一次可恢复。旧仪表盘未设置该字段时，在图表上方以 96 列、8 个细分行展示，首次布局或配置修改后保存实际位置。编辑画布和页内预览不重复显示仪表盘名称与描述，也不显示顶部数量栏和底部操作提示栏；名称保留在顶部操作栏。画布直接展示全局筛选控件与图表（含图表自身筛选控件），通过草稿只读取数和选项接口实时应用未保存的筛选配置。被全局条件接管的图表筛选器灰显，可切回图表条件并恢复全局条件。编辑与预览切换保留临时取值、接管状态、草稿、面板与撤销记录，不创建或更新仪表盘。试选不修改默认值，不进入编辑历史；删除或修改筛选定义会清理对应失效取值，修改字段映射会重新加载选项。

名称、描述、布局与全局筛选作为整体草稿记录最多 100 步撤销/重做，连续文字输入合并，移除组件与清理其筛选关联为同一步。支持 Ctrl/⌘+Z、Ctrl/⌘+Shift+Z 和 Ctrl+Y；输入框与对话框保留自己的撤销行为。自动网格压紧不新增历史。保存只在存在修改且名称非空时可用，成功后将当前草稿记为保存基准而不清除历史；保存期间锁定编辑，失败保留修改。

### 3.2 全局筛选器

全局筛选器独立设置字段、操作符、控件和默认值，再显式关联多张图表。候选是图表数据集的全部维度、度量（按求和筛选结果）、指标，以及图表已配置的指标的并集，不要求图表先配置本地筛选器：

```jsonc
"filters": [
  {
    "id": "g_user",
    "label": "用户ID",
    "op": "in",
    "control": { "type": "search_select" },
    "targets": [
      { "item": "w1", "field": "uid" },       // A 图表数据集的 uid
      { "item": "w2", "field": "user_id" }    // B 图表数据集的 user_id
    ],
    "optionsFrom": "w1",
    "default": []
  }
]
```

- `targets` 按仪表盘组件绑定 `field`（数据集字段）或 `measure`（图表查询指标的输出名），二选一。`field` 可附带 `aggregation` 明确聚合方式，例如 `{ "item": "w1", "field": "amount", "aggregation": "sum" }`；不能同时指定 `measure` 与 `aggregation`。一个组件可以关联多个字段，各映射条件之间为「并且」。
- 不带聚合的数据集维度和度量进入 `WHERE`；数据集指标、带 `aggregation` 的字段和图表指标进入 `HAVING`，按每张图表自己的维度分组。明细表不支持聚合目标。
- 图表引用的数据集指标与该数据集指标去重；原始度量与它的聚合指标是不同的候选。各目标的字段类型和明细/聚合层必须兼容，不能把文本与整数、明细与聚合混在一个筛选器里。
- 多个全局筛选器可以绑定同一语义字段，条件之间为「并且」，例如分别设置上下限；这些全局条件共同替换本地条件。不同数据集需显式映射，不能仅凭字段同名关联。
- 被接管时，全局的**完整条件**替换本地同字段条件，包括操作符和值。图表本地控件保持原来的形式和值，置灰并提示当前条件已被覆盖。空值表示解除该字段限制，仍保持接管。
- 未冲突的本地筛选器继续生效；`ChartSpec.filters` 中的固定条件遇到同字段绑定也被替换。需要始终成立的查询约束保留在 `query.filter`/`query.having` 或数据集定义中。
- 每个关联组件可以切到「使用图表筛选」：忽略作用于该组件的全部全局条件，恢复图表原有条件和用户自己的取值；也可以「恢复全局筛选」。这是查看时的组件状态，不修改已保存图表。
- 下拉选项取自 `optionsFrom` 指定的组件，默认是第一个 target。不取并集，那样要对每个数据集各查一次。
- `dependsOn` 引用同一仪表盘内的全局筛选器 ID，使用 2.5 的级联校验与候选规则。
- 新建全局筛选器时，可预选同数据集、同语义字段的组件，制作者可以取消。这只是预填，不保存就不生效。
- 保存时把静态图表指标绑定规范化：数据集指标转为 `field`，聚合的度量和维度转为 `field + aggregation`；动态指标保留 `measure` 别名。因此移除静态指标的显示列不影响其结果筛选，必要时转为仅参与 `HAVING` 的指标。删除仍被绑定的动态位置、修改成不兼容候选或切换成不兼容数据集时，拒绝保存并指出依赖仪表盘；删除本地图表筛选控件不影响全局绑定。

全局时间是日期字段上的普通全局筛选器。可以用单日期、日期范围或相对时间控件，关联图表的日期字段可以不同，本地日期控件形式也可以不同。

### 3.3 筛选条件如何叠加

- 按语义身份判断冲突：原始字段、数据集指标、某字段的特定聚合分别识别；`SUM(amount)` 与 `AVG(amount)` 是不同身份，原始 `amount` 也不同。全局条件替换相同身份的图表条件；剩余条件之间为「并且」。
- 明细条件与聚合条件分开合并。它们在图表 `query.filter`、`query.having` 自身条件之外追加，查询里的「或」不会吞掉追加条件。
- 数据集本身的 SQL、参数和过滤限制始终保留。

### 3.4 点击联动

仪表盘编辑器左侧「图表联动」配置显式的来源和目标。定义保存为可选的 `links`，旧仪表盘无需迁移：

```jsonc
"links": [{
  "id": "region_link",
  "label": "地区联动",
  "source": { "item": "w1", "column": "region" },
  "targets": [{ "item": "w2", "field": "area" }]
}]
```

- 来源是仪表盘组件 ID 和查询输出列名（别名优先），目标是其他组件 ID 和数据集字段 key。每条联动可以关联多个目标组件，但每个目标组件只能映射一个字段。跨数据集必须显式映射；同名字段不自动关联，同一个图表在不同组件中也分别配置。
- 第一版来源支持柱状图、条形图、饼图的分类，以及聚合表的维度列和明细表的字段列。动态维度、聚合指标、透视表、合计行和饼图合并出的「其他」不能作为来源。
- 目标必须是类型兼容的明细层字段，不能是聚合指标、动态位置或来源组件自身。日期与时间戳可以关联，但小时、分钟及未分组的时间戳不能映射到 DATE，避免丢失时间精度。
- 点击来源上的值先在点击处弹出菜单，选「图表联动」才生效，与下钻共用这个菜单（2.10）；按 Escape 或点别处关掉菜单，什么都不做。早先点一下就联动；有了下钻后，同一次点击可能是下钻也可能是联动，所以统一改为先弹菜单，只有联动时也一样。表格的格子同样如此。
- 点击取原始值，不用显示格式后的文字。每条联动单选，点到已经联动的值时，菜单里这一项是「取消联动」；仪表盘顶部列出当前条件，可逐条取消；条件里的值照来源图表上的写法显示，分享对话框里列出的联动条件也是。NULL 和空字符串是有效选择，分别显示「空值」和「空字符串」。柱子和扇区强调选中分类，表格中被选中的字段值加粗。
- 请求中的 `links` 是联动 ID 到标量值的映射。缺省 ID 表示不限制，显式 `null` 表示 `IS NULL`。字段、操作符、粒度均来自保存的配置；查看者不能提交任意过滤条件。
- 联动在全局筛选接管和本地筛选解析完成后以 AND 追加，保留查询自身条件、数据集限制和行级策略。「使用图表筛选」只退出全局接管，不取消联动。多条联动也取交集；没有结果时正常显示空结果，不放宽条件。
- 日期分类转换为半开时间区间 `[start, end)`。月、周等使用来源查询的粒度与工作空间的周起始日；DATE 保持日历日期，不受夏令时影响；时间戳按来源查询时区解释，再转换到目标查询时区。未分组 DATE 按天，未分组时间戳按当前结果展示的秒精度匹配。
- 同环比查询复用 `time` 条件，同时偏移日期联动和原有本期范围，其他字段联动保持不变。空日期与同环比所需的有限本期范围取交集，结果为空，不扩大比较范围。
- 编辑、预览、查看使用同一取数规则；在菜单里选了「图表联动」就立即生效，即使全局查询设置为手动，也只使用已经提交的全局条件。编辑与预览切换保留点击值，点击不进入撤销历史、不保存成默认条件。来源受到的筛选实际生效值、动态选择、下钻位置（2.10）、关联图表或映射改变时清除相应临时点击，重置筛选清除全部点击。来源点击改变或取消时，清除下游图表原先的点击，避免继续使用已过期的分类；修改普通目标图表的本地筛选不会取消来源点击。移动、缩放组件不会清除点击。
- 图表本地和全局筛选候选接口接受相同的点击上下文，按对应来源组件受到的联动限制候选；联动不会自动产生新的点击事件。
- 新建或修改联动需要 `dataset.use`；只有内容编辑权限时可保留已有联动并排版，移除组件时同时清理相关映射。组件移除及映射清理是同一步撤销。修改被联动使用的图表时校验依赖，拒绝删除来源列、换成不支持的图表类型或破坏字段类型兼容性的改动。

### 3.5 查看者能提交什么

图表取数 `POST /charts/{id}/data` 接受 `filters`（本地图表筛选 ID 到值）和 `selections`（动态位置 ID 到候选 ID）。仪表盘取数 `POST /dashboards/{id}/items/{itemId}/data` 接受以下请求，`selections` 属于当前组件的图表：

```jsonc
{
  "filters": { "g_region": ["华东"] },
  "chartFilters": { "f_total": 1000 },
  "selections": { "metric": "average" },
  "useChartFilters": false,
  "links": { "region_link": "华东" },
  "drill": ["华东"]
}
```

`drill` 是下钻路径上依次点中的值（2.10），图表取数也接受。筛选 ID 未出现在请求中时，图表用 `value`、全局用 `default`；显式 `null`、空选择等表示不限制，而非恢复默认值。动态位置省略时用第一项，空字符串仅对允许为空的维度有效。`useChartFilters` 默认 false，接管期间提交的本地冲突值被忽略，切回图表模式后才生效。字段、操作符、关联范围和动态候选来自已保存配置；未知筛选/选项和修改固定条件的请求会被拒绝，查看者不能提交任意查询。参数筛选器（2.11）的取值也按筛选 ID 放在 `filters` 和 `chartFilters` 里，下拉的取值只能是下拉里有的选项。

仪表盘组件结果的 `meta.overriddenFilters` 返回实际被接管的本地图表筛选 ID 数组，按解析动态选择后的字段/聚合身份计算；`useChartFilters: true` 时返回空数组。客户端以此灰显相应控件，可准确处理动态指标从 SUM 切到 AVG 后的冲突变化。这个结果属性是可选扩展，普通 `/query` 和单独图表结果不必提供，兼容旧消费者。

仪表盘作者通过 `POST /dashboards/preview/items/{itemId}/data` 提交同样的值及必填仪表盘草稿 `spec`。草稿中的组件仍只引用已保存图表。图表作者在编辑器里下钻时，通过 `POST /charts/preview/data` 提交图表取数的值及必填图表草稿 `spec`（2.10）。草稿预览与保存一样需要数据开发角色，取数和候选值都不会写库。

### 3.6 候选接口与兼容

交互候选使用 POST 传递当前上下文，不把临时值写回 Spec：

| 场景 | 路径 | 请求 |
|---|---|---|
| 已保存图表 | `/charts/{id}/filters/{filterId}/options` | `ChartOptionsRequest`：`filters`、`selections`、`search`、`related` |
| 图表编辑草稿 | `/charts/preview/filters/{filterId}/options` | 上述字段及必填图表 `spec`；筛选器可尚未保存，须存在于草稿中 |
| 已保存仪表盘全局筛选 | `/dashboards/{id}/filters/{filterId}/options` | `DashboardFilterOptionsRequest`：`filters`、`chartFilters`、`selections`、`useChartFilters`、`search`、`related` |
| 已保存仪表盘组件自身筛选 | `/dashboards/{id}/items/{itemId}/filters/{filterId}/options` | 同上；`filterId` 是组件图表内的 ID |
| 仪表盘草稿全局筛选 | `/dashboards/preview/filters/{filterId}/options` | 仪表盘候选请求及必填仪表盘 `spec` |
| 仪表盘草稿组件自身筛选 | `/dashboards/preview/items/{itemId}/filters/{filterId}/options` | 同上 |

所有表内路径使用 POST。`related` 默认 false，只应用祖先；true 允许反向匹配关联分量。`search` 对文本字段做字面量包含查找。仪表盘全局候选的 `selections` 属于 `optionsFrom` 对应图表，组件候选的则属于当前组件。`useChartFilters` 控制组件自身候选是否恢复本地条件，不会解除全局候选定义自身的级联约束。

返回 `{ "values": [...], "truncated": false }`，最多 500 个不同的非 NULL 值；聚合布尔结果直接提供 `[false, true]`，其他聚合结果不枚举。候选沿用数据集来源、参数、原查询约束与适用的固定筛选，不因读取选项放宽权限。即使只用部分级联值约束候选，也会检查请求提供的筛选 ID 和可修改性。

存在聚合结果条件时，先按原图表维度与日期粒度筛出合格分组，再取其中的候选值，不改按候选字段计算聚合。NULL 分组键仍可正确匹配；搜索仅缩小外层候选，原图表的排序、条数限制与偏移不截断候选来源。

已有图表和全局筛选的 GET `/options?search=...` 保留，按保存的默认值解析动态/级联上下文；需要反映当前试选值时使用 POST。新增请求字段、结果元数据和可选 Spec 属性不改变旧接口调用方式，旧 `last`/`current`/`start`/`end` 时间值与数组数值范围仍接受。

### 3.8 放大与查看数据

图表的「…」操作条中有这两项，查看态和页内预览中提供，编辑画布上没有。

- **放大**：在接近全屏的对话框里显示这张图表，带图表自身的筛选和动态维度控件。与原卡片共用同一份筛选、动态选择、联动和「使用图表筛选」状态：放大时改的条件，关闭后在仪表盘上继续生效；在放大的图表上点击联动，同样作用于其他图表。打开时直接使用已经取到的结果，不重新取数。Escape 或关闭按钮退出。
- **查看数据**：用表格展示这张图当前的查询结果行，也就是图表已经取到的数据，不发新查询。列名与图表的列标题相同，值按字段的显示格式显示。结果被「最多显示行数」或默认返回行数截断时，在表格上方注明。透视表、桑基图等显示扁平的行，合计与小计不在其中；表格隐藏的列（`hiddenColumns`）不显示。这几点与导出相同（2.9）。
- 查看数据不受 `allowExport` 限制，展示的是图表上已经呈现的数据；不提供下载，下载仍走导出（2.9）。
- 不提供查看底层明细。明细比图表展示的数据多得多，需要另外考虑授权。

### 3.9 全屏与定时刷新

- **全屏**：查看态工具栏的「全屏」让仪表盘盖住整个页面，顶栏和左侧目录都被遮住，浏览器允许时同时进入浏览器全屏；Escape 或「退出全屏」退出，全屏时不显示「编辑」。进入浏览器全屏的是整个文档而不是仪表盘元素，因为下拉菜单和对话框挂在文档末尾，只让仪表盘元素全屏会把它们挡在外面；因此全屏时筛选、联动、图表菜单、放大和查看数据照常可用。浏览器不允许全屏时（例如内嵌在其他页面里），仍然盖住整个页面。
- **刷新间隔**：作者在页面设置的「定时刷新」中设置默认间隔，保存为可选的 `autoRefresh`（秒），只能是 60、300、900、1800、3600，其他值保存时报 `invalid_auto_refresh`；缺省不定时刷新。查看者可以在工具栏临时改成其他间隔或关闭，只对当前页面有效，不保存。
- 只在查看态生效，编辑画布和页内预览不定时刷新。页面不可见（切到其他浏览器标签页、窗口最小化）时暂停计时；回到页面时如果已经超过间隔，立即刷新一次。开启时工具栏显示当前间隔。浏览器对后台标签页的计时器另有节流，所以后台标签页可能晚于间隔刷新，切回前台时补上。
- 每次刷新已经取过数的图表（3.11），使用已经应用的条件：手动查询模式下尚未点「查询」的输入不参与。筛选候选不随之刷新。
- **与缓存的关系**：定时刷新的请求带 `maxAge`，而不用 `refresh`。缓存中的结果，其语句开始执行的时间距今不足 `maxAge` 就直接使用，否则查数据库并写回缓存（[查询 IR](query-ir.zh.md) 6.6）。`maxAge` 比间隔略短：间隔减去其十分之一，最多减 30 秒，即 1 分钟间隔为 54 秒、1 小时为 3570 秒。这样本页面上一次取到的结果在下一次刷新时一定算过期，不会因为网络和计时器的误差被当成新结果而跳过一轮；别人在这之间取到的结果则直接使用。所以每张图大约每个间隔查一次数据库，每个人看到的数据都不比一个间隔更旧；用 Redis 缓存时多个实例之间也是这样。直接用 `default` 会读到最长保留 10 分钟的缓存，每分钟刷新形同虚设；每次都用 `refresh` 则每个打开页面的人各查一次，50 人开着一个 20 张图、每分钟刷新的仪表盘，每分钟要查 1000 次。
- 手动的「刷新数据」和「刷新图表」不变，仍用 `refresh`，一定查数据库。
- 数据源设为「不缓存」时，每次定时刷新都查数据库，同时在跑的相同查询仍然合并（[查询 IR](query-ir.zh.md) 6.7）。

刷新时的反馈。定时刷新每分钟发生一次，查询又常常只要几十毫秒，没有反馈时看不出它是否在工作；反过来，每次刷新都让图表闪一下或弹出提示，在大屏上又太吵。所以：

- **工具栏显示数据时间**：查看态工具栏左侧显示「数据更新于 14:32:05」，取所有图表中最旧那份数据从数据库取得的时间（结果的 `cachedAt`，查数据库和命中缓存的结果都有），不是「上次刷新的时间」：复用了别人 20 秒前取到的结果时，显示的就是 20 秒前。不是今天的数据带上日期。有图表正在取数时改为「正在取数…」并转动图标；有图表失败时在后面加「N 张图刷新失败」。开启定时刷新时，悬停显示下次刷新的时间。不显示秒级倒计时，大屏上跳动的数字分散注意力。
- **再次取数时保留旧图**：图表第一次加载显示「加载中」；之后再取数（刷新、定时刷新、改条件）都保留已经画好的图，卡片顶部出现一条细进度条，新结果到了直接替换。进度条在等待超过 300 毫秒后才出现，几十毫秒就返回的刷新不会闪。改了条件时，旧图在新结果到来前变淡，免得被当成新条件的结果；同样条件的刷新不变淡。
- **刷新失败不清空**：同样条件的再次取数失败时，保留上一次的图，标题旁出现警告图标，悬停显示「刷新失败，显示的是 14:31:05 的数据。点击重试。」和数据库的报错，点击重试（重试的仍是刷新）。改了条件后取数失败，则显示错误和重试按钮，不保留旧图：旧图回答的是之前的条件。
- 不在每次刷新时弹出提示，每分钟一次太吵。

### 3.10 分享链接

查看态工具栏增加「分享」，打开的对话框显示仪表盘的链接和复制按钮。

- 当前条件与默认不同时，对话框里多一个复选框「携带当前条件」，默认不勾选；条件与默认相同时不显示。默认不带有两个原因：带条件的链接有有效期，过期后接收者看到的是默认条件，而不带条件的链接就是仪表盘的地址，一直有效，随手复制的链接不应该一个月后悄悄失效；另外筛选值会被接收者看到（见下文）。
- 当前条件包括：全局筛选的取值、各图表自身筛选的取值、联动点击、动态维度和动态指标的选择、各图表「使用图表筛选」的切换、各图表的下钻位置（2.10），各标签页容器当前所在的标签（3.15），以及分页的仪表盘当前所在的页（3.13）。手动查询模式下只带已经应用的条件。下钻位置按图表组件记，标签页容器里每个标签的图表各记各的；记的是面包屑上的内容：第一层的名称，以及每层点中的原始值和它在图上的写法。只有值、没有写法时（AI 助手的出处链接由服务端保存，见 [AI 助手](ai-assistant.zh.md) 12.3），打开时按这一层的粒度写出来。
- **带哪些条件**：勾选后，下面按类别列出与默认不同的条件，每类一行：全局筛选、图表筛选（含「使用图表筛选」的切换）、联动、维度和指标、下钻、所在页和标签，只列有变化的类别。下钻写作「图表名称：华东 › 江苏」，值的写法与面包屑相同。每行一个复选框，默认全部勾选，可以去掉某一类；后面写出具体内容，例如「大区：华东、华南；金额 ≥ 200」，太长时截断，悬停显示全部。值多时沿用筛选控件的写法「华东、华南、华北 等 5 个」。去掉的类别不带，接收者看到的是这一类的默认条件。全部去掉时等于不带条件，链接回到仪表盘的地址，并注明这一点。
  - 按类别而不是按单个筛选器勾选：级联的全局筛选中，子筛选的取值依赖父筛选，单独去掉父筛选会带出对不上的组合；整类带或不带不会。界面也不会因为条件多而很长。
  - 每次勾选变化重新保存条件；相同的条件加相同的有效期得到同一个链接 ID。
  - 「打开链接的人会看到这些筛选值」的提醒只在勾选了全局筛选、图表筛选、联动或下钻时显示；维度和指标、所在标签不是数据里的值。
- **条件存在服务端，链接只带短 ID**，形如 `/dashboards/{id}?ws={workspaceId}&view={viewId}`。筛选值（客户名、手机号等）因此不进入浏览器历史、代理和网关的访问日志、聊天软件的链接预览；多选几百个值时链接也不会过长。

```jsonc
// POST /dashboards/{id}/views 的请求体；返回 { "id": "dv_…", "expiresAt": "…" }
{
  "state": {
    "filters": { "g_region": ["华东"] },
    "chartFilters": { "w1": { "f_total": 1000 } },
    "selections": { "w2": { "metric": "average" } },
    "useChartFilters": ["w3"],
    "links": { "region_link": "华东" },
    "drill": { "w4": { "root": "大区", "steps": [{ "value": "华东", "text": "华东" }, { "value": "江苏", "text": "江苏" }] } },
    "tabs": { "w7": "w9" },
    "page": "w21"
  },
  "validDays": 30
}
```

- 存在新表 `dashboard_views`：ID、所属仪表盘、条件、条件及其有效期的摘要、创建人、创建时间、过期时间、最后打开时间。同一个仪表盘的相同条件，以相同的有效期分享时，按规范化后的内容复用同一个 ID，反复分享不会产生新记录。条件创建后不修改，仪表盘删除时一并删除。
- **有效期**：携带条件时，对话框里选择条件的有效期，1、7、30 或 90 天，默认 30 天，从分享时算起，打开不会延长。以相同的有效期再次分享相同的条件时复用同一个 ID，过期时间取两者中较晚的。有效期不同时得到另一个 ID，按所选的时间到期：选过 30 天再选 1 天，得到的是 1 天后到期的链接，已经发出去的 30 天链接仍按自己的时间到期。对话框一勾选就按默认的 30 天保存条件，所以没有被复制过的记录可能留到过期。过期的条件由每小时的维护任务删除。不带条件的链接就是仪表盘的地址，没有有效期。
- 打开已过期或已删除的条件时，仪表盘按默认条件显示，并提示「分享的条件已过期，显示的是默认条件」。
- **工作空间**：仪表盘属于工作空间，接口按会话当前所在的空间查找，所以链接带上工作空间 ID（`ws`）。接收者当前在另一个空间、但能进入链接所在的空间时，页面说明仪表盘在哪个空间，并提供「切换到」按钮，点击后切换并重新打开链接；不自动切换，因为工作空间属于服务端会话，同一浏览器的其他标签页会一起切换过去，正在编辑的内容会写到另一个空间，所以按钮下注明这一点。不能进入时，与没有权限相同。
- **没有权限**：申请访问的流程还没有做，接收者看到无权访问的提示。服务端对看不到的仪表盘返回 404，不透露它是否存在，所以提示写作「这个仪表盘不存在，或者你没有访问权限，可以联系它的作者或管理员」，不区分两种情况。对话框里也用一行字提醒分享的人：只有能打开这个仪表盘的人才能看到。
- **分享不改变权限**。链接不授予访问权：接收者需要能打开这个仪表盘（[权限设计](access-control.zh.md) 4.2），取数按接收者自己的身份执行，行列权限照常生效。能打开仪表盘的人都能创建分享；读取分享的条件同样要求能打开所属仪表盘。
- **筛选值本身对接收者可见**。接收者没有某个客户的行权限时，图表是空的，但筛选框里仍显示这个客户名。勾选携带含有这类值的条件时，对话框提示这一点；对话框里写出了具体的值，分享的人也能看到自己要带出去什么。
- **条件失效**：作者之后删除或修改了筛选器、联动或动态位置，服务端对未知 ID 返回 400（`unknown_filter`、`unknown_link`）。打开链接时，前端先丢弃仪表盘上已经不存在的 ID、动态位置里已经没有的候选，以及形式对不上的取值（`in`、`not_in`、`between`、`not_between` 和多选控件要列表，时间筛选不检查，其余要单个值；联动只接受单个值），其余条件照常应用，并提示「分享的部分条件已失效」。下钻位置同样处理：图表已经不能下钻，或者路径比现在的层级长时，丢弃这张图的下钻位置，它停在第一层。路径里的值不检查：层级改了字段时可能查不到数，从面包屑返回即可，与下钻后别的条件变了相同（2.10）。
- 相对日期保持相对：「最近 7 天」按接收者打开时的日期计算。需要固定的范围，分享前选具体日期。
- 打开后，在接收者修改条件之前，地址中保留 `view` 参数，刷新页面仍是分享时的条件；修改条件后从地址中去掉它。手动查询模式下，分享的全局筛选条件直接作为已应用的条件。
- 携带的只是与仪表盘默认不同的部分：取值等于默认值的筛选、选了第一个候选的动态位置、停在第一层的图表都不带；把有默认值的筛选清空则带上显式的空值。服务端再把空的部分去掉、把「使用图表筛选」的组件排序，相同的条件因此得到相同的摘要。条件最多 64 KB。
- 接口：`POST /dashboards/{id}/views` 保存条件，返回 ID 和过期时间；`GET /dashboards/{id}/views/{viewId}` 读取条件并记下打开时间，已过期或不存在时返回 404 `view_not_found`。两者都要求能打开这个仪表盘，看不到仪表盘时与仪表盘本身一样返回 404。
- 创建分享记审计事件 `dashboard.share`（类别 `content`），详情为条件内容。接收者的取数照常记查询事件。

### 3.11 按需取数与渲染模式（规划）

状态：交互模式的按需取数已实现；完整渲染、就绪信号和打印已暂缓（见 [暂缓事项](../backlog.zh.md)）。没有「打印」，浏览器自带的打印只能打出已经取过数的图表，没滚动到的图表打出来是「加载中」。

仪表盘按用途分两种渲染模式。模式由页面的用途决定，不是作者或查看者的设置。

| 模式 | 用在 | 取数 |
|---|---|---|
| 交互 | 查看态、编辑画布、页内预览 | 图表距离可视区域一屏以内时开始取数 |
| 完整渲染 | 打印、导出 PDF，以后的截图和订阅推送 | 全部图表立即取数，关闭动画，全部完成后发出就绪信号 |

- **交互模式**：取过数的图表滚出可视区域后保留结果，不卸载也不重新取数。筛选、联动、动态选择变化以及「刷新数据」时，只有取过数的图表立即重新取数（其他标签页里的除外，见 3.13）；从没进入过可视区域的，等进入时按当时的条件取数。
  - **「一屏以内」按页面的滚动区域算**：查看态是仪表盘的内容区，全屏时是盖住页面的那一层，编辑画布和页内预览是画布的滚动区。可视部分向上下左右各扩出一个可视区域的大小，图表卡片的任何部分进入这个范围就开始取数。进入或退出全屏后按新的滚动区域计算。滚动区域由页面指明，不从样式推断：只设了横向 `overflow` 的元素，纵向也会算成可滚动，推断容易认错。没有指明时按浏览器窗口算。
  - 图表自身筛选控件（下拉、平铺、搜索选择）的候选值也是查询，同样等图表进入范围才取；「刷新数据」时也只重新取进入过范围的图表的候选值。
  - 图表出现时先量一次自己的位置，已经在范围内的直接取数；之后靠浏览器在滚动时报告位置。在后台标签页打开的仪表盘，浏览器不绘制页面，也就不报告位置，所以第一屏照常取数，不必等切到前台；其余的等切过去、滚动到附近时再取。一下子跳过去的中间部分（例如直接拖到底），没有进入过范围，仍然不取数。
  - 一张图表一旦开始取数，之后就不再看它在不在范围内，按上面的规则随条件和刷新重新取数。标签页容器（3.15）的当前标签同样要进入范围才取数；其他标签仍是第一次打开时才取数。
  - **没取过数的图表**显示与第一次加载相同的「加载中」，卡片标为忙碌（`aria-busy`）。它在一屏以外，平时看不到；快速滚动过去时，看到的就是它正在加载。
  - 不滚动就到不了的方式找不到没取过数的图表的内容：浏览器的页内查找，以及读屏软件的浏览模式（它读到下面时不一定滚动页面）。用 Tab 键移动焦点时，浏览器会把焦点所在的卡片滚动到视野内，因而会取数。
  - **工具栏只算取过数的图表**：「数据更新于」「正在取数…」和「N 张图刷新失败」都不算没取过数的图表，与看不见的标签（3.15）相同。否则页面下方的图表在滚过去之前一直没有结果，工具栏会一直显示「正在取数…」。
  - 进入范围之前点过「刷新数据」的，第一次取数也直接查数据库；之前有过定时刷新的，第一次取数带 `maxAge`（3.9）。这样它的数据不会比已经取过数的图表旧，「数据更新于」不会因为往下滚动而变早。
- **就绪信号**：全部图表都有了结果（成功、空结果或报错）并绘制完成后，仪表盘根元素上的状态属性变为就绪。截图程序等这个信号，而不是固定等几秒。
- **打印**：查看态的「打印」先切换到完整渲染模式，等就绪后再调用浏览器打印。浏览器自带的打印（Ctrl/⌘+P）等不了查询，只能打印已经取到数的图表。
- 以后的服务端截图通过地址参数进入完整渲染模式，与无头浏览器的登录方式一起设计。
- 交互模式下，没打开的标签页不取数（3.13）。

**实现顺序**

1. 交互模式的按需取数：上面「交互模式」的各条。已实现。
2. 完整渲染、就绪信号和打印。打印的排版在这一步之前决定：纸张方向，网格怎样缩到纸张的宽度，卡片不被分页切开，图表按纸面上的尺寸重画；分页的仪表盘（3.13）打印哪些页也在这时决定。2026-10-20 试做过打印样式，在 Chrome 里按 ⌘P 时图表右侧仍被截断或留白，已撤回，这一步暂缓。

### 3.12 标题与文本组件

组件类型增加 `title` 和 `text`，与图表一样在网格里布局：

```jsonc
// layout.items 中的三个组件
{ "id": "w3", "type": "title", "x": 0, "y": 0, "w": 96, "h": 8, "useDashboardName": true },
{ "id": "w4", "type": "title", "x": 0, "y": 8, "w": 96, "h": 8, "title": "华东区", "subtitle": "按下单日期统计",
  "style": { "align": "center", "verticalAlign": "top" }, "frame": { "background": "blue", "border": true } },
{ "id": "w5", "type": "text", "x": 0, "y": 16, "w": 48, "h": 16, "markdown": "**口径**：已支付订单，不含退款。" }
```

- 查看页不固定显示仪表盘的名称和描述，需要时放一个标题组件。
- **标题组件**：勾选「使用仪表盘名称和描述」（`useDashboardName`）时，标题是仪表盘的名称，副标题是描述，仪表盘改名后跟着变；描述为空时没有副标题。编辑画布和页内预览显示草稿中的名称和描述，在页面设置里应用后立即变。不勾选时写自己的标题（`title`）和副标题（`subtitle`），都可以留空。新加的标题组件默认勾选；取消勾选时把当前的名称和描述填进去，方便在此基础上改。勾选时不保存 `title` 和 `subtitle`。
- 标题单行，副标题最多两行，过长时省略，悬停显示全文。默认左对齐、垂直居中，没有边框，底色与仪表盘相同，看起来是页面上的标题。
- **标题的对齐**（`style`，可选）：只保存与默认不同的项，没有 `style` 的标题就是默认的左对齐、垂直居中。标题和副标题一起对齐，不分开设置。

  | 属性 | 取值 | 默认 |
  |---|---|---|
  | `align` | `left`、`center`、`right`：水平对齐 | `left` |
  | `verticalAlign` | `top`、`middle`、`bottom`：在组件里的上下位置 | `middle` |

- **标题的背景和边框**在容器外观 `frame` 里（3.14），与其他组件相同；下面几条说的是它在标题上的样子。
  - `background`：`neutral` 是浅灰底；调色板的一个色相名（`blue`、`orange`、`aqua`、`yellow`、`magenta`、`green`、`violet`、`red`）是这个色相的浅色底；六位十六进制色值（如 `#1f3a5f`）是作者自定义的颜色。不写时是默认底色，与仪表盘相同，和其他组件一样。
  - `border`：`true` 是 1 像素边框，圆角与图表卡片相同。不写时没有边框。

  - **内置背景随深浅色模式变化**：浅灰和 8 个色相存名字而不是色值，与图表的颜色一样（2.8），浅色和暗色模式各用自己那一档，与卡片底色混合成浅色底，暗色模式下不会出现看不清的组合。文字仍用正常的文字颜色，不做深色底白字：黄、品红等色相上的白字对比度不够。
  - **自定义颜色按原样显示**：作者自己挑的颜色所见即所得，不调浅。标题和副标题的文字按背景的亮度自动用深色或浅色，取与背景对比度较高的一个，深底上就是浅色字。暗色主题可以另设背景（3.14）；不设时两种模式用同一个颜色，在浅色模式下挑的浅色背景在暗色模式里是一块亮色，文字看得清，但比较显眼。同一个蓝色，内置的是调浅的底色，自定义的是原色，两者看起来不同。
  - 背景可以调透明度（3.14）。编辑器存小写色值，服务端接受大小写。
  - 没有「与图表卡片同色」的背景：仪表盘的底色和图表卡片相同，这样的背景看不出来。要像图表卡片那样，只开边框即可。
  - 边框只有有和无，颜色跟随主题的边框色，不随背景色相变化，也不能调粗细。
  - 有背景或边框时，文字与边缘之间留出与文本卡片相同的内边距；两者都没有时保持贴边，与图表卡片的左边缘对齐。
  - 编辑画布上，有边框的标题不再显示表示范围的虚线框；右上角「…」占的位置在左右两侧对称留出，居中的标题在编辑和查看时位置一致。
  - 属性栏「内容」下面是「对齐」分组，水平对齐和垂直对齐用分段控件；之后是所有组件共用的「外观」分组：背景用与图表配色相同的色块，边框是复选框，内边距是分段控件。修改进入撤销历史。
  - 背景上方是「亮色主题 / 暗色主题」切换（3.14），下面的色块设置所选主题的背景。色块依次是默认、浅灰、8 个色相，最后是「自定义」（吸管图标）。点击「自定义」弹出取色面板，注明正在设置哪个主题的颜色，有取色区域（react-colorful）和色值输入框，改动立即显示在画布上；选了自定义颜色后，这个色块显示该颜色并处于选中状态。在面板里拖动取色或输入色值，到关闭面板为止合并为一步撤销。色值输入框只接受 `#RRGGBB`，没写完或写错时不应用，也不清掉已选的颜色。
  - 不提供字号、文字颜色和装饰（如左侧色条），需要时另行添加。文本组件仍是卡片，没有这些设置。
  - 背景和边框原先写在 `style` 里，已由迁移搬到 `frame`。
- **文本组件**：用 Markdown（`markdown`）写说明、口径和结论，与图表一样显示在卡片里，内容超出卡片时在卡片内滚动。用 markdown-it 渲染，支持 CommonMark 以及表格和删除线；文本框里的一个换行就是一个换行；写出的网址自动成为链接。
- **防止脚本注入**：内容由作者填写、展示给所有查看者，所以只渲染 Markdown，其中的 HTML 原样作为文字显示；链接只允许 `http`、`https` 和 `mailto`，其他链接（`javascript:`、`data:`、相对地址等）不成为链接，按文字显示；链接在新标签页打开，不向目标页透露来源（`rel="noopener noreferrer"`）。不显示图片：图片会让每个查看者的浏览器去请求作者指定的地址，可以用来记录谁在什么时候看过；图片的写法按普通文字和链接显示。
- **作用范围由位置决定**：放在标签页上方的标题属于整个仪表盘，放在标签页里的只属于这个标签页（3.13）。不另设「全局标题」配置。
- **编辑器**：工具栏增加「标题」和「文本」，点击加到画布，选中它并在右侧属性栏编辑内容。标题加在画布最上方，宽度占满，其余组件下移；文本与图表一样加在最下方，宽度为一半。属性栏里的修改与其他编辑一样进入撤销历史，连续输入合并为一步。画布上的标题和文本整块都可以拖动，「…」中有组件配置和移除，移除同样二次确认。没有内容的标题和文本在画布上显示灰色的提示，查看时是空白。
- **尺寸**：标题默认高 8 格（默认行高下约 75 像素，放得下标题和一行副标题），文本默认高 16 格；两者最小高度都是 4 格，图表仍是 16 格。
- 这两种组件不取数，不能作为全局筛选的关联图表，也不能作为联动的来源或目标；不进入 `dashboard_charts`。查看态工具栏的数据时间、「刷新数据」和定时刷新只看图表，只有标题和文本的仪表盘不显示这些。
- **保存时的校验**：标题和文本组件不能有 `chartId`；图表组件不能有 `subtitle`、`markdown`、`useDashboardName`（`title` 是它的显示名称，见 3.14）；标题组件不能有 `markdown`，勾选 `useDashboardName` 时也不能有 `title`、`subtitle`；文本组件只有 `markdown`；只有标题组件可以有 `style`。违反时报 `invalid_item_fields`。`style` 中的取值不在上表里时报 `invalid_item_style`；`frame` 的校验见 3.14。长度上限按字符数计：标题 200、副标题 500、Markdown 20000，超出报 `item_text_too_long`。全局筛选关联到标题或文本时报 `invalid_filter_target`，联动用到它们时报 `invalid_link`。对标题和文本组件请求取数、候选值或导出，返回 404。

### 3.13 标签页

状态：已实现。

一个仪表盘可以分成多个标签页，下面简称「页」，每页各有一套布局。这是针对整个仪表盘的分页；与 3.15 的标签页容器（一个组件里用标签切换几张图）不是一回事，两者都要做。

**结构**

分页的仪表盘从上到下是共用区域、标签条和当前页。

```jsonc
"layout": {
  "columns": 96,
  "pages": [
    { "id": "w20", "name": "概览" },
    { "id": "w21", "name": "渠道" }
  ],
  "items": [
    { "id": "w3", "type": "title", "x": 0, "y": 0, "w": 96, "h": 8, "useDashboardName": true },  // 共用区域
    { "id": "w1", "type": "chart", "chartId": "ch_3f8k…", "page": "w20", "x": 0, "y": 0, "w": 48, "h": 32 },
    { "id": "w2", "type": "chart", "chartId": "ch_9c2m…", "page": "w21", "x": 0, "y": 0, "w": 48, "h": 32 }
  ]
}
```

- 页的顺序就是 `layout.pages` 的顺序，打开仪表盘时显示第一页。不设默认页：仪表盘的第一页通常就是概览。标签页容器有默认标签（3.15），是因为「日 | 周 | 月 | 年」这类顺序不能为了默认而打乱，仪表盘的页少有这种情况，以后需要再加。
- 组件用 `page` 说明自己在哪一页，没有 `page` 的在共用区域。组件仍然都在 `layout.items` 里，全局筛选、联动、取数、候选值、导出和分享链接照常按组件 ID 找图，接口不变。标签页容器里的标签跟着容器在同一页。
- 共用区域和每一页各是一块网格，纵向位置各自从 0 算起；列数、行高、间距等网格配置（`layout.grid`）所有网格共用。
- 共用区域里什么组件都能放：标题、文本、图表、标签页容器。放在这里的每页都显示，例如仪表盘的标题、口径说明、每页都要看的几个指标。共用区域可以是空的，这时标签条在最上面。查询容器总是在共用区域（见下面「全局筛选」）。
- 网格不嵌套：页里不能再分页。组件可以在共用区域和当前页之间拖动，到别的页用「移到」（见下面「编辑」）。
- 一个仪表盘有 2 到 20 页，只剩一页时变回不分页的仪表盘。没有 `pages` 的仪表盘与现在相同，不需要迁移。

**标签条**

- 每页显示它的名称。放不下时横向滚动，规则与标签页容器的标签条相同（3.15）：不换行，鼠标滚轮也能滚动，被挡住的一边渐隐，当前页总在可见范围内。标签条是一组标签（`tablist`），左右方向键切换，Home、End 到第一页和最后一页。
- 往下滚动时，标签条到了滚动区域的顶端就停在那里（吸顶），长的页面滚到下面也能直接切页；共用区域跟着滚走。全屏时相同。用 Tab 键移动焦点时，卡片滚动到标签条下面，不被它挡住。
- 标签条跟随界面主题，没有外观设置。

**标题**

不需要新的组件。标题组件（3.12）放在共用区域，就是整个仪表盘的标题，每页都显示；放在一页里只属于这一页，例如分区的小标题。不提供「使用页名称」的标题，标签条上已经有页名。

**全局筛选**

全局筛选器仍然都在一个查询容器里，查询容器在共用区域。每页只显示与这一页有关的筛选器：

- 与这一页有关的是：关联了这一页或共用区域里的图表的筛选器（标签页容器的任何一个标签都算），以及这些筛选器在级联中的上级。上级的取值限制着下级的候选，看不到上级，就不知道候选为什么少了。其余的筛选器隐藏。
- 筛选器的定义不变，仍按组件 ID 关联图表，一个筛选器可以关联几页的图表。图表移到另一页后，关联它的筛选器跟着在那一页显示，不用改配置。
- 一个筛选器在各页是同一个取值：在第 1 页选了华东，切到第 2 页还是华东。隐藏的筛选器保留取值，回到它的页时照常生效。
- 「查询」按钮、重置、查询方式和控件样式仍然只有一套。手动查询模式下，「查询」应用全部筛选器的当前输入，包括这一页没有显示的。
- 查询容器自动高度时随显示的筛选器多少变高变矮，共用区域里它下面的组件跟着移动。手动高度时不变，筛选器少时留白，多时在容器里滚动。
- 一页上没有要显示的筛选器时，查看态和页内预览中不显示查询容器，它占的高度也收起。编辑画布上仍显示容器，提示「这一页没有关联的筛选器」，以便继续配置。
- 全局筛选对话框中间一栏的关联图表按共用区域和各页分组。
- 不在页里另放查询容器，也就是不支持多个查询容器（见 [暂缓事项](../backlog.zh.md)）。那样每个容器都有自己的「查询」按钮和重置，要另行规定它们作用于哪些筛选器、查询方式和控件样式按容器还是按仪表盘、级联能否跨容器、图表换页后原来容器里关联它的筛选器怎么办。按页显示已经能让只属于一页的筛选器只在那一页出现。

**联动**

联动可以跨页：在第 1 页点击图表，第 2 页的目标图表同样受限，下次打开第 2 页时按新的条件取数。当前的联动条件列在网格上方（3.4），在哪一页都看得到，也能逐条取消。

**取数**

- 交互模式下只有打开过的页取数，页里仍等图表接近可视区域时才取（3.11）。切走再切回，保留之前的结果。
- 筛选、联动、动态选择变化，以及「刷新数据」和定时刷新时，共用区域和当前页里取过数的图表立即重新取数；其他页里取过数的图表在下次打开时按当时的条件重新取数，规则与标签页容器里看不见的标签相同（3.15）。第一次打开一页之前点过「刷新数据」的，这一页第一次取数也直接查数据库；有过定时刷新的带 `maxAge`。
- 工具栏的「数据更新于」「正在取数…」和刷新失败只算共用区域和当前页的图表。
- 完整渲染和打印已暂缓（3.11），打印哪些页届时再定。

**地址和分享**

- 当前页写进地址参数 `page`，值是页的 ID，不含筛选值；在第一页时不写。切页时替换地址，不新增浏览器历史记录，「后退」回到上一个页面，而不是仪表盘的上一页。刷新页面仍在这一页；地址里的页已经不存在时显示第一页。
- 从查看态进入编辑时带上当前页，编辑器打开在同一页。
- 分享的条件（3.10）增加 `page`，只在当前不是第一页时携带。它归入「所在标签」一类，这一类改名为「所在页和标签」，内容写作「页：渠道」。打开链接时，已经不存在的页丢弃，并像其他失效的条件一样提示部分条件已失效。之后切页与修改其他条件一样，地址中去掉 `view` 参数。

**浏览器标签页的标题**

分页的仪表盘，浏览器标签页的标题带上当前页的名称：「仪表盘名称 - 页名 - SupaBI」，切页时跟着变，编辑页相同。页名放在仪表盘名称后面：很多仪表盘的第一页都叫「概览」，页名在前时几个标签页都是「概览 - …」。不分页的仪表盘是「仪表盘名称 - SupaBI」（3.7）。

**编辑**

- **分页**：工具栏增加「标签页」。不分页时点击它，仪表盘分成两页：下沿在最上面的图表容器（含空容器和标签页容器）之上的标题和文本，以及查询容器，放进共用区域，其余放进第一页；再加一个空的第二页并切换过去。已经分页时点击它，加一个空页并切换过去。分页是一步撤销。
- 标签条右边有「+」，加一个空页并切换过去；「+」旁边是设置按钮，打开属性栏里页的设置。两者都不随标签滚动。
- 新页的名称是「第 N 页」，N 取还没有用过的最小序号。
- **切页**：在编辑画布上点击标签切换。当前在哪一页不进入撤销历史，也不保存；撤销或重做之后当前页不存在了，回到第一页。
- **页的设置**：点击标签条的设置按钮（「管理标签页」）或空白处，右侧属性栏显示页的列表，每行是拖动把手、名称和删除。名称直接在列表里改，焦点进入一行时画布切到这一页；名称清空时页仍用原来的名称，直到输入新的。拖动把手调整顺序，拖动时显示插入的位置，把手获得焦点时上下方向键上移或下移一位。修改立即生效，进入撤销历史，连续输入合并为一步。
- **删除页**：二次确认，写明这一页上有几个组件会一起移除，同时移除它们的筛选映射和联动，源图表不删除。只剩一页时变回不分页：共用区域的组件在上，剩下那一页的组件接在下面。删除和变回不分页是一步撤销。
- **新加的组件放在哪里**：标题加在共用区域最上方，宽度占满，与不分页时加在画布最上方一致；文本、图表和空容器加在当前页最下方。从图表库拖入时，拖到共用区域就放进共用区域，拖到当前页就放进当前页。共用区域是空的时，编辑画布上显示一条虚线框，提示「放在这里的组件每页都显示」，可以往里拖。
- **换位置**：组件的「…」中有「移到」，可以移到共用区域或另一页，放在那块网格的最下方，宽度和高度不变；编辑画布留在当前页。这是一步撤销。筛选映射和联动都按组件 ID，换页不影响它们。查询容器没有「移到」。
- **拖到另一块区域**：编辑画布上，组件可以在共用区域和当前页之间直接拖动，落在松开的位置。拖进另一块区域时，那里显示落点，其他组件让出位置，与在一块区域里拖动相同。原来的区域保持原样：组件原来的位置空着，旁边的组件不补位，松开后再按它的规则收拢，自动上移时下面的补上来，自由布局时留空，与「移到」相同。移过去的组件宽高不变，仍然选中。这是一步撤销，筛选映射和联动不受影响。
  - 指针在哪块区域，按拖动开始时各区域的范围算。自由布局下在共用区域里往下拖，共用区域会跟着组件变高，把标签条和当前页一路往下推，按实时的范围算，指针永远进不了当前页。
  - 在两块区域之外松开，例如停在标签条上，组件留在原来的区域，落在那里显示的位置。
  - 当前页滚动过后，把组件往上拖到画布顶边，画布照常自动往上滚，共用区域露出来就可以放进去。
  - 查询容器不能拖出共用区域，它也没有「移到」。
  - 到另一页：先拖进共用区域，切页后再拖下来，或者用「移到」。不在标签上停留时自动切页：拖动中的组件属于原来那块网格，切页会把那块网格藏起来，拖动随之中断。也不做拖到另一页的标签上、放到那一页最下方：作者认为只做同屏拖动就够了。
  - 跨区域的落点和让位在仪表盘的网格组件里计算，拖拽库的本地补丁（见 [暂缓事项](../backlog.zh.md)）不变。
- 页面设置的「仪表盘内容」中显示页数。

**保存时的校验**

- `layout.pages` 要有 2 到 20 页，否则报 `invalid_pages`。页的 ID 规则与组件相同，不合法报 `invalid_item_id`，与组件、标签或其他页重复报 `duplicate_item_id`。页名去掉首尾空白后不能为空，否则报 `invalid_page_name`；上限 50 字，超出报 `item_text_too_long`。
- 组件的 `page` 要是一个页的 ID，不分页的仪表盘的组件不能有 `page`，否则报 `invalid_item_page`。

**实现顺序**

1. 浏览器标签页的标题改为名称在前、SupaBI 在后（3.7）。与分页无关，先单独做。
2. 类型和校验。查看：共用区域、标签条（含吸顶）、切页、地址参数、按需取数和工具栏、浏览器标题带上页名。编辑：「标签页」和「+」、切页、改名、删除页和变回不分页、新组件放在哪里、「移到」。
3. 全局筛选按页显示；全局筛选对话框按页分组。
4. 调整页的顺序；分享链接和进入编辑时带上当前页。

四步按作者的要求一次实现。之后补充了在共用区域和当前页之间拖动组件（见「编辑」）。

### 3.14 组件容器

状态：已实现。

布局里的每个组件都是一个容器：位置、尺寸和外观属于容器，放在里面的图表、标题、文本或查询控件是它的内容。图表容器只引用图表（`chartId`），图表的定义、配色、坐标轴等仍在图表编辑页设置。这样，仪表盘上「这张图怎么摆、怎么装饰」与「这张图本身」分开，属性栏也按这两层分组，不混在一起。

```jsonc
// layout.items 中的组件
{ "id": "w1", "type": "chart", "chartId": "ch_9c2m…", "x": 0, "y": 8, "w": 48, "h": 32,
  "title": "华东销售额", "note": "口径：已支付订单，不含退款。", "hideHeader": true,
  "frame": { "background": "#f4f8ff", "backgroundDark": "#16202e", "border": false, "padding": "compact" } },
{ "id": "w2", "type": "chart", "x": 48, "y": 8, "w": 48, "h": 32 },                  // 空的图表容器
{ "id": "w3", "type": "title", "x": 0, "y": 0, "w": 96, "h": 8, "useDashboardName": true,
  "style": { "align": "center" }, "frame": { "background": "blue" } }
```

```jsonc
// 仪表盘 Spec 顶层：图表和文本容器的默认外观
"frame": { "border": false, "padding": "compact" }
```

**图表容器**

- **空容器**：图表库最上方是「空图表容器」，点击加到画布最下方（宽度一半、高 16 格，与添加图表相同），也可以拖到指定位置，用来先排好页面结构再放图。从图表库点击或拖入一张图表，仍然一步生成装好这张图的容器，不需要先建空容器。
- 空容器在画布上显示虚线框、「从图表库拖入图表」的提示和「从图表库选择」按钮，整块都可以拖动。选中空容器时，图表库顶部提示「点击图表放进……」，在图表库点击图表就放进这个容器，而不是另加一个。查看态和页内预览中，空容器是空白，与没有内容的文本一样。
- 拖着图表经过图表容器时，容器高亮，画布不为它让出位置；松开就放进这个容器（空的）或请求替换（有图的）。拖到空白处仍然是新加一个容器。
- **替换**：把图表拖到已有图表的容器上，确认后替换。位置、尺寸和外观保留；原图表的筛选映射和联动一并移除，显示名称和备注也清空，因为它们说的是原来那张图。「…」中另有「移出图表」，容器变回空容器，同样移除映射。替换和移出都是一步撤销，与映射的清理一起恢复。
- **显示名称**（`title`）：留空时显示图表的名称；填写后只在这个仪表盘里使用，不改源图表。卡片标题栏、放大对话框、导出文件名、无障碍名称，以及全局筛选和联动对话框里的组件名都用它；属性栏的「图表」分组仍显示源图表的名称。上限 200 字。
- **备注**（`note`）：填写后，标题栏右侧「…」的左边出现问号图标，鼠标悬停或键盘聚焦时显示备注全文。纯文本，保留换行，不渲染 Markdown；上限 500 字。用来写口径、数据来源等不必一直显示的说明。
- **隐藏标题栏**（`hideHeader`）：查看态和页内预览中不显示标题栏，图表占满容器。问号、刷新失败的警告和「…」浮在右上角：警告一直显示，问号和「…」在鼠标移入或键盘聚焦容器时显示；单张图的取数时间不显示，工具栏的数据时间仍在。
- 编辑画布上，隐藏的标题栏浮在图表顶部，半透明，下缘是虚线，不占位置，所以图表的大小和位置与查看时相同，不必切到预览才能看到实际效果。它仍然是拖动的把手；名称变灰，紧跟在名称右边注明「查看时隐藏」。浮着的标题栏会盖住图表顶部的一条，包括图表自身的筛选控件，需要操作它们时用预览。
- 空容器也可以有显示名称、备注和外观，放进图表后生效。

**容器外观**（`frame`，可选）：标题、文本、图表容器和查询容器（`queryContainer.frame`）共用同一套。

| 属性 | 取值 | 说明 |
|---|---|---|
| `background` | `default`、`neutral`、调色板色相名或 `#rrggbb` | `default` 是默认底色，即界面的表面色，仪表盘本身也是这个颜色，所有组件相同；不写时也是它，写出来用来在页面默认有背景时单独恢复。内置背景随深浅色模式变化；`#rrggbb` 是自定义颜色在亮色模式下的颜色 |
| `transparency` | 0 到 100 的整数 | 背景的透明度，百分比：0 不透明，100 完全透明，后面有什么就显示什么。两个主题相同。不写时是 0 |
| `backgroundDark` | 与 `background` 相同的几种 | 暗色主题下的背景。不写时跟随 `background`：浅灰和色相换成暗色的一档，自定义颜色不变 |
| `border` | `true`、`false` | 1 像素边框，颜色跟随主题 |
| `padding` | `compact`、`normal`、`comfortable` | 内容与边缘的距离，名称与图内控件的紧凑、标准、宽松相同 |

- **亮色主题和暗色主题分别设置背景**：外观的「背景」下面第一行就是「亮色主题 / 暗色主题」切换，默认是当前的界面主题，每一项旁边的圆点是该主题选中的颜色，与色块显示的颜色相同。下面的色块和自定义颜色设置所选主题的背景，色块按所选主题显示：切到暗色主题时，默认底色、浅灰和色相都是暗色那一档。暗色主题可以选任何一种：默认、浅灰、色相或自定义颜色。暗色主题没有单独设置时跟随亮色主题；单独设置后出现「与亮色主题相同」，点击恢复跟随。界面上不再写说明文字，跟随与否看圆点即可。与亮色主题相同的暗色背景不保存 `backgroundDark`。画布只显示当前界面主题下的背景，另一种看切换项旁的圆点，或切换界面主题。这解决了 3.12 中「亮色下挑的浅色背景在暗色里是一块亮色」的问题；只设亮色时仍是原来的行为。
- 最初的入口放在取色面板里，只能为自定义颜色分开设置，不容易发现；改为放在色块上方，所有背景都可以分主题设置。
- **自定义颜色上的内容按背景深浅换一套主题**：背景亮时用亮色主题的颜色，暗时用暗色主题的，取文字与背景对比度较高的一套，两种模式各算各的。做法是把那套主题的颜色变量写在容器上，背景色作为容器的「表面色」，所以标题、文本、图内控件和表格都跟着变，不必逐个处理。
- **图表在自定义背景上**：按同样的规则用亮色或暗色那一套颜色画，背景色作为图表的表面色：条形之间的间隙、表格的单元格和合计行用它，表头在它上面略加深。序列用该主题那一档的同一色相。放大对话框里的图表画在对话框上，用界面主题的颜色。内置背景和默认背景下用界面主题的颜色。
- **透明度**：「背景」下面是「透明度」滑块，0% 到 100%，每格 5%，旁边显示当前百分比；它作用于所选背景，默认背景也一样，所以图表默认是不透明的卡片，拉到 100% 就完全透明。两个主题用同一个值，因为它说的是「让后面透出来多少」，与颜色无关。拖动滑块到松开为止是一步撤销。标题和其他组件一样可以调，想让标题透出画布就把透明度调高。
  - 文字、图表的颜色按背景与仪表盘表面色叠加后的实际颜色来选：深色自定义颜色调到很透明时，叠在亮色表面上已经是浅色，里面就用深色字。这个叠加后的颜色也是图表的表面色。仪表盘的底色就是界面的表面色（全屏时也是），所以查看时看到的正是这个叠加色；编辑时画布有网格，半透明的卡片会透出网格。
  - 背景只在一个主题里设了颜色时，两个主题的内边距仍按「有背景」算，切换主题时文字不会移动。
  - 从图表库拖空容器经过已有的图表容器时，照常让出位置，松开就新加一个空容器，不会放进那个容器。
  - 曾经让「无背景」直接透明，结果编辑页上所有卡片都透出网格，看着不舒服；改为默认不透明，需要时用透明度调。
- **背景选项所有组件相同**：标题、图表、文本和查询容器的色块和透明度完全一样，默认都是不透明的默认底色。早先标题的默认是「无底色」、滑块不可用，与图表不一致，已改为相同，透明与否由透明度决定。
- **默认的边框按类型不同**：图表和文本容器默认是卡片（有边框、标准内边距），标题默认没有边框（3.12），查询容器默认有边框。仪表盘顶层的 `frame` 是图表和文本容器的默认外观，在页面设置的「组件默认外观」中修改，与页面设置的其他项一样点「应用」后才生效；组件上没写的项跟随它，写了的覆盖它，所以组件上的 `border: true` 与不写不同。组件上只保存与它本来的外观不同的项，改回去就不再保存。标题不跟随页面默认，它应当像页面上的标题，而不是卡片；查询容器也不跟随。
- 内边距三档在各类组件上的具体距离不同：图表、文本和查询容器是 8/10、12/16、18/24 像素（上下/左右），有背景或边框的标题是 4/10、8/16、14/24，没有的标题是 0、4/2、8/8。查询容器自动高度时按所选内边距计算。没有边框的图表和文本在编辑画布上用虚线表示范围，与标题相同。
- 标题现在的 `style.background` 和 `style.border`（3.12）移到 `frame`，`style` 只留对齐。开发库中已保存的标题样式由迁移搬过去；还没有发布，不保留旧写法。

**属性栏**：选中图表容器时分为「容器」和「图表」两组。

- 「容器」：显示名称、备注、隐藏标题栏；之后是「外观」（背景、边框、内边距）和尺寸。
- 「图表」：放的是哪张图（空容器时是「从图表库选择」）、编辑源图表、移出图表；之后是关联的筛选器和数据导出说明。
- 标题、文本和查询容器的属性栏同样增加「外观」；标题原来的「样式」分组只剩对齐，改名为「对齐」。
- 取色面板里的拖动和输入，到关闭面板为止是一步撤销；面板内的焦点移动不会把它拆开。

**保存时的校验**：图表容器可以没有 `chartId`（空容器）；空容器不取数，取数、候选值和导出返回 404，不能作为全局筛选的关联图表（`invalid_filter_target`）或联动的来源和目标（`invalid_link`），也不进入 `dashboard_charts`。`title`、`note`、`hideHeader` 只属于图表容器，其他类型报 `invalid_item_fields`；显示名称超过 200 字、备注超过 500 字报 `item_text_too_long`。`frame` 中的取值不认识，报 `invalid_item_frame`。

原计划分五步实现（`frame` 与标题迁移、各类容器的外观、显示名称与备注、空容器、页面默认外观），按作者的要求一次实现。

### 3.15 标签页容器

状态：已实现。

图表容器可以有多个标签页，每个标签放一张图表，点击标签切换，用来在同一块位置轮流看几张相关的图，例如销售额、订单数和客单价。它与 3.13 的仪表盘级标签页是两回事：那是把整个仪表盘分成几页，每页各有一套布局；这里是一个组件里的几张图，网格不嵌套。两者都要做。

```jsonc
// layout.items 中的标签页容器
{ "id": "w7", "type": "tabs", "x": 0, "y": 40, "w": 48, "h": 32,
  "frame": { "border": true }, "defaultTab": "w9",
  "tabs": [
    { "id": "w1", "chartId": "ch_3f8k…", "title": "销售额", "note": "口径：已支付订单。" },
    { "id": "w9", "chartId": "ch_9c2m…" },
    { "id": "w10" }                                  // 空标签
  ] }
```

**结构**

- 每个标签就是一个没有位置、没有外观的图表容器：有自己的组件 ID，可以有图表（`chartId`）、显示名称（`title`）和备注（`note`），也可以是空的。标签的 ID 与组件的 ID 一起在仪表盘内唯一。
- 全局筛选、联动、取数、候选值、导出和分享链接都按组件 ID 找图，标签里的图用标签的 ID，所以这些功能对它和对普通图表容器里的图一样：可以单独映射筛选字段，作联动的来源或目标，导出数据。接口不变。
- 位置、尺寸和外观（3.14）属于容器，所有标签共用。外观跟随页面的组件默认外观，与图表容器相同。
- 一个标签只放一张图，不放几个组件组成的小布局：那样就是在网格里嵌套网格，跨网格拖动很复杂（3.13）。标签里也只放图表，不放标题和文本。
- 一个容器有 2 到 20 个标签。只剩一个时变回普通图表容器（见下面「编辑」）。
- **默认标签**（`defaultTab`）是打开仪表盘时显示的标签，存它的 ID；不写时是第一个标签，所以默认标签就是第一个时不写。顺序和默认分开：标签的顺序本身常有含义，例如「日 | 周 | 月 | 年」，默认显示「月」时不必打乱顺序。动态维度是「第一个候选是默认」（2.4），这里不同，因为那里的顺序只是下拉列表里的先后，标签是排在页面上的。
- 调整顺序不改变默认标签；移除默认标签后，默认回到第一个标签。

**查看**

- 容器的标题栏换成标签条，每个标签显示它的名称：显示名称，没有时是图表的名称。放不下时标签条横向滚动，不换行，鼠标滚轮也能滚动；哪一边还有被挡住的标签，那一边就渐隐；当前标签总在可见范围内。
- 标签条右边是当前标签的数据时间、刷新失败的警告、备注的问号和「…」，与图表容器的标题栏相同，都作用于当前标签。数据时间只显示时钟图标，悬停时显示「更新于……」和具体时间：写成文字会挤占标签的位置，窄的容器里连第一个标签都显示不全。放大、查看数据和导出用当前标签的名称。
- 没有「隐藏标题栏」：标签条要用来切换。
- 查看态和页内预览中不显示空标签，与空容器是空白一致；标签都是空的时，容器是空白。默认标签是空的时，先显示第一个有图的标签。
- 键盘：标签条是一组标签（`tablist`），左右方向键在标签之间移动并切换，Home、End 到第一个和最后一个。

**取数**

- 只有当前标签取数。其他标签第一次打开时才取数；切走再切回，保留之前的结果，不重新取数。第一次打开前点过「刷新数据」的，第一次取数直接查数据库；有过定时刷新的带 `maxAge`，与 3.11 中进入范围之前的图表相同，所以它的数据不比已经取过数的图表旧。
- 筛选、联动、动态选择变化，以及「刷新数据」和定时刷新时，只有各容器的当前标签立即取数；其他取过数的标签在下次打开时按当时的条件重新取数，取到之前显示变淡的旧图（3.9）。
- 工具栏的数据时间和刷新失败只算各容器的当前标签，看不见的图不影响「数据更新于」。
- 当前标签不保存在仪表盘里，查看者切换的标签只对当前页面有效。完整渲染（3.11）只渲染当前标签。

**编辑**

- 图表容器（包括空容器）的「…」和属性栏中有「添加标签页」：容器变成标签页容器，原来的图成为第一个标签，并保留原来的组件 ID，所以它的筛选映射和联动都还在；同时加一个空标签并切换过去。显示名称和备注跟着图，成为第一个标签的；位置、尺寸和外观留给容器；「隐藏标题栏」去掉。容器另取一个新 ID。
- 标签条右边有「+」，加一个空标签并切换过去。「+」不随标签滚动，标签再多也一直看得见。
- **把图表拖到标签条上**：从图表库把图表拖到标签页容器的标签条（标签和「+」所在的一行）上，松开就新加一个放这张图的标签，插在指针所在的位置，并切换过去。拖动经过时，标签条高亮，标签之间用一条竖线标出插入的位置，卡片本身不高亮；拖到标签条下面的图上，仍然是放进或替换当前标签的图（3.14）。标签已满 20 个时，标签条提示已满，松开不添加。拖「空图表容器」经过时不放进标签条，照常让出位置，加空标签用「+」。普通图表容器的标题栏不接收拖入的新标签，要先「添加标签页」。
- 在编辑画布上点击标签切换；标签条的空白处仍是拖动的把手。空标签与空容器一样，显示虚线框、提示和「从图表库选择」按钮：选中容器时在图表库点击图表，或者把图表拖到容器上，放进当前标签；拖到有图的标签上，确认后替换，规则与 3.14 相同。
- 「…」中的配置和移出图表作用于当前标签。「移除」变为「移除标签」，二次确认，同时移除这个标签的筛选映射和联动，源图表不删除。删到只剩一个标签时，容器变回普通图表容器，组件 ID 用剩下那个标签的 ID，它的映射和联动都保留。移除标签和变回普通容器是一步撤销。
- 编辑画布上当前在哪个标签，不进入撤销历史，也不保存。打开编辑页时先显示默认标签，与查看时相同。
- 属性栏：选中标签页容器时，依次是「容器」组（标签列表和「添加标签页」）、「当前标签」组（当前标签的显示名称和备注）、外观、尺寸，以及与图表容器相同、作用于当前标签的「图表」组。「当前标签」紧跟在标签列表下面，切换标签后马上就能改它的名称，不用翻过外观和尺寸。底部的「移除组件」移除整个容器，连同所有标签的映射和联动。
- **标签列表**：每行从左到右是拖动把手、标签名称、星标和删除。点击名称切换到这个标签。默认标签的星标是实心的，一直显示；其他标签是空心的，点击设为默认。
- **调整顺序**：在属性栏的标签列表里拖动把手，拖动时显示插入的位置。把手获得焦点时，上下方向键把标签上移或下移一位。每次调整是一步撤销。不在画布的标签条上拖动排序：标题栏是拖动整个容器的把手，标签条又窄、放不下时还会滚动，而且第 3 步要把图表从图表库拖到标签条上，几种拖动容易混在一起；以后需要再加。
- 页面设置的「仪表盘内容」中，标签里的图算进图表数，空标签算进空容器数。全局筛选和联动的对话框里，标签里的图与其他图表并列，按名称显示。

**保存时的校验**

- `tabs` 类型的组件要有 2 到 20 个标签，否则报 `invalid_tabs`。`defaultTab` 要是它的一个标签的 ID，否则报 `invalid_default_tab`。只有它可以有 `tabs` 和 `defaultTab`；它本身不能有 `chartId`、`title`、`note`、`hideHeader` 等图表容器的字段，否则报 `invalid_item_fields`。
- 标签的 ID 规则与组件相同，不合法报 `invalid_item_id`，与组件或其他标签重复报 `duplicate_item_id`。标签只有 `id`、`chartId`、`title`、`note` 四项，长度上限与图表容器相同（`item_text_too_long`）。
- 空标签与空容器相同：不取数，不能作为全局筛选的关联图表或联动的来源和目标。标签里的图进入 `dashboard_charts`，被引用的图表不能删除。
- 不需要迁移：没有标签页容器的仪表盘与现在相同。

**实现顺序**

1. 类型和校验；查看、切换和按需取数；添加标签页、「+」、移除标签和变回普通容器；属性栏。
2. 默认标签；在属性栏的标签列表里调整顺序。
3. 把图表拖到标签条上，新加一个放这张图的标签，插在指针所在的位置。
4. 分享链接（3.10）的条件增加 `tabs`：容器 ID 到当前标签 ID，只带当前显示的不是打开时那个标签的容器（默认标签是空的时，打开时显示的是第一个有图的标签）。打开链接时，已经不存在的容器、不在容器里或已经没有图的标签丢弃，并像其他失效的条件一样提示部分条件已失效，其他照常应用。之后切换标签与修改其他条件一样，地址中去掉 `view` 参数。

四步都已实现。

### 3.16 窄屏

我的仪表盘（[架构总览](architecture.zh.md) 12）可以在手机上看。在工作台里制作和排布仪表盘，以及数据探索，仍是电脑上用的工具。

- **列表和仪表盘分成两屏。** 窗口窄于 760px 时（设置页把导航挪到内容上方的宽度，见[权限设计](access-control.zh.md) 2.2.1），`/dashboards` 只显示列表，占满宽度；`/dashboards/{id}` 只显示仪表盘。仪表盘上方有一行：返回按钮和仪表盘名称。列表看不见以后，别处不再显示名称。按钮回到列表，浏览器的返回也一样，因为两屏是两个地址。名称取自列表，所以仪表盘打不开时这一行也在。全屏（3.9）像盖住页面其他部分一样盖住这一行。
- 调整列表宽度的分隔条不显示，仪表盘四周的留白收窄到 16px，与设置页一致。列表看不见时仍然保留，回去时筛选框里的字还在。工具栏不改：有了整个宽度后自动换到第二行，每个按钮都够得着。
- 宽于 760px 时（包括竖放的 768px 平板），列表和仪表盘仍左右并排。
- **单列显示时组件随内容变高。** 仪表盘窄于 640px 时，组件按阅读顺序排成一列。每个组件至少有网格里的高度，内容需要更多时更高：KPI 的指标换行、文本组件的文字、图表筛选控件换成更多行（下面的图表仍保留最小 96px 的高度）。ECharts 画的图、表格和透视表与电脑上一样填满给定的高度，表格和透视表在里面滚动。查询容器本来就按控件定高度（3.1）。标签页容器的高度由当前显示的标签决定。
- 这只是单列的画法。宽于 640px 的网格不变，变高也不保存。
- 实现方式：单列沿用网格本身的元素，网格与单列之间切换时组件不重新绘制，也不重新取数（7）。单列时用 CSS 撇开网格库给组件的位置和固定像素尺寸，由浏览器按阅读顺序上下排列。每个组件给的是最小高度而不是固定高度，由浏览器按两者中较高的排版。图表和表格按从容器量出的高度绘制，所以不会要比给定更多的高度。KPI 的指标用 CSS 填满容器，而不是用量出的高度，所以能把容器撑高。若单列改由网格库来摆放（它把组件固定在像素高度上），就要改成量出内容高度再换算成行数。

## 4. 存储

- `charts` 表：ID、工作空间、名称、描述、所属数据集、Spec、创建人与修改人。数据集被图表引用时不能删除。
- `dashboards` 表：ID、工作空间、名称、描述、Spec、创建人与修改人。
- `dashboard_charts` 表：仪表盘与其引用图表的关系，保存仪表盘时重建。图表被仪表盘引用时不能删除。
- `dashboard_views` 表：分享链接携带的条件，见 3.10。
- `chart_revisions`、`dashboard_revisions` 表：每次保存的修订，见 4.1。

### 4.1 修订记录

状态：已实现。

图表和仪表盘每保存一次，记一个修订：版本号、保存时间、修改人，以及保存的定义。编辑器里只列出版本、时间和修改人，回答「谁在什么时候改过」；不能查看旧版本的内容，也不能比较或恢复。定义存下来是为了以后需要追查时有据可查，这次不做查看它的界面和接口，需要时直接查库。

不做比较和恢复，是因为图表画出来的结果还取决于它读的数据集，仪表盘还取决于它引用的图表。例如数据集改了 SQL 和字段，图表随之从 v3 改到 v4；这时把图表退回 v3，它需要的是当时的数据集，单独恢复图表得不到当时的样子，结果也不可控。仪表盘同理。数据集能恢复，是因为它在最上游，保存时还有影响分析把关（[数据集模型](dataset.zh.md) 第 9 节）。

**什么算一个修订**

- 创建是版本 1，之后每次保存成功加一，与保存冲突检查用的修订号（`revision`）是同一个数。
- 名称、描述和定义一起保存，改名也是一个修订。图表的定义包括它读哪个数据集。
- 移到文件夹、仪表盘授权、分享链接不是保存，不产生修订，与数据集相同。
- 保存失败（校验不通过、保存冲突）不产生修订。

**存什么**

- `chart_revisions`：图表、修订号、名称、描述、数据集及保存时校验所用的数据集修订号、Spec 及其格式版本、修改人、保存时间。有了数据集修订号，追查时能找到这一版图表当时配的是哪一版数据集，两边的定义都在各自的修订里。
- `dashboard_revisions`：仪表盘、修订号、名称、描述、Spec 及其格式版本、修改人、保存时间。
- 与保存在同一个事务里写入：保存成功就一定有修订。审计不在保存的事务里，写失败时会漏记（[权限设计](access-control.zh.md) 第 7 节），所以不靠审计。
- 写入后不再修改。以后修改 Spec 格式的迁移只改图表和仪表盘本身，不改写修订里的旧定义：它们只供追查，程序不会读回来用，保持保存时的原样更可信。数据集不同，它的修订可以恢复，所以迁移时一起改写。
- 全部保留，不设上限，也不随审计的保留期清理。
- 删除图表或仪表盘时，它的修订一起删除；删除这件事本身记在审计里。

**编辑器里的列表**

- 图表编辑器的底部面板在「引用」后面加「修订历史」；仪表盘编辑器在页面设置的最后加「修订历史」一节。
- 按版本倒序，每条一行：版本号、保存时间、修改人，最新的一条标「当前」。时间用短格式「10-20 10:27」，与数据集的修订历史相同，鼠标悬停显示完整时间；仪表盘的属性栏较窄，修改人的名字放不下时截断，悬停显示全名。名称与现在不同的版本，在下面一行显示当时的名称。
- 分页与数据集的修订历史相同，「加载更早版本」继续。列到最早一条时，它不是版本 1 的，在末尾说明「版本 N 之前没有记录」。
- 修改人显示现在的名字，与数据集相同；没有修改人的显示「系统」。
- 新建还没保存的图表和仪表盘显示「保存后开始记录」。保存成功后列表刷新。
- 接口是 `GET /charts/{id}/revisions` 和 `GET /dashboards/{id}/revisions`，分页参数和每条的字段与数据集的修订列表相同。没有读取某个版本定义的接口。只向当前工作空间的数据开发和管理员开放；只读，不记审计。

## 5. 权限

| 操作 | 所需角色 |
|---|---|
| 查看图表和仪表盘，获取图表数据，已保存图表和仪表盘的候选接口 | 普通用户，限被授权的仪表盘及其上的图表（[权限设计](access-control.zh.md) 4.2）；候选只能访问作者配置的筛选目标 |
| 导出仪表盘上图表的数据（见 2.9） | 能打开该仪表盘，且图表 `allowExport` 为 `true`；不区分角色 |
| 新建、修改、删除图表和仪表盘，图表和仪表盘草稿的取数与候选 | 数据开发 |

角色见 [权限设计](access-control.zh.md) 4.1。

**普通用户通过图表取数，而不是直接查询数据集。** 「获取图表数据」接口只执行图表自己保存的查询，调用方只能附带筛选取值和作者允许的动态候选 ID，不能提交任意查询。这就是 [权限设计](access-control.zh.md) 中「仪表盘可见即数据可见」的落地方式：普通用户不能直接查询数据集。

## 7. 设计取舍

以下取舍与当前实现一致：

1. **图表独立保存、仪表盘引用图表**，而不是把图表定义内嵌在仪表盘里。好处是复用和单独授权；代价是改一个图表会影响所有引用它的仪表盘。
2. **全局筛选器直接绑定字段和图表指标**，候选范围和接管/恢复行为已与用户讨论确定。
3. **系统不自动创建图表筛选器**，数据集没有默认时间字段。
4. **图表和仪表盘只记录修订，不能查看、比较或恢复旧版本**（4.1）。它们的结果还取决于上游的数据集和图表，单独退回一个旧版本得不到当时的样子。
5. **饼图和序列超过 8 个时合并为「其他」**，而不是报错或生成更多颜色。
6. **动态字段在图表层解析，级联在候选层缩小选项**。查询层只接收解析后的普通 IR，动态与级联不创建另一套查询执行器。
7. **组合图允许右轴，但要作者逐个指定**。两个数值轴容易误读，作图规范通常不建议；用户明确需要，所以提供，但默认关闭、图例注明、编辑器提示。

画布默认横向 96 列、纵向行高 8px、横纵网格间距各 1.5px、容器额外纵向留白 0 格，开启自动向上补位。两个方向均按格吸附。`layout.grid` 的字段与范围：

| 字段 | 默认值 | 允许范围 |
|---|---|---|
| `layout.columns` | 96 | 12–192，整数 |
| `grid.rowHeight` | 8 | 4–64px，步长 0.5 |
| `grid.columnGap` | 1.5 | 0–24px，步长 0.5 |
| `grid.rowGap` | 1.5 | 0–24px，步长 0.5 |
| `grid.containerGap` | 0 | 0–24 个空行，整数 |
| `grid.autoCompact` | true | 布尔值 |

`grid` 为可选整体配置；不存在时沿用原渲染行为，包括旧 12 列 Spec 曾按 96 列渲染的效果，不自动迁移历史坐标。显式配置允许 12–192 列。修改列数时同比换算图表和查询容器的横向边界，并约束在画布内；纵向位置和格数保持不变，必要的碰撞整理归入同一次撤销操作。

`containerGap` 是横向范围重叠的容器之间额外保留的空行数。实际纵向间距为 `rowGap + containerGap × (rowHeight + rowGap)`，组件本身的高度不包含这部分留白。关闭自动补位后保留空白，仍吸附网格且不允许重叠，碰撞时向下让位。拖拽、缩放、外部拖入、内容撑高及窄屏单列显示均保留配置的最小留白。单列显示时组件还会随内容变高（3.16）。

背景沿用淡色圆角色块，以同一组列宽、行高和间距绘制，只在编辑时生成。若横向间距会挤掉列宽，按当前画布宽度自动收窄间距，保存值不变。新图表默认宽约半幅、高 32 行，最小宽为总列数的六分之一向上取整、最小高 16 格、最大高 192 格；查询容器最小高 6 格，并按控件实际内容与内边距提高下限。编辑、预览和查看态使用相同配置。布局参数不进入图表数据依赖，修改参数不重新取数。网格与窄屏单列显示之间切换也只是挪动组件位置：组件保留已取到的数据，不重新取数。

性能复核（2026-10-16，本机 Node 24 与内嵌浏览器）：`node dev/benchmark-grid.mjs` 可复现布局计算基准。100 个组件的默认／自定义布局计算中位数约 0.50／0.53ms；500 个组件约 10.5／11.4ms，关闭补位约 0.51ms。浏览器以 20、100 个真实折线图（每图 100 点）、每场景 45 次全体行高更新比较修改前组件与新组件：默认配置的 React 同步更新时间中位数分别约 3.5／13.8ms，修改前约 3.9／13.8ms；更新到下一帧分别约 16.8／78.2ms，修改前约 18.1／77.8ms。该压力场景包含图表重绘，不包含网络取数；100 图同时持续变尺寸仍较重，配置采用点击「应用」后一次更新，避免逐键触发全体重绘。这是本机开发模式样本，不是跨设备帧率保证。独立应用按钮改动后重跑计算基准：100 个组件默认／自定义约 0.48／0.51ms，500 个约 10.8／11.3ms；待应用输入不改变网格参数。布局库补丁同时检测自定义 compactor 的变化，修复仅修改纵向留白时不重新排布的问题，不需要切换自动补位或重建图表。

查询容器「… → 设置」右侧面板可选择自动触发或手动触发，保存为仪表盘 `queryMode: "auto" | "manual"`；缺省为自动，兼容旧仪表盘。手动模式区分当前输入与已应用条件，连续输入、选择及切换编辑/预览不会刷新图表，点击「查询」才一次性应用所有当前条件。未改动、输入无效或级联反向推断未结束时按钮禁用；单图刷新使用已应用条件。筛选器候选值与级联选项仍按需请求，以支持选择条件。模式修改进入撤销/重做并持久化，临时输入不写成筛选器默认值；切回自动时应用当前有效条件。默认条件在页面首次加载时仍正常取数，删除筛选定义会同步清理输入与已应用值。

查询设置同时提供容器高度模式 `queryHeightMode: "auto" | "manual"`，缺省为自动。自动模式按控件实际高度、内边距和最小 6 格计算高度，宽度变化、换行或内容增减时可撑高也可收缩，后续图表随网格压紧；拖动右边缘只调整宽度。手动模式保留指定高度和右下角缩放手柄，同时继续以内容高度作为下限。模式随仪表盘保存，支持撤销/重做，预览与查看态同样应用。

查询容器菜单在编辑、预览和查看态提供「重置筛选条件」，一次恢复全部全局筛选器默认值，无默认值的清空；同时取消尚未提交的输入和级联推断。自动查询模式立即应用，手动模式等待点击「查询」。重置不改变已保存的默认值和图表自身的筛选条件，不进入布局撤销历史。
