# 导出、后台任务与导出中心

导出有两个来源：数据探索的 SQL 导出，以及仪表盘上的图表数据导出。两者生成 CSV 或 XLSX，共用同一套后台任务、文件存储、限制和顶栏「导出」入口。

## 1. SQL 导出

用户在数据探索提交当前 SQL（选中文本时只提交选中部分）以及参数配置的快照，后台重新执行，保留 SQL 自身的 `LIMIT`，不沿用预览的 1000 行上限。查询返回的列名与顺序直接成为文件表头，空结果也生成含表头的文件。要求当前工作空间的数据开发或管理员角色。

## 2. 图表数据导出

### 2.1 开关

图表 Spec 增加可选属性 `allowExport`，缺省为 `false`：

```jsonc
{ "specVersion": 1, "query": { /* … */ }, "viz": { /* … */ }, "allowExport": true }
```

- 在图表编辑器配置栏的「通用」分组里设置，开关名为「允许导出数据」，默认关闭。说明文字写明：打开后，能看到这张图表的人都可以在仪表盘上导出它的完整数据，行列权限照常生效。
- **开关对所有角色生效**，包括数据开发和管理员。关闭时仪表盘上任何人都没有导出入口。这样做仪表盘的人看到的就是查看者看到的，不需要按角色推测。
- 开关属于图表，图表被多个仪表盘引用时在每个仪表盘上一致。修改开关就是修改图表，要求数据开发角色，与其他图表编辑相同。
- 开关不是对数据开发的安全边界：他们仍可在数据探索中对数据源写 SQL 并导出。它限制的是仪表盘消费者能否把数据整体带走。普通用户在仪表盘上只能看到图表显示的行（默认最多 1000 行），导出却能拿到全部结果，这正是需要作者明确打开的原因。

### 2.2 谁能导出、在哪里导出

- 能打开仪表盘的人（被授权的普通用户；数据开发和管理员看到全部仪表盘，[权限设计](access-control.zh.md) 4.2），且图表的 `allowExport` 为 `true`，就能导出该仪表盘上这张图表的数据。
- 入口在图表右上角「…」操作条中的「导出数据」，仅在 `allowExport` 为 `true` 时出现，查看态、编辑态和页内预览都一样。点开后与数据探索一样，选择格式、修改文件名（默认「仪表盘名称 - 图表名称」），说明行数上限、保留时间，以及导出的是当前筛选条件下的完整结果。
- 导出按**已保存**的仪表盘执行：筛选器、联动、组件和图表的定义取自已保存的版本，查看者当前选的筛选值、动态选择和点击联动随请求提交。所以在编辑态和页内预览中，只有草稿与已保存的仪表盘一致时才能导出；有未保存的修改（包括还没保存过的新仪表盘）时按钮置灰，提示「保存仪表盘后才能导出」，避免导出的数据与眼前的草稿不一致。仪表盘编辑器的组件属性栏还会显示该图表「允许导出数据」或「不允许导出数据」，并提供进入源图表修改的入口。
- 图表编辑器首版不提供导出；数据开发可以在数据探索中导出。

### 2.3 导出什么

导出与查看者此刻在仪表盘上看到的这张图表取同一份数据，只是不截断到显示行数。

- **筛选与上下文**：请求体与仪表盘组件取数相同，包括全局筛选、图表筛选、动态选择、`useChartFilters`、点击联动和下钻路径（[图表与仪表盘](chart-dashboard.zh.md) 3.5、2.10），再加上格式和文件名。服务端按与取数相同的规则合成查询，拒绝未知筛选、未知候选和修改固定条件的请求。查看者仍然不能提交任意查询。
- **行**：查询自带的 `sort`、`limit`、`offset` 保留。作者在「通用」里设置的「最多显示行数」写在 `query.limit` 里，是图表问题的一部分（例如 Top 10），所以导出同样只含这些行。没有设置 `limit` 时，不使用取数的默认返回行数，导出全部结果，受导出行数上限约束。编辑器在 `allowExport` 打开且设置了行数时提示这一点。
- **列与表头**：列的顺序与查询输出一致。表格隐藏的列（`viz.hiddenColumns`）不导出，与仪表盘上看到的一致；其他图表类型导出查询的全部输出列。图表用到发起人看不到的字段时，仪表盘上这张图表显示「无权限」，导出也同样被拒绝（`hidden_field`）。表头使用仪表盘上显示的列名，包括数据集显示名、图表里的重命名，以及同比、环比、占比、累计的说明。这些说明由前端按界面语言生成，所以表头文字由发起导出的页面随请求提交；服务端只接受查询输出列的表头，限制长度，缺省的列用数据集显示名。表头只影响发起人自己的文件，不涉及权限。
- **值**：写原始值，不套用显示格式（单位、千分位、小数位、前后缀、百分比），XLSX 保留数值、日期和布尔类型，方便在 Excel 中继续计算。占比和增长率写成小数，例如 `0.25`；累计写累计值。其余规则与 SQL 导出的文件格式相同，见第 4 节。
- **按图表类型**：一律导出查询结果的行，不导出图表的呈现结构。透视表导出扁平的行，即每行是行维度、列维度和度量各占一列，不展开成交叉表。合计、小计和桑基图的层间合计是额外的查询，首版不导出。序列和扇区合并出的「其他」只是绘制规则，导出时保留原始各行。
- **时间**：时间范围按任务创建时间解析，时间戳按工作空间时区输出，与仪表盘显示一致。

### 2.4 快照与权限复查

- API 创建任务时校验仪表盘可见、组件存在、组件引用的图表 `allowExport` 为 `true`，并按当前定义和发起人的数据权限合成查询、编译一次，有错误立即拒绝。导出快照保存数据集 ID、合成后的查询 IR（已包含请求中的取值）、要写的列和表头、工作空间时区和周起始日；任务记录另存仪表盘 ID、组件 ID、图表 ID，以及创建时的仪表盘名和图表名，用于复查权限和在导出中心显示来源。
- worker 执行时以发起人的身份查询：重新读取数据集定义，按发起人当前的行列权限编译（数据开发和管理员不受数据权限限制，与仪表盘取数相同），不使用查询缓存。执行前和提交完成前都再检查：账号有效、仍是工作空间成员、仍能看到该仪表盘、组件仍引用同一张图表，以及图表仍然 `allowExport`。任一项不满足时任务失败，不发布文件。
- 快照固定的是任务创建时作者定义的问题：之后图表被修改，不影响已提交的任务。行列权限总是按执行时计算，权限收紧会立即反映在尚未完成的任务中。
- 创建任务后才失去某个字段的列权限时，查询在执行时被拒绝，任务以 `export_forbidden` 失败。

## 3. 执行与恢复

- API 校验格式、名称和来源，将任务与导出快照在同一事务中写入 Postgres，立即返回任务 ID。SQL 导出还校验 SQL 参数和数据源归属。每个用户跨工作空间、跨来源最多有 5 个排队或运行中的导出。
- worker 使用 `FOR UPDATE SKIP LOCKED` 原子领取任务。每次领取产生新的执行令牌，租约 30 秒，每 2 秒续期并记录已写行数。租约到期后可重新领取，最多 3 次；旧令牌不能提交结果。
- worker 重新检查账号状态和来源要求的权限（SQL 导出要求数据开发角色，图表导出见 2.4），使用与 API 相同的连接管理、只读数据库连接和数据源并发限制，导出最多占用一个数据源一半的查询槽。数据库驱动逐行读取，CSV 和 XLSX 逐行写入，不把整个结果保存在内存或查询缓存中。不同进程的并发限制仍各自计数。
- 文件完成后再次检查权限。完成状态、文件元数据和「新结果」标记在同一事务里提交；取消请求与完成提交在任务行上串行化。取消先被接受时，即使文件已经生成也不会发布。
- 关闭页面或退出登录不取消任务。用户可以在导出中心取消任务；排队任务立即取消，运行任务在下一次心跳时中断查询。进程退出后由另一个 worker 在租约到期后恢复。
- 重试会重新查询数据源，因此数据可能与第一次尝试或之前的预览不同；导出不是数据库的历史快照。来源快照、工作空间时区与导出格式保持创建时的状态。相对日期按任务创建时间计算，时间戳按提交时的工作空间时区输出，与探索预览和仪表盘一致；日期字段不做时区偏移。

## 4. 文件与限制

### 4.1 文件存放

导出文件放在导出存储里。存储有两种实现，由 `--export-storage` 选择：

| 实现 | 文件位置 | 适用 |
|---|---|---|
| `local`（默认） | `SUPABI_DATA_DIR/exports/<键>` | 单实例，或多实例挂载同一个共享卷 |
| `s3` | bucket 中的 `<前缀>exports/<键>` | 多实例部署而不想用共享卷；AWS S3 或兼容的对象存储，如 RustFS、Ceph RGW、云厂商的对象存储 |

键是 `<org>/<workspace>/<export>/<attempt>/result.csv` 或 `result.xlsx`，两种实现相同，记在任务记录里。`<attempt>` 是这次执行的租约令牌，每次执行写到不同的键，旧 worker 无法覆盖新 worker 的输出。键只能是相对路径，不能含 `..`、反斜杠，也不能以 `/` 开头。

两种实现提供同一组操作，导出、下载和清理只调用这组操作，不区分实现：

| 操作 | 本地目录 | S3 |
|---|---|---|
| 写入 | 写权限为 `0600` 的 `.part` 文件 | 在内存里攒满一片就上传一片（分片上传）；整个文件不到一片时，提交时用一次 `PutObject` 写入 |
| 提交 | 同步到磁盘后原子改名 | 上传最后一片并 `CompleteMultipartUpload`，对象此时才出现 |
| 放弃 | 删除 `.part` | `AbortMultipartUpload`，已上传的分片随之删除 |
| 读取 | 打开文件 | `GetObject`，带上请求的范围（Range） |
| 删除 | 删除文件 | `DeleteObject` |
| 清扫 | 遍历 org 目录，删除空的执行目录 | 按 `<前缀>exports/<org>/` 分页列出对象和未完成的分片上传 |

删除不存在的文件不算错误，对两种实现都一样。

导出文件不作为静态目录发布，只能经下载接口取得。

**写入与发布**。worker 边查询边写入，写完后复查权限（2.4 和第 3 节），通过后提交文件，再在 Postgres 中按租约令牌提交完成状态（第 3 节）。只有数据库提交成功，文件才能下载；在此之前，提交了的文件只是存储里的一个对象，没有记录指向它。之后的处理：

- 失败、取消、超时或租约丢失发生在提交文件之前：放弃写入，本地删除 `.part`，S3 中止分片上传。放弃用一个新的短超时上下文执行，因为任务的上下文这时往往已经被取消。
- 提交文件本身失败：尽力删除这个键。S3 的 `CompleteMultipartUpload` 超时时可能已经成功，删除可以覆盖这种情况。
- 文件已提交，但数据库判定任务被取消，或者租约已丢失：删除文件。
- 数据库提交的结果不明确（例如超时）：保留文件，由孤儿清扫按数据库记录判断（第 5 节）。

进程崩溃留下的 `.part` 文件和未完成的分片上传也由孤儿清扫处理。

**分片**。每片默认 8 MB；文件大小上限超过 80 GB 时按上限的万分之一取片大小，因为 S3 最多 10,000 片，除最后一片外每片至少 5 MB。一个导出在内存中最多占一片的缓冲，一个 worker 进程共占 `--export-workers` 片。各片依次上传，一片上传完才继续读取数据库。

**校验与加密**。只在 S3 操作明确要求时附加校验和（SDK 的 `RequestChecksumCalculation` 设为 `WhenRequired`），不启用 AWS SDK 新的默认附加校验：有些兼容存储不支持。请求仍按 SigV4 签名，生产环境应使用 HTTPS 地址。静态加密交给 bucket 的默认加密设置（SSE-S3 或 SSE-KMS），SupaBI 不单独配置。

### 4.2 S3 设置

| 启动参数 / 环境变量 | 说明 |
|---|---|
| `--export-storage` / `SUPABI_EXPORT_STORAGE` | `local`（默认）或 `s3` |
| `--s3-endpoint` / `SUPABI_S3_ENDPOINT` | 兼容存储的地址，如 `https://s3.example.com`；留空时使用 AWS S3，按 region 确定地址 |
| `--s3-region` / `SUPABI_S3_REGION` | 默认 `us-east-1`。兼容存储多数不区分 region，但签名中要用这个值 |
| `--s3-bucket` / `SUPABI_S3_BUCKET` | `s3` 时必填，需要事先建好 |
| `--s3-prefix` / `SUPABI_S3_PREFIX` | 对象键的前缀，默认为空。多套 SupaBI 共用一个 bucket 时使用，如 `prod/` |
| `--s3-path-style` / `SUPABI_S3_PATH_STYLE` | 是否用路径形式的地址（`endpoint/bucket/key`）而不是虚拟主机形式（`bucket.endpoint/key`）。默认 `false`；自建的 RustFS、Ceph 一般要设为 `true` |
| `SUPABI_S3_ACCESS_KEY_ID`、`SUPABI_S3_SECRET_ACCESS_KEY` | 访问密钥。只从环境变量读取，没有对应的启动参数，不会出现在进程列表里。两个都不设时，使用 AWS SDK 的默认凭证链：`AWS_ACCESS_KEY_ID` 等环境变量、`~/.aws` 下的配置，以及 EKS、ECS、EC2 上的 IAM 角色 |

S3 参数是通用的连接设置，名字里没有 `export`：以后其他需要存放文件的功能可以共用同一个 bucket，各用自己的前缀。

SupaBI 使用的权限：对 `<前缀>exports/*` 的 `s3:PutObject`、`s3:GetObject`、`s3:DeleteObject`、`s3:AbortMultipartUpload`，以及对 bucket 的 `s3:ListBucket`、`s3:ListBucketMultipartUploads`。

启动时检查配置：选了 `s3` 却缺少 bucket 时拒绝启动；随后用 `HeadBucket` 确认 bucket 能访问，失败（地址、密钥、bucket 名不对，或存储没有就绪）也拒绝启动，并在错误中写明原因。与 Redis 不同，存储不可用时导出全部失败，带着错误配置运行只会推迟发现问题。

**切换存储**。已有文件不会迁移。切换后，旧存储中尚未过期的文件在导出中心仍显示可下载，下载时返回 410 `export_file_missing`，到期后照常显示为过期；过期清理在新存储上删除不存在的键，不算错误。旧存储中留下的文件需要手动删除。

### 4.3 限制

两种来源使用同一组限制，由系统管理员在「系统管理 → 通用设置」里设置，存在元数据库，各实例读到同一份值，改了立即生效（[启动配置](configuration.zh.md) 第 10 节）：

| 设置 | 默认值 |
|---|---|
| 导出文件保留 | 完成后 24 小时 |
| 导出超时 | 每次尝试 15 分钟 |
| 导出行数上限 | 2,000,000 行 |
| 导出文件大小上限 | 512 MB |

同时执行几个任务按机器定，仍是启动配置：`--export-workers` / `SUPABI_EXPORT_WORKERS`，默认每个 worker 进程同时执行 2 个任务。

这些限制保护的是 supabi 服务器的磁盘、内存和执行时间。对数据源的压力已由数据源并发槽约束。以后如果某个工作空间需要更严的限制，再在工作空间设置中提供只能调低、不能超过系统值的设置。

超出行数、文件大小或 XLSX 单元格/列数上限时任务失败，不发布部分结果。文件大小上限按最终文件字节计，XLSX 为压缩后的大小。

### 4.4 文件格式

CSV 使用 UTF-8 BOM，按 CSV 规则引用逗号、引号、换行。可能被电子表格识别为公式的文本加前置单引号，正常的负数仍保留数字内容。CSV 不携带字段类型；长编号、精确小数需要直接在 Excel 中打开时，优先使用 XLSX。

XLSX 使用流式 OOXML，不建立全表共享字符串池。首行加粗并冻结；日期、时间和布尔值使用相应单元格类型，原始字符串保持文本。超过 Excel 15 位有效数字能力或可表示数值范围的数值保存为文本。每张工作表最多 1,048,576 行（含表头），后续数据自动进入下一张表并重复表头；最多 16,384 列，单元格最多 32,767 个 UTF-16 单元。依据 [Microsoft 的 Excel 限制说明](https://support.microsoft.com/en-us/excel/excel-specifications-and-limits)。

### 4.5 下载

下载接口每次检查当前登录身份、任务归属、有效期、数据源仍存在，以及来源要求的权限：SQL 导出要求数据开发角色；图表导出要求仍能看到该仪表盘、组件仍引用同一张图表且图表仍 `allowExport`。作者关闭开关或收回仪表盘授权后，已生成的文件立即不能下载。响应为附件并禁用缓存。文件到期立即禁止下载，不依赖清理任务是否已经运行。历史文件的内容不会随数据源变动更新。

两种存储都由 API 读出文件、流式转发给浏览器，不把整个文件读进内存。S3 上也不使用预签名 URL：预签名 URL 在有效期内谁拿到都能下载，绕过上面每次下载时的权限复查和下载审计，还要求浏览器能直接访问存储。转发支持断点续传：S3 上按浏览器请求的范围读取对象，通常一次下载只发一次 `GetObject`。存储中找不到文件时返回 410 `export_file_missing`。

## 5. 调度与清理

用户主动导出直接由 API 入队。scheduler 每分钟尝试为有导出记录的组织投递清理任务，按小时去重，因此每个组织每小时清理一次，进程重启后也能及时补上；实际清理由 worker 执行。

一次清理做三件事：

1. **过期文件**：按数据库中已过期、尚未清理的记录逐个删除文件（S3 上是 `DeleteObject`），删除成功后标记已清理。键记在记录里，所以这一步不需要列出存储中的文件。删除失败时保留记录，下一次清理再试。
2. **任务记录**：移除超过 30 天且文件已清理的终态任务。
3. **孤儿清扫**：列出该组织下的全部文件（本地遍历 `exports/<org>/`，S3 按 `<前缀>exports/<org>/` 分页列出对象和未完成的分片上传），与数据库对照，删除超过一小时、既不被完成记录引用也不属于有效租约的执行的文件；S3 上同时中止这样的分片上传，本地删除空的执行目录。一小时的宽限期保护清理读取数据库之后才开始写入的文件；有效租约保护运行任意长的任务。

同一组织的两次清理可能同时运行，对方已经删除的文件、已经中止的上传不算错误。S3 上可以另给 bucket 设一条生命周期规则，例如未完成的分片上传 7 天后中止，作为兜底，但 SupaBI 不依赖它。

API、worker、scheduler 可以在同一个进程，也可以分别运行；仅启动 API 时任务会排队等待 worker。

## 6. 导出中心

顶栏只有一个「导出」入口（下载图标），面向工作空间的所有成员，不随角色改变图标或含义。目前站内消息只来自导出，导出列表已经包含每个任务的状态，另设通知列表只会重复同样的信息。

- **列表**：本人在当前工作空间发起的全部导出，按创建时间倒序，SQL 导出和图表导出混排。每项显示文件名、格式、来源（「数据探索」或「仪表盘名称 / 图表名称」，取创建时的名称）、状态、行数、大小和到期时间；失败时显示原因。列表只返回元数据，不返回 SQL 或筛选取值。
- **操作**：排队和运行中的任务可以取消。成功的任务在仍有下载权限时显示「下载」；权限已不满足时（例如角色降为普通用户后的 SQL 导出、图表已关闭导出、仪表盘授权被收回），显示「无权下载」及原因，不提供下载。
- **新结果**：任务成功或失败时标记为本人未看过的新结果；本人取消的任务不标记。顶栏角标显示新结果数量；有任务在排队或运行且没有新结果时显示一个小圆点。打开导出中心即把当前的新结果全部标为已看，这些项在本次打开期间保持高亮，不需要逐条标记已读。
- **提示**：新结果出现时显示短提示，例如「销售明细.xlsx 已可下载」或「销售明细.xlsx 导出失败」，附「查看」按钮打开导出中心。
- **刷新**：可见页面在有运行任务时每 3 秒查询一次，无运行任务时每 15 秒检查；页面隐藏时暂停，重新可见时立即刷新。发起导出后立即打开导出中心并刷新。
- **权限**：查看本人的导出列表和取消本人的任务，要求仍是该工作空间成员，不限角色。新建 SQL 导出要求数据开发角色，新建图表导出见 2.2，下载见第 4 节。
- 退出登录后记录仍保留，下次进入相同工作空间可查看。没有邮件或站外推送。

以后有告警、订阅等与下载无关的消息时，再在顶栏加独立的通知入口（铃铛），按消息种类展示并跳转到对应对象；导出入口继续只管导出任务。

接口：`GET /exports` 返回本人的导出、新结果数量（`unseen`）和限制；每项带来源（`source`、`dashboardName`、`chartName`）、是否为新结果（`unseen`），以及成功且未过期但当前不能下载时的原因（`denied`）。`POST /exports/seen` 把本人在当前空间的新结果全部标为已看。原先的通知表和 `/notifications` 接口已移除，迁移时未读的成功和失败通知转为新结果。

## 7. 导出审计

导出的关键动作写入审计日志（见 [权限设计](access-control.zh.md) 第 7 节），作为导出数据流向的记录，在系统管理的「审计日志」中按「导出」类别查询：

| 事件 | 记录 |
|---|---|
| 创建 `export.create` | 导出 ID、名称、格式、来源。SQL 导出记录数据源 ID、SQL 全文与参数取值；图表导出记录仪表盘、组件、图表、数据集 ID 和请求中的筛选取值 |
| 完成 `export.finish` | 终态（成功、失败、取消）、行数、文件大小、失败原因代码。由 worker 记录，操作人是发起人 |
| 取消 `export.cancel` | 导出 ID |
| 下载 `export.download` | 下载用户、行数、文件大小。下载是数据离开系统的时刻，因此单独记录；拒绝下载记为结果「拒绝」，并写明原因（过期、权限、来源已删除） |

审计详情只在元数据库中，应用日志里的审计行不含 SQL；文件内容不记录。完整的 SQL 快照另在任务记录中保存 30 天。
