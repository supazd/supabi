# AI 助手

状态：第一步（最基础的 Agent）、第二步（用量页面，第 13 节）和第三步（工具，第 12 节）已实现。第四步只记方向，做到时再设计。

## 1. 定位

- AI 助手是一个 Agent，先给普通用户用。它先要解决的问题是让人快速拿到想要的数据。
- 数据来自用户有权限的仪表盘和图表。数据集不直接取数，用来解释口径（字段的显示名、说明、同义词）。
- 回答里的每个数都要有出处：哪个仪表盘、哪张图、什么筛选条件、图表和数据集的第几版。否则用户拿到一个系统里本不存在的数，数据开发无法核对它怎么算出来、是否和内部口径一致。生成的 SQL 不给普通用户看：有了版本和条件就能复现，审计日志里也记着（12.3）。
- 和其他入口一样，AI 不直接写 SQL（[架构总览](architecture.zh.md) 第 3 节）。

## 2. 分步

| 步骤 | 内容 |
|---|---|
| 1. 最基础的 Agent | 系统管理里配置模型；能正常聊天；压缩上下文；记录用量和花费。本文第 3 到 10 节 |
| 2. 用量页面 | 系统管理里单独一页，按人、模型、工作空间、用途、天看用量和花费；不看对话内容。AI 看了哪些数据已在审计日志里。第 13 节 |
| 3. 工具 | 工具按角色分配；四个只读工具查用户能打开的仪表盘上的图，回答带出处；图表上没有的数用计算器算，算式也是出处。第 12 节 |
| 4. 记忆与历史对话 | 记住用户的偏好和习惯，参考以前的对话 |

先保证 Agent 本身可用，再加工具。开发阶段不为「还没有工具」另加限制。

## 3. 模型配置

### 3.1 供应商和模型

系统管理里新增「AI 模型」，只有系统管理员能看和改，全组织共用，不按工作空间分。改了立即生效：每次调用模型前从元数据库读当前配置，各实例一致，不用重启。正在生成的回答用它开始时的模型写完。

**供应商**：

| 项 | 说明 |
|---|---|
| 名称 | 管理员自己起，如「DeepSeek」「内网 vLLM」 |
| 协议 | 第一步只有「OpenAI 兼容」（Chat Completions 的流式接口）。DeepSeek、通义千问、Kimi、智谱，以及 vLLM、Ollama 部署的模型都提供这种接口。以后再加「Anthropic」，Claude 走它自己的协议 |
| 接口地址 | 如 `https://api.deepseek.com/v1` |
| API 密钥 | 和数据源密码一样用 `secret-key` 加密后存库。读取时不返回原文，只说明是否已设置；编辑时不填就不变 |

**模型**属于一个供应商：

| 项 | 说明 |
|---|---|
| 模型 ID | 调用接口时传的名字，如 `deepseek-chat` |
| 上下文长度 | token 数，压缩上下文按它判断（第 6 节）。可以照供应商的写法填 128K、1M，1K 按 1,000 计 |
| 最大输出 | token 数，每次调用都带上 |
| 思考等级 | 选填。填了就作为 `reasoning_effort` 原样发给供应商，不填就不发，由供应商决定。见下 |
| 价格 | 每百万 token：输入、缓存命中的输入、缓存写入、输出。缓存命中和缓存写入有的供应商不单独收费，可以不填，不填时按输入的价格算 |
| 币种 | 这个模型的价格用什么货币，存 ISO 4217 代码，如 `CNY`、`USD`。从列表里选，列表显示代码、符号和名称，三者都能搜。不同供应商可以不同 |

金额用定点小数，不用浮点数。价格和币种都可以改，只影响以后的用量记录。

思考等级是文本，不是下拉框：各家的取值不一样，DeepSeek 和 Kimi 是 low、high、max，OpenAI 还有 none、xhigh，写死几个值总会缺。填错的值由供应商报错，点「测试」就能看到（3.3），所以只限制长度，最多 32 个字符。

- 只用于回答问题和测试。起标题和压缩上下文不带：它们的 token 上限小（1024 和 4096），模型的思考也算在内，等级高时可能还没写出结果就用完了。
- 设了等级时，测试用模型的最大输出，和回答问题时一样，否则思考用完了额度，会误报回复为空或不调用工具。没设等级时，测试的额度不变。
- 不是每家都认：通义千问用 `enable_thinking` 和 `thinking_budget`，这类模型留空。这些参数和 `thinking.type` 这样的开关不做。

删除：被某个用途用着的模型不能删，要先换掉；删供应商时一并删掉它的模型，同样要求这些模型都没被用着。用量记录存的是当时的名称快照，不受删除影响。

### 3.2 用途

不同的事用不同的模型，各选一个：

| 用途 | 说明 |
|---|---|
| 对话 | 回答用户，必须设置 |
| 标题生成 | 给会话起标题，不设置时用对话的模型 |
| 上下文压缩 | 总结较早的对话，不设置时用对话的模型 |

用户始终不能自己选模型，只有管理员在后台改，用户不需要了解模型。没有设置对话模型时，AI 助手页面提示管理员还没有配置；系统管理员看到的提示里有去配置的链接。

### 3.3 测试

每个模型有「测试」按钮：发一条很短的请求，显示是否成功、耗时，失败时显示供应商返回的错误。测试也花钱，记一条用量，用途为「测试」。

## 4. 对话

### 4.1 入口和归属

- 顶栏新增「AI 助手」，所有角色都能用。页面左边是会话列表，右边是当前会话。
- 会话属于「本人 + 工作空间」：切换工作空间看到的是那个空间里的会话。第三步的工具读的是当前空间的仪表盘，会话跟着空间走。工作空间永久删除时会话一起删除。
- 会话只有本人能看。拿别人的会话 ID 调接口得到「不存在」。

### 4.2 会话列表和标题

- 新建、改名、删除，按最近更新排序。删除会话同时删除其中的消息，用量记录保留。
- 第一轮回答完成后，用标题生成模型根据第一个问题和回答起一个短标题，生成好了列表里自动更新。在此之前，或者生成失败时，标题是第一个问题的开头。用户改过名的不再自动改。

### 4.3 发送、流式输出和停止

- 用户发一条消息，服务端先存下，再调用对话模型，用 SSE（`text/event-stream`）把增量文字推给浏览器，写完存下完整回答。
- 输入框回车发送，Shift+回车换行；输入法组字时的回车不发送。
- 同一个会话同时只能有一个回答在生成，生成期间不能再发。
- 还没有文字输出时显示「思考中」。有的模型（如 DeepSeek 的推理模型）在正文之前另外返回思考过程，第一步不显示也不保存，只当作「还在工作」。
- 「停止」后，服务端取消对模型的请求，已经生成的部分保存下来，标为「已停止」。
- 生成跟着这次请求走，不放进后台任务。关闭、刷新或离开 AI 助手页面等同于停止。这样最简单，代价是刷新页面会中断回答。在 AI 助手里切换到别的对话不会停止，回答在后台写完；写的过程中不能在别的对话里发送。
- 正在写的回答每 15 秒保存一次已写的部分，同时表明还在写。服务异常退出时没写完的回答，一分钟没有更新就算中断，再打开时显示为失败（原因是中断），可以重试。
- 部署在反向代理后面时，代理不能缓冲这个接口的响应，否则文字会攒到最后一起出来。服务端带上 `X-Accel-Buffering: no`，其他代理要另外配置。

### 4.4 出错

模型连不上、超时、密钥不对、被限流、供应商返回错误时，这条回答标为失败并显示原因，可以「重试」，重新生成这一条。供应商长时间什么都没发来（暂定 5 分钟；思考过程和它为保持连接发的注释行都算）时中断，按超时处理。

单条消息本身就超过可用的上下文时，不发送，直接说明这条消息太长。除此之外，对话再长也不应该因为超出上下文而失败，见第 6 节。

### 4.5 显示

- 用户的消息按纯文字显示，保留换行。
- 回答按 Markdown 显示，用 AI 助手自己的组件，不复用仪表盘「文本」的代码：文本组件以后要改，AI 这边也会按需加功能，两边各自演进。
- 第一步的要求是流式输出时能正常渲染：写到一半的代码块、表格、列表不错乱、不闪动。用 react-markdown 和 remark-gfm 渲染（表格、删除线等 GitHub 写法）；写的过程中先用 remend 把末尾没写完的加粗、代码、链接补齐再渲染。单个波浪号不当删除线，「20~25%」照原样显示。文字每 50 毫秒合并刷新一次，模型输出很快时也不会每几个字重画一遍。
- 支持标题、列表、表格、代码块、链接和图片，外部图片照常显示，链接在新标签页打开。Markdown 里的 HTML 按文字显示，不执行。
- 消息列表打开时停在最后。正在写回答时，读者停在最后就跟着往下走；往上翻了就停住，出现「回到最新」按钮。发送一条消息会回到最后。用的是 use-stick-to-bottom。
- 这些界面组件（消息列表、消息、Markdown、输入框）放在组件包 `packages/ui` 的 `Chat.tsx`，AI 助手页面只从组件包引入，见 [架构总览](architecture.zh.md) 11.2。没有用 shadcn 生态的 AI Elements，原因和何时重新评估见 [暂缓事项](../backlog.zh.md)。

## 5. 发给模型的内容

- **系统提示**：它是 SupaBI 的 AI 助手；按用户的语言回答；当前日期和工作空间时区；用工具在用户能打开的仪表盘上查数，数怎么写、怎么标出处见 12.3（第一步时是「还查不到数据，如实说明，不编造数字」）。写在代码里，不可配置。
- **对话内容**：系统提示 + 压缩摘要（如果有）+ 摘要之后的消息。已停止的回答用户看到过，照常带上；失败的不带。

## 6. 上下文压缩

对话再长也不能因为超出上下文而失败，到一定长度就把较早的部分压缩成摘要。

- **判断用了多少**：每次调用模型，供应商都会返回这次的输入和输出各用了多少 token，据此知道这个会话的上下文已经有多长。服务端不为各家模型自己数 token；供应商没有返回用量时按字数估算。
- **何时压缩**：上一次调用的输入加输出，再加上这次新发的消息（按字数估算），超过可用上下文（上下文长度减最大输出）的 80%（暂定）时，先压缩再发送。供应商仍然报上下文超长时，压缩后重试一次。
- **怎么压缩**：用上下文压缩模型，把旧摘要和要压缩的消息总结成一份新摘要，保留用户的目标、已经得出的结论、还没解决的问题和提到过的名称。最近的消息原样保留，不超过可用上下文的四分之一（暂定），至少保留最后一轮。要压缩的内容超过压缩模型的上下文时，分段总结。
- **只保留最新一份摘要**，存在会话上，并记下它总结到第几条消息为止。
- **用户看到的不变**：界面上仍显示完整的对话，只是发给模型的内容换了。压缩时显示「正在整理对话」。
- 压缩的花费照常记录，用途为「上下文压缩」。

## 7. 用量和花费

每次调用模型记一条，页面见第 13 节：

| 内容 | 说明 |
|---|---|
| 时间、组织、工作空间、用户 | |
| 会话、消息 | 测试时为空 |
| 用途 | 对话、标题生成、上下文压缩、测试 |
| 供应商、模型 | 名称和模型 ID 的快照 |
| token | 未命中缓存的输入、缓存命中的输入、缓存写入、输出，四类互不重叠 |
| 花费、币种 | 按调用时模型的价格和币种算好存下，以后改价格或币种不影响已有记录 |
| 耗时、结果 | 成功、失败、已停止 |
| 是否估算 | 供应商没有返回用量时按字数估算，并标明 |

各家报告用量的方式不同，统一换算成上面四类再记：

- OpenAI 兼容接口报告的输入（`prompt_tokens`）里包含缓存命中的部分（`prompt_tokens_details.cached_tokens`），要减掉；有的供应商用自己的字段，如 DeepSeek 的 `prompt_cache_hit_tokens` 和 `prompt_cache_miss_tokens`。
- 流式调用时，用量要在请求里要求（`stream_options.include_usage`），供应商在最后一段返回。停止或失败时可能拿不到，按字数估算。
- 以后加 Anthropic 协议时，它的 `input_tokens` 不含缓存读写，缓存命中和缓存写入另有两个字段。

统计花费时按币种分开计算，不同币种之间不相加、不换算：系统没有汇率来源。

记录不建外键，用户、会话、模型删除后照常保留，工作空间永久删除时也保留：和审计日志一样，是组织的记录。保留期和审计日志相同，见 13.5。

## 8. 权限和审计

- AI 助手：至少是普通用户，也就是所有角色。这是 [权限设计](access-control.zh.md) 4.1 中「做到时再决定归哪个角色」的结论。
- 模型配置和用途：系统管理员。
- 模型配置的增删改和用途的设置记入现有的审计日志，新加一个类别 `ai`。请求内容里有 API 密钥，和数据源一样只记对象、不记内容。
- 对话内容不进审计日志，管理员也看不到（13.2）。AI 取了哪些数据，记在查询事件里（12.6）。

| `POST /assistant/messages/{id}/retry` | 重新生成失败的回答，返回方式同上 |

## 10. 为后面几步留的位置

- **消息的内容存成一串「片段」**：第一步只有文字。第三步的工具调用和工具结果（带出处）放进同一串，不用改表结构。
- **Agent 的循环**：第一步每次回答只调用一次模型（`internal/assistant` 的 `write`）。第三步在这里改成「调用模型 → 有工具调用就执行 → 把结果交回模型」的循环（12.4）。工具列表按当前用户算：每个工具登记至少需要哪个角色，没登记的不给，和接口的做法一样。以后要细到按人或用户组，也在这一处扩展。
- **摘要和出处**：压缩时，以前回答里的数进了摘要就丢了出处。第三步定为摘要只记查过什么，不记数值，要用时重新查（12.4）。
- **会话存在服务端**，第四步参考历史对话在此基础上做。记忆只记偏好和习惯（常看哪个仪表盘、「营收」指哪个指标），不记数据本身：数每次重新查，记住的数会过时，也没有出处。

## 11. 第一步不做

- 工具和出处（第三步）；用量页面（第二步）；记忆和参考历史对话（第四步）。
- 用户自己选模型：一直不做。
- Anthropic 协议：作为下一种协议加入。
- 对回答内容的安全限制（如外部图片）：以后再考虑。
- 显示思考过程、可配置的系统提示、上传文件和图片、编辑已发送的消息、对成功的回答重新生成、分享和导出会话。

## 12. 第三步：工具

状态：已实现。

### 12.1 范围

- 四个只读工具，都只要普通用户角色。数据只从本人能打开的仪表盘上取，取法和在仪表盘上操作一样：全局筛选、图表筛选、动态维度和指标、下钻、联动。
- 每个工具对应一个现有的查看者接口，调用同一批函数，按当前用户的身份执行。仪表盘授权、行列权限、查询缓存、审计照旧生效，不另写一套（[架构总览](architecture.zh.md) 第 1、3 节）。查看者只能提交取值、不能提交查询（[图表与仪表盘](chart-dashboard.zh.md) 3.5），对 AI 同样成立。
- 不做：直接查数据集、写 SQL（普通用户没有这个入口，见 [权限设计](access-control.zh.md) 4.1.1）；血缘和引用关系（只有数据开发能看）；导出、生成个人仪表盘（不是只读）；MCP 服务（只预留，见 12.7）。

### 12.2 四个工具

| 工具 | 输入 | 返回 | 对应接口 |
|---|---|---|---|
| `list_dashboards` | 无 | 当前工作空间里本人能打开的仪表盘：ID、名称，每个仪表盘上图表组件的 ID 和名称 | `GET /dashboards` |
| `describe_dashboard` | 仪表盘 ID | 筛选器，以及每张图能怎么取数，见下 | `GET /dashboards/{id}` |
| `filter_options` | 仪表盘 ID、筛选器 ID，图表自身的筛选器另带组件 ID；可选搜索词、已选的其他筛选值 | 最多 500 个候选值和是否截断，与界面上的候选相同；级联时按已选的值缩小 | `POST /dashboards/{id}/filters/{filterId}/options`、`POST /dashboards/{id}/items/{itemId}/filters/{filterId}/options` |
| `query_chart` | 仪表盘 ID、组件 ID；全局筛选、图表筛选、动态选择、下钻路径、联动的取值 | 数据和出处，见 12.3 | `POST /dashboards/{id}/items/{itemId}/data` |

列表和详情分开：仪表盘多了，一次给出全部图表的字段会占满上下文。模型先按名称挑仪表盘，再看详情。

`describe_dashboard` 返回：

- **全局筛选器**：ID、名称、字段类型、操作符、单选还是多选、默认值、作用于哪些图、级联的父筛选器。参数筛选器（[图表与仪表盘](chart-dashboard.zh.md) 2.11）一样列出。时间筛选器写明可以用相对时间（如「上个月」），由服务端按工作空间时区解析。
- **每张图**：组件 ID、名称、图表类型；维度和指标的显示名，以及它们在数据集里的说明和同义词，用来对上用户说的词和口径；图表自身的筛选器，写法同全局筛选器，并注明哪些被全局筛选接管；动态位置和候选；能下钻时，下钻的维度和往下各层的名称。
- **联动**写在目标图上：「可以按 地区 等于某个值缩小，值取自〈来源图〉的〈列〉」，模型不用理解来源和目标。
- 只列图表组件，标题、文本等组件不列。字段说明按列权限给，看不到的字段不给（[权限设计](access-control.zh.md) 5.2）。

`query_chart` 的取值与仪表盘取数请求相同（[图表与仪表盘](chart-dashboard.zh.md) 3.5），只是不提供「刷新数据」和「使用图表筛选」：AI 和查看者一样按缓存规则取数；被全局筛选接管的图表筛选，通过全局筛选来改。

### 12.3 结果和出处

- **交给模型的数据**：列名用显示名，值用原始值，每列附上显示格式（百分比、小数位、单位），模型照格式写数。最多 200 行（暂定），多出的截掉，并告诉模型一共多少行；合计照常给。
- **出处**：一次 `query_chart` 是一个出处，在一条回答里按 [1]、[2] 编号。出处记下：
  - 仪表盘和图表组件的 ID、名称，仪表盘、图表和数据集的版本号；
  - 实际生效的条件：全局筛选、图表筛选、动态选择、下钻路径、联动，没传而用了默认值的也写上；相对时间写出解析后的起止日期，日期参数相对今天的取值（如 `today-1d`）写出取数时的那一天；
  - 数据的时间（命中缓存时是缓存的时间）、模型是否只读到部分行。图表本身只列前几行的不算：它展示的每一行模型都读到了；
  - 打开的链接，见下。
- **不给普通用户看 SQL**。版本号加上条件就能复现；每条 SQL 也照常记在审计日志的查询事件里（[权限设计](access-control.zh.md) 7.3）。
- **链接**借用分享链接存条件（[图表与仪表盘](chart-dashboard.zh.md) 3.10）：取数时把这次的条件存成一条，带上这张图所在的页和标签，打开就能看到它；有效期 30 天，链接放进工具结果。没有任何条件时不存，打开的就是仪表盘本身。服务端存的下钻位置只有值，打开时按各层的粒度写出来。这不是有人在分享，不记 `dashboard.share` 事件，取数本身照常记查询事件。分享的条件要先能带上下钻位置（3.10），否则下钻后的出处打开时回到第一层。
- **过期**：站内点出处的「打开」时，用存下的条件重新保存一次再打开。相同的条件得到同一个 ID，过期时间往后延，所以旧对话的出处也能打开；这一次走分享的接口，记一条 `dashboard.share` 事件。只存在工具结果里的链接（以后的 MCP）到期就失效。
- 仪表盘、图表后来改了或删了，出处照样显示当时的名称和版本；链接打开的是现在的仪表盘，看不到时和仪表盘本身一样提示不存在或没有权限。

**回答怎么用出处**，写进系统提示：

- 回答里的数只能来自工具结果，每个数后面标出处编号，如「华东上月营收 1,234 万元[1]」。
- 图表上没有、但能由查到的数算出来的数（差值、增长率、占比），用 `calculate` 算，不心算，正文里写出怎么算的（12.9）。可以比大小、说排名。查不到、也算不出用户要的数时如实说明，并指出最接近的图。
- 几张图都可能是用户要的数时，说明用的是哪一张，并提一下其他的。

**界面**：回答下方是这条回答的出处，默认折成一行，写出条数和用到的仪表盘，如「出处 5 条 · 销售看板、库存看板」：仪表盘去掉重复的，按编号先后排，一行放不下时省略。点这一行展开，再点收起。出处多时逐条列出来比正文还长，喧宾夺主，所以和查数步骤一样折起来。展开后每条出处写「仪表盘 › 图表」、条件摘要（与分享对话框的写法相同）、数据的时间和「打开」。正文里的编号可以点：出处折着时先展开，再跳到对应的那一条。每条回答各自展开、收起，不记住，重新打开对话时都是折着的；写回答的过程中，条数随取数增加。生成过程中，工具调用显示为一行状态，如「正在查：销售看板 › 月度营收」；写完后折叠成「查了 3 次」，可以展开。组件放进 `packages/ui`；按 [暂缓事项](../backlog.zh.md) 里的约定，先评估 AI Elements 的 tool、inline-citation 组件合不合用。

### 12.4 Agent 的循环

`write` 改成循环：调用模型时带上工具；模型要调工具就依次执行，把结果交回去再调用；模型不再调工具时，这次的文字就是回答。

- **上限**：一条回答最多调用工具 20 次（暂定）。到了上限，最后一次不再给工具，让模型就已有的结果回答。模型一次回复里同时调用多个工具时也算在内，超出的不执行，告诉模型已到上限。
- **工具出错**（未知的筛选器或候选、没有权限、查询失败）不让回答失败：错误说明作为工具结果交给模型，模型可以改了再试，或者如实告诉用户。
- **停止**：正在执行的查询一起取消，已经写出的文字和工具结果保存下来。
- **上下文**：前几轮的工具调用和结果照常发给模型，追问「那华南呢」时用得上；太长时按第 6 节压缩。压缩时摘要只记查过什么（仪表盘、图表、条件），不记数值，要用时重新查，免得数没了出处。一条回答之内的工具结果不压缩；这条回答用到可用上下文的 80% 时，不再给工具，让模型就已有的结果回答。
- **SSE 事件**加一种「工具」：开始执行时带上工具名，结束时再发一次，带上查了什么（仪表盘、图表的名称）和出处。每 15 秒保存已写的部分时，连同工具调用和结果一起保存。停止时正在执行的那一次调用不保存：它返回了什么不知道。
- **模型要支持工具调用**（OpenAI 兼容接口的 `tools`，流式返回的 `tool_calls`）。模型的「测试」多发一次带工具的请求，不支持时提示管理员。推理模型在工具循环里要不要回传思考过程，各家要求不同，实现时按供应商实测。

### 12.5 存储

- 回答的「片段」（第 10 节）多一种「工具」：一次调用和它的结果放在同一个片段里（调用 ID、工具名、参数、交给模型的内容、查了什么、出处），和文字片段按发生的顺序排在一起，不改表结构。片段记下它是这条回答第几次调用模型时发出的：同一次发出的几个工具，交还给模型时放在一起。推理模型的思考过程记在每次的第一个工具上，只在这条回答之内交还，以后的回答不带。
- 接口只给界面看工具名、查了什么、是否完成或失败和出处，不给交给模型的内容。
- 「重试」重新生成整条回答，工具调用也重来。

### 12.6 工具的定义和权限

- 每个工具只登记一次：名称、给模型看的说明、参数格式（JSON Schema）、最低角色、执行函数。站内 Agent 的循环和以后的 MCP 服务（12.7）是同一套工具外面的两层壳。
- 工具的实现放在接口层（`internal/api`），和对应的接口处理函数调用同一批函数。`internal/assistant` 只认识「工具」这个接口：api 引用了 assistant，反过来引用会成环。
- 执行时用这次请求的身份和工作空间，和接口一样。工具列表按角色算，没登记的不给（第 10 节）；这四个都是普通用户。
- 每次取数（`query_chart`、`filter_options`）照常记查询事件，对象是仪表盘，详情注明来自 AI 助手。
- 工具本身不花模型的钱；用量和花费照第 7 节记在模型调用上。
- `calculate`（12.9）不在这里登记：它不碰数据、不涉及权限，由 Agent 循环自己提供。

### 12.7 为 MCP 服务预留

以后要做 MCP 服务，让普通用户用本地的 Agent 取数。打算在同一个程序里多一个远程 MCP 地址，用户在本地 Agent 里填上地址就能用，不用另装程序。这一步不做，只保证两点，以后不用返工：

- 工具不依赖 AI 助手（12.6），MCP 直接暴露同一套工具。
- 出处在工具结果里，带链接（12.3）：MCP 的客户端只看得到工具结果。

MCP 不提供 `calculate`（12.9）：本地 Agent 有自己的计算能力。

做 MCP 时再定：浏览器以外的登录方式（个人令牌或 OAuth），以及令牌属于哪个工作空间；数据经用户自己的模型离开系统，实际上等于导出，要不要按图表的「允许导出数据」限制，管理员要不要总开关。模型配置、花费、压缩、会话只属于站内 Agent，MCP 用不上。

### 12.8 实现顺序

原计划分三步，实际一起实现、一起测试：

1. 分享链接带上下钻位置（[图表与仪表盘](chart-dashboard.zh.md) 3.10）。它本身是查看体验的改进，单独能试。
2. 模型的工具调用、Agent 循环、消息片段，加上 `list_dashboards` 和 `describe_dashboard`：能问「有哪些仪表盘」「这个仪表盘能看什么」。
3. `filter_options`、`query_chart`、出处和界面：能问出带出处的数。

### 12.9 计算

状态：已实现。

图表上没有、但由查到的数简单算得出的数（差值、增长率、占比、几项之和），原先一概不答，看起来很怪。现在让模型用 `calculate` 工具算，自己不心算，算式作为一个出处列出来。

当初不让模型算，担心三件事，计算器各管多少：

| 担心 | 怎么办 |
|---|---|
| 算术算错（大数相减、除法） | 程序算，十进制定点，不用浮点数 |
| 拿来算的数读错、记错或编出来 | 服务端核对每个输入确实在它所说的出处里 |
| 口径错：把平均数、比率、去重人数相加，把前十名加总当成全部 | 计算器挡不住。算式摆出来让人看得到，工具说明和系统提示里提醒模型 |

**工具**：输入是算式和它用到的输入，每个输入写名称、值和出处编号：

```jsonc
{
  "expression": "(a - b) / b",
  "inputs": {
    "a": { "label": "华东销售额", "value": 4184761.25, "source": 1 },
    "b": { "label": "华南销售额", "value": 3005120.40, "source": 1 }
  }
}
```

- 算式只有 `+ - * /`、括号、输入的名称和常数。常数如 ×100 换成百分比、÷12 算月均，照写在算式里，出处里一并显示。
- 十进制定点计算，除法保留 10 位有效数字（暂定）。返回结果和这次计算的出处编号。
- **核对输入**：每个输入的值要出现在它所说的出处里：取数结果的某一行或合计行里的某个格子，按数值比较（`"100.50"` 与 `100.5` 相等）；也可以是这条回答里前一次计算的结果。对不上、出处不存在都不算，把原因交回给模型改。
- **只用这条回答里的出处**：前几轮回答里的数要用时重新查，与 12.4「数要用时重新查」一致。代价是追问时多查一次。
- 除以零、算式写错、用了没给出的名称，都作为错误交回给模型。
- 计算器和取数工具一起给模型。到了调用上限、或者没再给工具时，模型仍发来的工具调用不执行，这次的文字就是回答。

**出处**：一次计算占一个出处编号，和取数的出处排在同一个序列里。出处记下算式、各输入的名称、值和出处编号，以及结果。界面上写作「③ 计算：(华东销售额 [1] − 华南销售额 [1]) ÷ 华南销售额 [1] = 0.3925」，没有「打开」；其中的 [1] 可以点，跳到对应的取数出处。

**回答怎么写**，写进系统提示和工具说明：

- 图表上没有的数用 `calculate` 算，正文里写出怎么算的，如「华东比华南多 117.96 万 [3]（华东 418.48 万 [1] − 华南 300.51 万 [1]）」。
- 不把平均数、比率、去重计数相加。
- 要合计时用结果里的合计行；结果被截断，或者图本来只列前 N 名时，不拿各行相加当全部。
- 只做用户要的算术，不预测、不估算。

**放在哪里**：`calculate` 放在 `internal/assistant`，由 Agent 循环自己提供，它看得到这条回答已有的工具结果，用来核对输入。存储上和其他工具一样是回答的一个「工具」片段，出处多一种「计算」。计算不调用模型，不记用量，也不碰数据源，不记查询事件。

## 13. 第二步：用量页面

状态：已实现。

### 13.1 为什么要做

- 每次调用模型的用量和花费都记下了（第 7 节），但只能直接查库看到。
- 「AI 看了哪些数据」不用另做：每次取数都记在审计日志的查询事件里，详情注明来自 AI 助手（12.6），带图表、条件和 SQL。第二步只补用量和花费。
- 2026-10-25 在开发库实测：24 条回答调了 45 次模型，平均每条 1.9 次、最多 6 次，工具循环每一轮都要重发整段上下文；输入 40.7 万 token、输出 2 万，缓存命中为 0（OpenRouter 上的 Claude Haiku 5.5）。按模型列出四类 token，管理员才看得出这种情况。

### 13.2 范围

- 系统管理里「AI 模型」下面新加一页「AI 用量」（`/settings/system/ai-usage`），只有系统管理员能看。模型和花费属于全组织；和审计日志一样，空间管理员没有只看本空间的视图。
- 只看用量和花费，不看对话内容。会话只有本人能看（4.1），用户是按这个预期提问的。会话标题由第一个问题生成，所以也不显示。
- 查看用量页不记审计，和查看审计日志一样。

### 13.3 页面

**筛选**只有时间范围，默认近 30 天（含今天）。和审计日志一样，按浏览器所在的时区划分日子。

**合计**写在最上面：

| 项 | 说明 |
|---|---|
| 花费 | 按币种分开写，如「USD 0.05 · CNY 12.30」，不相加、不换算（第 7 节） |
| 回答数 | 用途为对话的调用涉及多少条回答 |
| 调用次数 | 另写其中失败、已停止的次数 |
| token | 四类分开：未命中缓存的输入、缓存命中的输入、缓存写入、输出。有按字数估算的调用时，写明有几次 |

**汇总表**：从按人、模型、工作空间、用途、天中选一种，每组一行，写调用次数、四类 token 和花费。

- 一组用了两种币种时，花费格里两种并列写，不相加。
- 按调用次数从多到少排：不同币种没法按花费排。按天时从近到远排，没有调用的日子不列。

各组的名称：

| 分组 | 写法 |
|---|---|
| 人 | 现在的姓名和邮箱。账号只能停用、不能删，总能找到 |
| 模型 | 记录时的供应商和模型名称，如「OpenRouter · anthropic/claude-haiku-5.5」。改过名的分成两行；模型删了照常显示 |
| 工作空间 | 现在的名称，永久删除后写「已删除的工作空间」。模型测试不属于任何工作空间，写「模型测试」 |
| 用途 | 对话、标题生成、上下文压缩、测试 |
| 天 | 日期 |

### 13.4 接口

`GET /ai/usage`：参数为起止时间、分组方式（`user`、`model`、`workspace`、`purpose`、`day`）和浏览器的时区（IANA 名称，按天分组时用）；返回合计和各组，花费按币种分开。只有系统管理员能调，不记审计。

### 13.5 保留

- 用量记录和审计事件用同一个保留期，即「系统管理 → 通用设置」里的审计保留（默认 180 天，`0` 表示永久保留，见 [权限设计](access-control.zh.md) 7.6），由每小时的维护任务一起分批删除，不另加配置。
- 要看更长时间的花费，就把保留期调长或设为 `0`。用量记录每条只有两三百字节；1000 人每天各问 20 次、每次回答调用两次模型，一年约 1500 万行。

### 13.6 这一步不做

逐次调用的明细列表、用量趋势图、导出用量、审计日志按「来自 AI 助手」筛选、空间管理员只看本空间的用量、管理员查看对话内容、用量单独的保留期。原因和何时重新评估见 [暂缓事项](../backlog.zh.md)。
