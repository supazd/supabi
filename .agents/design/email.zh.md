# 邮件

状态：第一步（第 1 到 9 节）已实现：SMTP 设置、测试邮件和一个发信的函数。还没有功能发邮件。2026-11-08 定下。

## 1. 为什么做，这一步做什么

好几个功能在等邮件：

- 找回密码和邮件邀请，账号功能现在缺这两样（[暂缓事项](../backlog.zh.md)「现有实现的缺口」）。
- 定时导出和订阅（[导出设计](exports.zh.md)）。
- 以后的告警。

管理员没配好邮件服务器，这些都做不成；而服务器怎么配，不取决于它们哪个先做。所以这一步只做它们共用的部分：

- 系统管理里的 SMTP 服务器设置。
- 测试邮件，让管理员在有功能依赖它之前就知道设置能用。
- 后端一个发一封信的函数，给这些功能调用。

信怎么排队、重试、记录，取决于发的是什么、谁在等它，所以由第一个发邮件的功能来定（第 10 节）。

## 2. 设置放在哪里

设置存在元数据库里，每个组织一行，系统管理员在「系统管理 → 邮件」里修改。启动配置里没有这些设置，也不能用环境变量覆盖，理由和系统设置一样（[启动配置](configuration.zh.md) 10.5）：留了覆盖，各实例又可能不一致。

S3 和 Redis 留在启动配置（[启动配置](configuration.zh.md) 10.6），但那里的理由一条都不适用于 SMTP 服务器：

| | S3 和 Redis | SMTP 服务器 |
|---|---|---|
| 客户端 | 启动时建好，启动时顺带检查能不能连上 | 每封信连一次，发完就关 |
| 运行中换掉 | 旧文件留在旧的地方；共享的锁和计数会分到两个地址上 | 什么都不留下，下一封信就用新的服务器 |
| 由谁共用 | 整个安装 | 一个组织：有多个组织时，各自用自己的发件地址，可能还有自己的服务器 |
| 谁来改 | 部署的人 | 管理员，改完想马上发一封试试 |

密码用 `secret-key` 加密后再存，和数据源密码、AI 供应商的 API 密钥一样。

## 3. 设置项

| 设置 | 列 | 留空时 | 规则 |
|---|---|---|---|
| SMTP 服务器 | `smtp_host` | 邮件关闭 | 主机名或 IP 地址，不带协议和端口 |
| 端口 | `smtp_port` | 跟着加密方式：587、465 或 25 | 1 到 65535 |
| 加密方式 | `smtp_security` | 不会为空；没保存过时是 STARTTLS | STARTTLS、SSL/TLS 或不加密 |
| 用户名 | `smtp_username` | 不登录，直接使用服务器 | |
| 密码 | `smtp_password` | | 用 `secret-key` 加密；从不返回 |
| 发件地址 | `from_address` | | 填了服务器时必填 |
| 发件人名称 | `from_name` | `SupaBI` | 最多 100 个字符 |

- **开和关**：服务器和发件地址都填了，邮件就是开的，没有单独的开关。清空服务器再保存，邮件就关了，其他值留着，下次打开时还在。
- **加密方式**：
  - STARTTLS 先明文连接，再请服务器加密。服务器不支持就报错，绝不继续用不加密的连接，否则密码会明文发出去。
  - SSL/TLS 从第一个字节起就加密，通常用 465 端口。
  - 不加密用于内网的中继，通常用 25 端口。选了不加密就不能保存用户名（`email_auth_unencrypted`），这样密码不会明文发出。
- **证书**按本机的信任证书校验，没有跳过校验的选项。服务器的证书来自内部 CA 时，把这个 CA 加进信任证书就行，比如用 `SSL_CERT_FILE`。
- **登录**：填了用户名，就必须有密码（`email_password_required`）。认证方式从服务器支持的里面选，先 PLAIN，再 LOGIN。比如 Microsoft Exchange 就只支持 LOGIN，不支持 PLAIN。两个都不支持时，发送失败，阶段是 `no_auth`。
- **密码**：和 AI 供应商的 API 密钥一样，读取时只说有没有设密码。保存时不带密码，密码不变；带空字符串，密码被删掉。清空用户名时，密码也一起删掉。
- **什么时候读**：每封信都读一次，改了在所有实例上马上生效。正在发的信用开始时读到的设置发完。
- **超时**写死：连接 10 秒，和数据源的「测试连接」一样（[启动配置](configuration.zh.md) 10.7）；整封信 30 秒。服务器慢到这个程度，几乎一定是配错了或者连不上。

## 4. 发送

`internal/mail` 包：

- `Send(ctx, server, message)` 发一封信，服务器接受或拒绝后返回。只试一次。
- `Configured(ctx, pool, key, orgID)` 读出组织的设置并解开密码。邮件关闭时返回 `ErrNotConfigured`，功能据此提示邮件还没配好。
- 一封信有收件人、主题、纯文本正文和可选的 HTML 正文。有 HTML 正文时按 `multipart/alternative` 发，不显示 HTML 的邮件客户端就显示纯文本。正文是 UTF-8，用 quoted-printable 编码；主题和发件人名称里的非 ASCII 文字按 RFC 2047 编码。每封信都带 `Date` 和发件域名下的 `Message-ID`。
- 主题或发件人名称里有换行就拒绝，这样外部写进来的内容不能给信加头。每个地址用之前都先解析。
- 用 Go 标准库的 `net/smtp`，LOGIN 在包里自己写，不加依赖。

发送失败时，错误说明失败在哪个阶段，并带上服务器自己的原话：

| 阶段 | 含义 |
|---|---|
| `connect` | 连不上服务器 |
| `tls` | 加密连接建不起来，比如证书不受信任 |
| `no_starttls` | 加密方式是 STARTTLS，但服务器不支持 |
| `auth` | 服务器拒绝了用户名或密码 |
| `no_auth` | 填了用户名，但服务器 PLAIN 和 LOGIN 都不支持 |
| `sender` | 服务器拒绝了发件地址 |
| `recipient` | 服务器拒绝了收件人 |
| `data` | 服务器拒绝了信本身 |

## 5. 测试邮件

页面上有一部分「发送测试邮件」：一个收件人，开始时是管理员自己的地址，和一个按钮。

- 测试用表单上的值，保存没保存都行，管理员可以先试再存。密码留空就用已保存的，和数据源的「测试连接」一样。
- 只有一个收件人。
- 信用发送人的界面语言（第 6 节）。信里写了是谁发的、经过哪台服务器，没料到会收到它的人也知道它从哪里来。
- 成功时，页面说服务器接受了这封信，以及用了多久。之后能不能进收件箱由邮件系统决定，页面也这样说明：服务器接受了，信仍可能被当成垃圾邮件。
- 失败时，页面用读者的语言说明失败的阶段（第 4 节），下面显示服务器自己的原话，只有系统管理员看得到。

## 6. 服务端语言包

服务端生成的内容用读者的语言（[架构总览](architecture.zh.md) 10.1）。测试邮件是第一份这样的内容，所以后端有了语言包：

- `internal/i18n` 包为每种语言嵌入一个 JSON 文件，`en-US.json` 和 `zh-CN.json`，和界面用的名字一样。一个测试检查两个文件的键相同、每段文字的参数也相同。
- 服务端现在还不知道每个人的界面语言：界面把选择存在浏览器里，`users` 表的 `locale` 列没有用上。所以测试请求带上发送它的页面的语言。
- 第一个给别人发邮件的功能，要让服务端知道每个收件人的语言。见 [暂缓事项](../backlog.zh.md)。

## 7. 接口、权限和审计

| 接口 | |
|---|---|
| `GET /system/email` | 设置、有没有设密码，以及默认值（每种加密方式的端口、发件人名称） |
| `PUT /system/email` | 整体保存设置 |
| `POST /system/email/test` | 用请求里的设置发一封测试邮件，并报告结果 |

- 只有系统管理员能调用。
- 发不出去时，测试的响应仍是成功的，内容说明哪里出了错，和「测试连接」一样。不可能有效的设置，比如端口超出范围，用 400 拒绝，和保存时一样。
- 审计，类别是「系统 `system`」：
  - 保存记 `email_settings.update`，详情写改前和改后的值。密码本身从不写进去，详情只说它改没改。
  - 测试记 `email.test`，写收件人和服务器。测试失败记为失败，并写明阶段：和别的测试不同，它会把一封信发出系统。

## 8. 页面

系统管理的导航里加一项「邮件」（`/settings/system/email`），在「AI 用量」后面。只有系统管理员看得到。

- 布局和「通用设置」一样（[启动配置](configuration.zh.md) 10.3）：单列，每个设置左边是名称，右边是输入框，下面是说明。分三组：「SMTP 服务器」「发件人」「发送测试邮件」。
- 顶部一行说明邮件开没开。关着时，说明要填服务器和发件地址。
- 端口的占位文字是所选加密方式的默认端口。密码显示已设置；勾选框可以删掉它，和 AI 供应商的 API 密钥一样。
- 有改动才能保存；有未保存的改动时，离开页面先确认。测试不需要先保存。

## 9. 密钥

邮件密码是 `secret-key` 加密的密码之一（[启动配置](configuration.zh.md) 11）：

- 启动时还没有校验值的情况下，核对时可能拿邮件密码来试，和别的已存密码一样。
- `clear-secrets` 把它和别的一起清掉，报告的数量里也算上它。设置本身保留，管理员重新填密码。

## 10. 这一步不做

| 事项 | 暂缓原因 | 何时重新评估 |
|---|---|---|
| 队列、重试和发送记录 | 立刻发还是稍后发、重试几次、谁能看到发送失败，都取决于发的是什么：重置密码有人在等，订阅没有 | 第一个发邮件的功能 |
| 附件 | 只有订阅和定时导出要用，大小上限又取决于导出的限制 | 做订阅时 |
| HTML 模板和所有信共用的版式 | 还没有设计任何一封信 | 第一个发邮件的功能 |
| Microsoft 365 和 Gmail 的 OAuth 2.0 登录（`XOAUTH2`） | 要在供应商那里注册应用，还要在后台刷新令牌 | 组织的邮件服务不再接受密码时 |
| 跳过证书校验 | 网络上任何人都能借此读到密码。可以把内部 CA 加进信任证书 | 部署环境改不了信任证书时 |
| 每个工作区不同的发件人 | 没有东西从工作区发出时，组织一个发件人就够 | 工作区要用自己的名义发订阅时 |
| 服务端知道收件人的语言 | 见第 6 节 | 第一个给别人发邮件的功能 |
| `Reply-To` 地址 | 还没有发出需要回复的信 | 代表某个人发信时 |
