[计算字段](/zh-cn/data/datasets/#计算字段)有两种写法，在**写法**里选择：

| 写法 | 含义 |
|---|---|
| **标准函数** | SupaBI 自己的语言，默认使用。它在所有数据库上含义相同，更换数据源时不用修改，保存前就能发现错误 |
| **原生 SQL** | 数据源自己的 SQL，原样使用。换一种数据库时要重写 |

数据集的来源 SQL 始终用数据源自己的语法，标准函数只用于计算字段。

## 语言

```sql
IF(${订单金额} >= 1000, '大单', '小单')
SUM(${订单金额}) / COUNT_DISTINCT(${用户 ID})
CASE WHEN ${状态} = 'paid' AND ${备注} IS NOT NULL THEN 1 ELSE 0 END
```

| 元素 | 写法 |
|---|---|
| 字段 | `${名称}`。字段改名后，引用它的表达式会自动更新 |
| 文本 | 单引号。文本里的单引号写两次：`'it''s'` |
| 数字 | `12`、`3.5` |
| 其他值 | `TRUE`、`FALSE`、`NULL` |
| 算术 | `+` `-` `*` `/` `%` |
| 比较 | `=` `<>` `!=` `<` `<=` `>` `>=` |
| 逻辑 | `AND` `OR` `NOT` |
| 条件 | `x IN (a, b)`、`x BETWEEN a AND b`、`x IS NULL`，以及它们的 `NOT` 形式 |
| 分支 | `CASE WHEN 条件 THEN 值 ELSE 值 END`，或 `CASE x WHEN 值 THEN 值 END` |
| 函数 | `名称(参数, …)` |

关键字和函数名不区分大小写。

## 每一行还是一组行

维度和度量在每一行上都有值，指标则是对一组行做聚合。所以：

- 维度和度量的表达式不能聚合，也不能引用指标。
- 指标的表达式必须聚合。在指标里要写 `SUM(${订单金额})`，而不是 `${订单金额}`。
- 每行的值不能和聚合值放在一起：`SUM(${金额}) / ${数量}` 是错误的。
- 聚合不能嵌套。

## 各数据库一致的行为

在各数据库有差异的地方，标准函数统一成一种行为：

| 项目 | 行为 |
|---|---|
| 除法 | 两个整数相除会保留小数。除数为 0 时得到空值，不报错 |
| `CONCAT` | 只接受文本，任何一段为空时结果为空。数字和日期先用 `TO_STRING` 转换 |
| 文本长度和位置 | 按字符计算，位置从 1 开始 |
| `ROUND` | 小数四舍五入 |
| `TO_INTEGER` | 直接去掉小数部分，不四舍五入 |
| 取日期的一部分 | 按查询使用的时区取 |
| `WEEKDAY` | 周一是 1，周日是 7 |
| `DATE_TRUNC` 配 `'week'` | 一周从工作空间设置的那天开始 |
| `DATE_ADD` | 超过月底时取当月最后一天 |
| `DATE_DIFF` | 计算跨过了多少个单位边界：1 月 31 日到 2 月 1 日相差 1 个月 |

还有几处取决于数据库：文本比较是否区分大小写，布尔值怎样返回（MySQL、StarRocks、Doris 和 ClickHouse 上是 0 或 1），`TO_STRING` 显示小数的位数，以及 `ROUND` 处理恰好在中间的浮点数时往哪边舍入。

:::note[扩展函数]
`MEDIAN` 和 `REGEXP_MATCH` 是扩展函数，在函数面板里标记为**扩展**。`MEDIAN` 在 MySQL 上不可用，各数据库的算法也略有差异；正则表达式的语法也不完全相同。数据源不支持的函数不会出现在面板里，使用它的表达式不能保存。
:::
